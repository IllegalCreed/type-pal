## AI Quick Path

先读任务卡顶部状态、范围、前提与当前准入，再选择实施或复核步骤。本页落实[AGENTS 当前临时模式](../../AGENTS.md#当前临时模式codex-分派贡献者执行codex-独立验收)；旧三贤人流程完整保留在[历史快照](archive/protocols/workflow-snapshot-20261015.md)，不作为当前门禁。

## 目的

将 Codex 委派、贡献者隔离执行、Codex 独立验收与集成写成可执行流程。聊天辅助沟通，任务卡和证据保存可追踪状态；人负责产品裁决与必要的体验验收，不负责搬运审查正文或代跑技术门。

## 前置条件

所有新功能、缺陷修复、重构、测试和工具开发先读[长期工程质量规范](code-quality.md)，按完整八维开展设计、实现和审查；本页规定推进方式，不维护第二套质量条文。

- Codex 核范围、前提、单一 Coding Owner、修改白名单、验收方式和隔离 worktree。
- 非小改或跨会话/Owner 接手先开卡并补上下文锚点；完整/轻量卡见[任务模板](templates/README.md)。
- 读[当前看板](board.md)和[生成任务索引](tasks/index.md)，确认任务没有被替代；旧 pending 席位不阻止当前模式准入，旧 counter 须逐项闭合。
- 阶段拿不准时停下来问用户；第一阶段读 [CLAUDE](../../CLAUDE.md)与相关机制/工程知识；第二阶段读 [READ-FIRST](../phase2/READ-FIRST.md)及对应知识 harvest；跨阶段按事实来源区分。
- 不因文档模板化改变产品行为、测试合同、schema/save 或公共接口。需要这些变化时仍按任务范围与用户裁决推进。

## 步骤

### 1. 进入 build 前核前提

任务沿用 `draft → build → review → done`，以及 `blocked/rework/cancelled`。`Status` 本身不代替准入证据。

高风险、用户可感知行为、原版/第一阶段机制或碰撞/移动语义任务，在详细方案前完成：

1. 一句话写清工程前提或用户可见行为。
2. 原版/primary source、第一阶段、当前二阶段、本任务目标四向真值矩阵；每格有 file:line 或一手来源。N/A 必须解释。
3. 最强替代解释及什么观察会推翻前提。关键项 unknown 时保持 blocked。
4. 大量 mismatch 只证明不一致；分别排查 runtime/命令分类、原版或一阶段理解、提取/地图/解码、audit/test model。不能从红项数量直接推出迁移根因。
5. 若主动偏离已核真值，给用户一句 before→after 和代表场景作产品裁决；保持已核真值的修复不重复请示。

Codex 核实后在卡内记录 `build allowed`、Owner、白名单与验收方法。固定三席签字、额度代班和缺签豁免不再是当前门禁；不代签也不追溯改写历史。

### 2. 隔离实施与交付

先核模块职责、状态Owner与依赖，再定文件边界；拆合、重命名和目录重组按[质量规范](code-quality.md#2-定位问题并选择整改)同步caller/出口/测试/文档映射。纯重构与行为修复分提交；必要检查随影响范围安排，全仓check/官方coverage/protected集中在较大稳定窗口。

同一实现文件同一时间只由一位 Coding Owner 写入。贡献者在隔离分支/worktree 实施并提交自测、源/候选 SHA、命令、产物和限制；未接收前不得自行合 main。作者自验不替代 Codex 独立复核。

换 Owner 前卡内写清改派原因、已完成/剩余、文件范围、验证结果、必读锚点与风险。专项审查按能力选择贡献者，不设固定席位。

### 测试质量验收（用户 2026-10-03 固化）

- 每个测试对应原子、可观察、可反证的业务合同。必要结果可成组断言，不把不同输入轴、状态转换或调用层塞进万能用例。
- 与 main、既有测试及已接收候选逐合同排重；换数字/名字/fixture 或弱 matcher 不算新合同。已证重复、恒真、无业务执行、输入非法或不进正式 runner 的候选合并、撤销信用或精简。未知候选不自动删除，历史由 Git 保存。
- 输入来自当前公开 typed/caller；业务核心不得用 `as unknown as`、`as never`、私有状态、核心 mock、放宽 timeout 或 ignore 掩盖问题。坏输入只用于明确的 IO/未知域，不冒充业务覆盖。
- 有效反控必须保留 command/cwd/执行身份、JSON/raw、exit/signal/spawn、file×fullName 集合、恰一指定业务 AssertionError、恢复全绿、源/测试/mutant hash 和精确临时树清理。普通 Error、collection/runtime failure、pending/skip/todo、重复红不算有效针。
- 按真实 caller、oracle、IO、生命周期判断判别力；慢不等于低质，短不等于高质。全绿/数量/覆盖率不能单独 accept。精简后重跑官方基准，不为数字堆弱断言或降规则。

逐项保留/合并/补强/删除/blocked 要有 file:line 和证据。[测试治理](../testing/governance.md)定义 catalog、报告和机器回执的配对，候选不自动接入正式覆盖率。

### 3. 独立复核与集成

逐文件审查[八维结论](code-quality.md#1-逐文件核清八维)，核具体实现和全部变更，不只验收报告或包级全绿。接收[可独立复验交付](code-quality.md#4-交付可独立复验的证据)：先快检候选/附件/原始结果，再按需定向实跑，复核失效或疑点范围；哈希匹配不授语义信用。缺维不升代码审查切片partial，关键未知或重要未修项不关闭文件。

Codex 直接核交付和一手证据，决定返工或接收；结论写回卡、交接日志和对应文档。lint/格式/typecheck 等硬静态门的 error/warning/info 全部清零，exit 0 但有诊断不算通过，不用存量、ignore 或降规则豁免。

高风险继续核原前提、可证伪观察与充分验证；核心前提变化使旧准入失效，先 rework/blocked 再核，不能用旧结论授权新方案。schema/save/migration/资源管线问题先证明根因层，修上游、重生成并验幂等；当前作者真源边界按 READ-FIRST，不恢复已退役转换器。开发期只消费当前 canonical 版本；旧版 fallback/upgrader/双读写等默认删除，真实不可重建输入的临时隔离转换器须有用户批准、唯一 caller 和退出条件。

质量门与独立交付复核分开记录；全仓未零诊断前不得宣布统一质量门或集成收口。通过后由 Codex 提交/合并/推送并按授权清理退休候选，不能替用户作新的产品取舍。

### 4. 视觉、资源与用户验收

Generation Owner 仍为 Codex。生图/替代资源任务记录目的、对象、提示词、尺寸/格式/透明背景、路径、登记与验证；审美与覆盖可请专项审查，不自动移交实际生图。

GLM 可在明确委派范围执行浏览器、截图、布局与交互初审，首包交实际操作样本；工具/资产不满足则报 blocked，不能用源码推断冒充看图。Codex 复核接收并作最终整体验收。

剧情/演出观感使用 `e2e-deferred`：开发期登记入口、准备数据、步骤、预期画面/时序、批次/Owner 和证据路径，冻结后集中实跑；延后的只是视觉，脚本/状态/数据/时序仍须开发期验证。功能界面用 `dev-functional` 做最小可达性和工作流验证，mixed 逐项区分。已存在的同一视觉证据不重复跑。缺工具如实记未完成，等待恢复或用户裁决。

只剩用户体验判断时给 2–5 分钟清单：从哪个界面进入、代表对象、具体操作、通过/失败画面、无需重验的已通过项。部分通过继续有效，失败项精确 rework，不让用户重跑全部。

### 5. 写回与交接

卡顶部状态是任务事实源；[索引](tasks/index.md)由生成器投影，看板仅活动分工，候选能力看 capability-map。完整卡保持目标/范围、前提、锚点、设计风险、Owner、实施、自测、独立结论、用户裁决与交接；模板只定义结构。

跨 Agent 交接时在卡和回复都提供自含提示词：任务卡、状态、角色、按序必读、已完成/证据、余风险、明确动作、白名单和输出。未准入须写不得实现/不得 done。无需转交时明确“无下一位 Agent 提示词”，并说明实际下一步。

同一阶段的独立审查可并行钉同一候选，但不读或复述另一席结论；各 reviewer 只落自己的块，提交前同步并自行处理 push 竞态。Codex 统一判断准入。确有证据/实现依赖再串行，不能因历史表述恢复固定三席。

## 失败处理

### 共享工作树与 stash

- 接手先读 git status；未提交内容可能属于其他 Owner。不得为 pull、切分支或清理而擅自 stash、reset、还原或覆盖，只提交自己明确拥有的文件。
- stash 不是当前进度。恢复前核完整 SHA、日期、源分支、基础提交、文件清单、卡状态及是否已被接收/替代；禁止裸 pop/apply，不按序号推断归属。
- 自己的临时 stash 也记录精确 SHA，恢复前复核。无法证明相关、其他 Owner、已 done/cancelled 的 stash 不自动恢复，不复活退役目录。
- 清理历史 stash/分支先保留并验证可恢复备份，再按精确对象删除；并发状态变化立即停下重新核，不整批清空未审对象。

原 2026-09-06 stash 备份与 2026-09-23 分支/worktree 退休的完整数量、路径和验证保留在[历史快照](archive/protocols/workflow-snapshot-20261015.md#原始结论)，不能因旧目录仍存在就在旧快照继续实现。

### 停止线

一手证据冲突、旧 counter 未闭合、关键前提 unknown、真实产品取舍未定或不可逆操作未获授权时停止受影响步骤，写 blocked/rework 和可解除条件。取消固定签字不取消这些边界；事实核验由 Agent 负责，不把技术归因转嫁用户。

## 完成定义

依[长期质量完成定义](code-quality.md#完成定义)分别核审查完整、整改完成和可集成；功能正确、质量合格、必要质量门实际通过共同构成完成。贡献者负责执行和自验，Codex负责独立核代码、判定与集成，用户保留新产品取舍的决定权；不恢复固定模型席位。

验收条件实际满足、前提仍成立、必要检查有真实结果、文档/索引/能力记录同步、产品判断已由用户裁决（或纯文档按卡授权收口），才可 done。记录未运行项与范围限制；静态文档、候选回执、历史结论不能冒充 runtime/E2E/视觉/coverage。

历史完整原文与来源 SHA 见[分层前工作流](archive/protocols/workflow-snapshot-20261015.md)。当前协议发生新变化时同提交写回本页、任务卡与操作路由。
