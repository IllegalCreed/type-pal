## 前提真值门

### 一句话行为 / 工程前提

同一个脚本差异可能修数据错误、规避原执行器缺陷或适配英文排版；必须同时核历史说明与当前 caller，不能靠静态差异或一次调用效果决定是否采纳。

### 反证与替代解释

- 最强替代解释：某些 `0 → 明确结束地址` 是对原执行器的规避，当前 TS/SDLPal 执行器可能已不受影响；当前等价不能否定历史修复的必要性。
- 推翻条件：实际版本、对象归属、调用上下文或原指令与预期不符，停止该规则，不能按地址硬套。一次战斗 probe 不证明重复使用、存档、换队和完整剧情。
- runtime：`runScript` 的普通 end 返回起始入口，advance 返回后继；SDLPal 同样保存独立的 next entry。原 EXE 的 `0000` 缺陷本轮未运行验证。
- 原版理解：社区有 DOS、Win、98 及《新仙剑》混用，后者不作为本轮对应证据。历史补丁同时含新增物品、音乐等取舍，不能整包认作 bug 修复。
- extractor：先比 MKF 原始 chunk，再解码；没有用生成 JSON 的文本差异推断二进制修改量。
- probe：第一次夹具误用局部 labelMap，以及把字段 21 误认作身法，均已纠正；这些失败不计产品红绿反控。字段 21 为吉运，20 才是身法。

### 自动纠错管线

建议新增独立的、带版本和前置断言的数据纠错模块，供 `pal-extract` 调用：

1. 检验原盘版本/指纹，忠实解码；先执行现有原盘 round-trip 断言，保留未经纠错的解码事实。
2. 克隆为 runtime 构建输入，按命名规则应用纠错。每条记录 ID、原因、输入版本、原指令/对象字段断言、替代值与来源；不匹配时停止并报告，不静默套用、不按可变中文文本定位。
3. 所有改动完成后重新计算脚本入口、标签、切片和共享引用，同时生成 `events/all.json`、场景/对象/共享脚本等消费者。尾块地址统一分配，不能只修改 all.json。
4. 对象专属的触发锚点等配置由同一层输出到明确的场景/事件元数据；引擎只保留通用能力。具体 schema 需实施前核全部读写路径，不能给它们伪造原盘字段。
5. manifest 记录来源指纹、纠错版本及实际规则，哈希对应最终产物。生成可重复且不污染 raw；应用包、缓存键、CDN 资源成套升级，避免脚本与标签混版。
6. 中英文共享纠错后的玩法数据；翻译只覆盖消息/词条及明确的布局映射，不能引入第二套剧情、数值或脚本事实源。

宝箱已有修复先等价迁移；太守配置迁移保留用户已选行为。玉佛珠默认值继续在解释器。酒神的通用入口回写/新游戏初始化/保存恢复属于引擎生命周期问题，不能用重新提取掩盖。
