## 结论

应把它设计为**编辑器统一的战斗测试工作台**，以现有第二阶段战斗引擎实际运行，
而不是“技能专用小弹窗”，也不是另写一套简化战斗计算器。
所有战斗相关编辑页都可复用同一配置/启动/结果机制，但入口要按对象性质区分：

- **直接试打**：角色、物品、技能、敌人、敌队、毒、战场，共7个现有页面。
- **带上下文接入**：场景开战、脚本开战、战斗资源及相关全局配置；不能对任意图片/声音/变量无条件给一个“试打”按钮。
- **保留专用验证**：地图、开局、商店、炼蛊皿等世界流程，不能靠一场独立战斗声称验收。

我方配置取自可复用的**我方预设**，敌方/战场由本次试打配置决定；不要求选择开局入口、不加载场景剧情。
从业务页打开时只预填当前对象，其余沿用已选测试配置，避免每次重填。

## 需要一并覆盖的战斗子功能

不能只接页面按钮却漏掉页面里的难测配置。以下都应使用同一运行核心，但准备条件不相同。

| 子功能 | 模拟器必须能准备的条件 | 应观察的真实结果 |
|---|---|---|
| 普攻、连击、攻击全体、防御、逃跑 | 我方配装、敌方阵形、Boss开关 | 实际行动/目标/伤害/限制，不另算一个预测值代替执行 |
| 普通技能与物品效果链 | 施放者、目标、HP/MP、金钱、背包、技能已用次数 | 合法可选性、消耗、命中/未命中、状态/资源变化 |
| 道具投掷 | 道具数量、投掷者、敌槽、对应表现资源 | 数量扣减、单体/全体目标、真实投掷效果与演出 |
| 装备效果 | 合法穿戴者/槽位、基础值与装备后有效值 | 属性、抗性、授技、常驻状态、全体攻击、回合恢复、战斗外观覆写 |
| 合击与守护 | 满足现行合同的队伍关系、全队状态/血量 | 合击资格/代价/效果、守护触发；不临时篡改公式或角色关系来假装成功 |
| 濒死/阵亡反应 | 队友关系和恰当血量、敌方可触发行动 | 已有伤亡脚本、对话、buff与音效；缺实现仍按Q2缺陷登记 |
| 毒和状态 | 目标阵营、初始毒/状态及剩余回合、抗性 | 玩家/敌人逐回合差异、抵抗、解除、自解、毒关系及耗材 |
| 敌人AI/回合hook | 难度、敌槽、我方能力；能自然运行到所需回合/血量条件 | 条件命中、行动、召唤/分身/变身和游标连续性；复杂条件可后续加受控场景夹具 |
| 偷取与收服 | 对应技能/敌人可偷物和收服值、背包/资源状态 | 获得物、次数/余额变化；已有写回缺陷不能靠结果面板自造数据遮盖 |
| 战场和战斗表现 | 指定战场、我敌双方、真实动作 | 五灵影响、屏波/背景、施法定位、精灵动作和声音同步 |
| 遭遇战斗演出 | 所选startBattle/敌人choreography，必要的真实角色 | 战斗开始/回合开始的对话/音乐/终止指令，仅当前battle子集 |
| 奖励与成长 | 可重建的入战快照、真实结算依赖 | 胜败逃分类、经验/金钱/技能/物品/成长前后差异，仅写临时世界；不写正式存档 |
| 战后事件 | 当前onDefeated子集及所需变量/标志/人物输入 | 隔离世界里的事件与变更轨迹；实际场景剧情连通性仍需场景试玩/E2E |

代码支持不等于无需工程改动：敌方初始毒/状态、特定AI中间态并非所有场景都有现成公共输入。
不足时设计受控的测试输入，不能直接改私有队列/阶段字段冒充真实触发；确定性随机复现也须查全随机源，不能只替换session rng却忽略结算Math.random。

## 统一工作台应具备的配置

修订建议：新增独立一级**战斗模拟器**，与现有负责内容定义的“战斗”模块分工。
理由是它已具有独立预设/方案生命周期，并跨角色、物品、战斗与资源服务，而不只是“有几个页签”。
用户已提出一级模块疑问并指出试打应是方案内按钮；这里据此修订建议，**尚未视为最终导航/视觉批准**。
各处“试打/试放”打开同一方案编辑页并预填对象。原有轻量帧预览、背景预览和音频试听保留，两者解决不同问题。

1. **我方**：选择/保存/复制/重命名/删除我方预设；成员与顺序、等级、基础数值、当前HP/MP、技能、装备。
   基础数值和装备后有效数值分别显示，避免手动填数后装备再加一次。明确“继承角色定义”与“本次覆写”。
2. **敌方**：选择已有敌队，或临时编辑成员/顺序/空槽；可从敌人页只带入单个敌人，不为此创建正式敌队。
   临时属性覆写与正式敌人编辑分开；召唤/变身仍解析工程中真实定义，不能丢掉资源/身份合同。
3. **背包与资源**：测试道具及数量、测试金钱、技能限用计数；支持所需的战斗初始状态。
   技能可能消耗物品/金钱，不是只把MP改大就足够。战外专用物品显示原因，不伪装成战斗可用。
4. **战场**：独立选战场和需要的战斗音乐；场景/脚本入口可带“已解析的有效战场/音乐及来源”，但不要求加载那个场景才能打。
5. **试打与结果**：开始、停止、按相同入战配置重新开始；显示真实结果与消耗/奖励/状态变化。
   首版不必承诺逐帧、时间旅行、批量平衡跑分、录像/完整脚本调试器；它们不是复用入口成立的条件。

### 四种保存对象，试打是方案内操作

2026-09-19用户进一步指出：“试打”应是方案页里的按钮，并要求明确背包归属与一级模块。
以下是**修订后的产品设计建议**，不代表UI批准或已有运行能力；原“子模块内四视图、单列试打页”的建议撤回。

| 保存对象 | 保存什么 | 为什么分开 |
|---|---|---|
| 我方预设 | 队员与顺序、配装/技能/数值覆写、初始状态 | “前期低配队”可用于所有敌队/技能/战场；不再兼任背包或金钱配置 |
| 敌方预设 | 现有敌队引用或自定义临时编队，以及逐槽数值/血量/状态覆写 | “普通三敌”“残血首领”“中毒敌群”可反复用，不改正式敌队 |
| 背包预设 | 已有物品引用和数量 | “基础补给”“投掷物测试包”“解毒测试包”可配任意队伍，不重复配置也不重建物品定义 |
| 试打方案 | 所选我方/敌方/背包预设+战场/音乐、测试金钱、战斗规则、本场覆写及测试目的 | 保存整套组合；“开始试打/停止/重开/查看结果”是本页操作，不再单列试打页 |

建议四种对象都纳入基础设计与保存/重开合同，字段可分基础和高级逐批开放；没有预设时也能在临时方案里配置并直接试打，
不要求用户先创建四份记录。只有希望以后复用时才保存命名对象。战场本身已有正式目录，不再造“战场预设库”。

### 我方预设字段

| 类别 | 建议可配置的内容 | 来源/边界 |
|---|---|---|
| 标识 | 名称、说明；预设稳定ID由工具管理 | 不与角色ID混用 |
| 队伍 | 从当前工程选择可参战角色、增删和顺序 | 无battler角色不能入队；人数、重复角色实例能力按真实引擎合同限制，不借模拟器扩容量 |
| 基础数值 | 等级、最大体力/真气、武术、灵力、防御、身法、吉运 | 默认继承角色；逐项覆写基础值，不填已经加过装备的最终值；改等级不暗中重算成长 |
| 当前资源 | 当前体力/真气，提供满值/指定值/比例的快捷编辑 | 0是明确数值而非“未填”；比例在开战快照时解析，不能和绝对值同时各当一套真源 |
| 装备 | 各现有装备槽所穿物品、显式空槽或继承默认 | 使用正式可装备角色/槽位校验；有效数值、装备授技、抗性与常驻状态只读展示来源，防重复叠加 |
| 技能 | 初始习得技能继承或显式测试集合；各技能已使用次数 | 装备授予技能单独标记，不烙入习得表；从技能页带入的临时技能需明确可见 |
| 初始状态 | 毒、可携带状态及剩余回合、临时毒抗；受支持的中毒阶段为高级项 | 状态/毒相互独立；傀儡等战斗限定状态不能塞进现行CarriedStatus，须受控入战能力后开放 |
| 高级观察 | 用于结算测试的经验/隐藏经验输入、战斗形象覆写等 | 有真实消费者与合法入口才开放；成长生成依N6b，不把内部hiddenCounts当保存输入 |
| 角色关系 | 展示合体技、守护对象、伤亡反应及是否满足队伍条件，支持跳回角色编辑 | 首版继承正式角色定义，不复制一套关系/伤亡脚本编辑器；缺队友明确提示，不自动换人 |

### 敌方预设字段

| 类别 | 建议可配置的内容 | 来源/边界 |
|---|---|---|
| 标识 | 名称、说明、稳定预设ID | 与EnemyDef/EnemyTeamDef身份区分 |
| 编队来源 | 引用现有敌队，或选择敌人组成临时编队 | 原敌队成员变化默认跟随；修改引用编队的成员时显式转为本预设临时编队，不改正式敌队 |
| 槽位 | 敌人、顺序、空槽；同种敌人允许占不同槽 | 当前固定最多5个敌槽（battle-core.ts:67）；保留空洞，不按存活数重新挤队 |
| 数值覆写 | 最大体力、等级、武术/灵力/防御/身法、现行抗性与双行动等 | 默认继承EnemyDef.stats；各抗性沿用现行单位/公式，不统一假装百分比；只影响指定槽实例 |
| 入战状态 | 当前体力、毒、状态及剩余回合 | 新受控初始化能力，不能声称现行构造器已支持；同敌种两个槽可不同血量/状态 |
| AI与技能 | 展示正在引用的AI规则、施法、召唤/变身目标、hook及演出；提供“编辑敌人定义” | 首版不在预设里再造完整AI/脚本编辑器；真实规则自然驱动行动，不默认强制每招成功 |
| 偷取/收服/奖励 | 显示可偷物及数量、收服值、经验/金钱与战后事件来源 | 默认继承定义；专项剩余偷取量/奖励覆写另列高级字段，不引入不存在的掉落系统 |
| 外观 | 默认用敌人战斗精灵；资源测试时可显式临时选择兼容用途 | 不把玩家/召唤精灵误当敌人profile；画面站位仍由语义槽和正式布局派生 |

**敌方不能照搬我方表单。** 当前EnemyStats/BattleEnemyState没有我方装备槽或真气池；敌人施法来自AI，
不能为了两侧对称加“装备/真气/习得技能”假字段。将来敌方机制真的增加这些能力，再同步编辑器。
AI中间游标、已触发once集合、行动队列、动画帧、内部时间戳不是普通预设字段，不把预设做成D13时间旅行快照。

### 背包预设的界限

- 只保存物品ID和数量，不复制物品名称、效果、投掷公式、图像等定义；这些仍在“物品”模块编辑。
- 一套背包能供多套方案复用。方案可临时加减物品/数量，保存方案只保存本场覆写，不无提示改基础背包预设。
- “穿戴中的装备”仍归我方成员配置；“携带但未穿戴的物品”归背包。不会因为背包里有一把剑就自动装备，也不会把已穿装备重复计入可消耗库存。
- 测试金钱归方案，避免不同队伍/背包都各带一份金额产生优先级混乱；若未来有更多战斗资源，再在方案里按实际能力扩展。
- 缺失物品时标记配置失效并阻止开始试打，仍可打开修复；只有战外用途的物品可作为库存/技能消耗材料保留，但界面必须说明不能在战斗中直接使用，不伪造可用能力。
- 从物品页打开模拟器时把当前物品和可编辑数量放入**临时方案**，可直接试打；不强迫先建命名背包预设。

### 试打方案字段与合并规则

- 引用我方/敌方/背包预设、选战场、需要的战斗/胜利音乐、测试金钱；Boss标记及手动/自动等**已有**战斗规则。
  当前difficulty只是AI条件匹配ID，不宣传成已有全局难度倍率系统；自动战斗会影响伤亡脚本，测试时须显示区别。
- 本次测试目的/来源对象、临时加入技能或道具、资源/状态覆写；需要战斗演出片段时显式绑定来源。
  通用世界变量只为受控战后片段提供，不扩成任意开局/剧情编辑器。
- 同一配置字段按“正式定义 → 所选预设覆写 → 本场覆写”解析；**技能集合/装备集合等集合值不暗中叠加**，
  用户显式选继承/替换，来源页的“临时加入”作为可见动作。解析后才走正式装备/技能派生。
- 一场开始时冻结完整输入副本；画面同时能看到本场最终值和来源。预设/定义后来改变不影响正在运行的战斗，
  下一次开始重新核引用/版本。重新开始恢复相同配置，不保证随机过程相同；固定随机种子须全部随机源统一后另开放。
- “保存预设”修改基础配置；“保存试打方案”只保存组合与本场覆写，不连带修改引用的我方/敌方/背包预设。
  运行中的扣血、耗蓝、耗物、死亡和奖励不保存为新初始状态，避免下次开战从上一场残局开始。

### 专门的编辑界面放在哪里

建议独立一级**战斗模拟器**，下设四个有明确保存对象的目录页，默认打开“试打方案”：

| 视图 | 主要工作 |
|---|---|
| 我方预设 | 左侧预设目录、中间队伍/成员编辑，复用现有选择器与数值字段；新建/复制/改名/删除/保存 |
| 敌方预设 | 相同目录与编辑骨架，敌槽/继承来源/覆写内容；不复制敌人定义编辑器 |
| 背包预设 | 预设目录、物品选择与数量编辑；不新增另一套物品定义目录 |
| 试打方案 | 左侧方案列表，中间选择三类预设/战场并调整本场条件；本页提供“开始试打”、停止、重开和结果入口，无须再跳一个“试打”页面 |

配置编辑状态应保留，测试回来能继续调参数。首版实际战斗可继续在同源独立试玩页运行；工作区是否内嵌战斗画布需在UI草图中明确，
不能因“模块内编辑预设”就默认重写游戏画布或强行把长表单挤在战斗旁。独立运行窗口属于方案执行方式，不是第四种“试打”管理页。
此处只建议信息结构，未作视觉批准；实现前需把一级导航变更列入r2范围，不借旧r1签字直接修改EDITOR_MODULES。

### 其他模块的快速试打（用户已认可接入方向）

2026-09-19，用户在说明“基于完整试打方案、仅本场可见调整、不修改原预设或绕规则”后答复“理解了，我觉得可以”。
各业务页的按钮打开轻量启动面板：选一套完整试打方案、当前测试对象、必要目标/数量、调整摘要，
提供“开始试打”和“到模拟器详细配置”；不是每次重选所有预设，也不是另建一个常驻试打页面。

| 来源 | 本场预填/调整 | 必要选择 |
|---|---|---|
| 技能 | 给选定队员临时加入当前技能；已有不重复 | 施放队员 |
| 道具 | 当前道具与可编辑测试数量进入本场背包 | 使用/投掷用途及数量 |
| 装备 | 临时替换合法装备槽 | 穿戴队员 |
| 战场 | 替换本场战场 | 展示替换摘要 |
| 敌队 | 替换本场敌方编队 | 展示替换摘要 |
| 单个敌人 | 放指定敌槽或组成临时单敌编队 | 放置方式/位置 |

调整只作用于本次配置副本，不反写原方案、各预设或作者定义；想复用再显式另存方案。
不自动补到MP999、清空限用次数或绕过装备规则；条件不足显示原因，并允许明确调整本场配置。
没有方案时进入模拟器的临时方案，配置后即可试打，不强迫先创建命名记录。
未保存作者修改不得悄悄改用磁盘旧版；“先保存再启动”还是“正式校验后的临时完整快照”仍待r2确定。
此次认可不替代尚未完成的UI草图、所有字段/持久化合同和r2设计准入。

### 保存与引用生命周期

- 推荐按工程保存编辑器测试配置、随工程备份/重开；不是游戏存档，也不是另一套ActorDef/EnemyDef。
  文件位置、格式版本、独立可玩包是否排除此类编辑数据尚需技术设计，接入既有作者保存事务，不随手加localStorage或孤立JSON绕过合同。
- 配置保存的是定义引用及明确覆写，没覆写的部分在下次启动跟随正式定义；每次运行另外保留当次解析快照用于结果解释，不把过时定义整份常驻复制进预设。
- 从技能/物品/战场页带入对象只改未保存的本场草稿，不无提示覆盖原预设。切换预设、退出工作区时明确处理未保存修改。
- 建议测试引用作为**可定位的依赖告警**，不额外阻止作者删除正式内容；现有正式内容引用删除守卫不降低。
  被引用对象删除后，预设标记失效、列缺失项并阻止启动，不自动删预设或换成另一个对象。删预设也应提示受影响的试打方案。
- 跨工程不能凭同名ID偷偷复用；预设导入/共享需身份与资源映射，首版不提供未经设计的跨工程复制按钮。

### 当前支持与待增加能力，不能混为一谈

- 可直接复用：角色实例基础值/装备/技能、库存/金钱、我方毒及可携带状态、敌队槽和定义、战场/Boss/AI难度条件等正式输入。
- 需要新做：预设管理/持久化、统一输入校验、逐敌槽的初始血量/毒/状态适配以及所有相关资源/取消生命周期；不是只给已有构造器加几个表单值。
- 暂不承诺：自动成长到目标等级、任意AI中间态、全世界剧情变量、逐帧/回滚、完全确定性录像；依N6b或后续独立设计。
- **初始状态不等于触发事件**：开场HP=0不证明“本次攻击造成阵亡”的反应，预设已中两毒不等于本次投毒触发致死。
  应用低HP/既有毒准备前置，再走真实攻击/投掷触发；初始配置不能替代行为验收。

本轮字段核验新增锚点：character.ts:187–239、actor-condition.ts:3–108、poison.ts:1–65、enemy-ai.ts:12–62、
battle-core.ts:64–125/184–268/278–364。初始敌血固定取def.stats.health且毒/状态清空，证明新字段须实现正式适配后才可开放；
按英文结构给中文表单逐项映射时仍需沿用编辑器现有名称，不重新发明“速度控件”等术语。

### 等级不能假装等于属性生成

现行instantiate只复制角色baseStats；把level从1改为50不会自动推导50级属性。r2必须明确：
显式等级和基础数值覆写可作为输入；“按成长规则生成指定等级数值”的能力依赖N6b及随机成长口径，不能在模拟器另写第二套升级算法。
同理装备提供的技能、抗性与状态须走正式派生，不能把已派生值永久烙进预设后下一次再叠加。

## 实现边界与成本判断

这已从两个入口bug修复扩大为**中等偏大的编辑器工具功能**；无需重写战斗核心，但不是增加几个按钮。
主要成本在统一输入、保存预设、资源/生命周期隔离、状态准备与真实结果可见性，按钮接线只是最后一层。

| 层 | 应复用 | 需要新做/核实 |
|---|---|---|
| 编辑器配置 | Ds标准表单、当前人物/技能/物品/敌队选择与引用定位 | 统一工作区、来源预填、临时覆写、预设管理 |
| 运行适配 | main现有装备/技能/形象派生、资源readiness、BattleSession | 从私有配置创建临时世界/玩家输入、早分流、共同清理；必要最小提取而非复制main |
| 战斗 | 正式菜单、AI、公式、状态、道具/投掷和演出 | 不另写算法；现有Q2缺陷保持公开，不在模拟器里“修成另一个结果” |
| 结算 | grantBattleRewards、buildSettlementScreens及已有写回规则 | 仅针对临时副本复用、展示结果；模拟器绝不进入正常SaveStore |
| 预设保存 | 作者保存事务/工程身份/重开/引用处理 | 编辑器配置落盘合同、持久化范围与可能的版本影响；旧r1“无需版本升级”不可照搬 |

### 建议按三批接入，不把所有拓展压成一个巨卡

1. **共享底座与主闭环**：我方/敌方/背包预设与试打方案的基础编辑和保存、战场与金钱、真实战斗和退出隔离；先替换技能和敌队现有入口。
   基础配置一次按通用模型设计，不先造一个只能试技能的临时方案。需有角色/物品支持数据，但不必所有页面按钮同批接完。
2. **全部直接编辑入口**：角色、物品（装备/使用/投掷）、敌人、毒、战场；补必要初始状态与真实结果观察。
   技能、敌队已在第一批，至此7个D类页面闭合，不遗漏合击/守护/毒/道具等准备条件。
3. **上下文与资源入口**：战斗精灵/背景/头像/音乐/音效、场景敌对和脚本startBattle、战斗演出/战后受控片段、相关项目资源。
   分清battle-only与世界流程，不为接一个页面实现完整X5/D13。各独立接入可按收益再拆小批。

这里只建议分批与边界，**没有决定三批全是E2E前置**。建议原D-04/D-05真实试打与存储隔离必须闭合，
完整工具接入按用户确定的阶段范围推进，不把所有资源按钮/高级条件编辑/长期覆盖率目标变成R4薄E2E的新门槛。
Q2仍负责战斗完整专项测试；模拟器可复用其场景准备，但手动打通一次不替代自动业务断言、概率边界或完整通关。
