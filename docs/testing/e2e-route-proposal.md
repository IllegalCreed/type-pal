## 建议：把探索成本支付一次，后续机械重放

1. **路线编制**：每段先列目标NPC/出口/机关/道具门、前置条件、结束条件；从当前内容与地图定位，
   本席只对含糊处向用户确认。先001/002验证成本，再由Codex起草003–010边界，不要求用户写攻略或手玩通关。
2. **路线执行**：有限动作词表`walkTo / interact / choose / useItem / waitFor / assert`。
   每步先验前置→执行→验后置；NPC移动/碰撞/菜单变化用状态等待，不写固定睡眠时间或盲发几十个确认键。
3. **迷宫自动导航**：静态地图先规划途经点及路径，再以真实方向键/生产移动链前进；按实际位置收敛，
   动态障碍只能有限重规划，超预算失败。机关、跨层/换图出口、强制触发区必须作显式路线节点，不能用最短路绕掉。
   不能传送过墙、直接触发隐藏函数、改flag或塞任务物品来宣布正常路线通过。
4. **合法检查点链**：第一段从新游戏真实开始；本段结束断言通过才导出下一档。
   输入与输出hash、项目/内容/save版本、前驱fragment及源码候选一起记录，受影响链从最近可信上游重建。
   从独立档重跑验证局部；从头连续跑验证跨段累积。两者分别出报告，互不冒充。
5. **失败按段诊断**：常态仅输出段名/状态/耗时/断言数；失败才加载对应地图、输入轨迹、精简状态及截图，
   不每帧截图/读全世界。没有进展、未知弹窗、超出重规划次数、超时即停，不让模型无限探索。

## 三条验证线，不能相互替代

| 线 | 验什么 | 加速边界 |
|---|---|---|
| Q1剧情链 | 场景、交互、剧情条件/取物、队伍变化、存读档、结局接续 | 普通重复战斗可按已批准合同速胜，仍须真实入战/正式结算；不跳剧情副作用 |
| Q2战斗专项 | 真实输入、回合、AI、状态、规则、音画、战后状态 | 固定seed/预设与战斗模拟器等窄入口；不使用Q1结果旁路 |
| 编辑器闭环 | 创建/编辑→保存→重开→试玩，冲突/权限/恢复 | 专用项目/浏览器存储，不能靠直接写文件代替被测UI动作 |

必败/逃脱/坚持回合/特殊敌方hook的战斗不能机械判胜；先核目标段实际内容。
旧“Q1任何战斗直接胜利”的表述如与具体剧情合同冲突，应由用户确认修订，不用探针替用户改剧情。
同理，测试用例能直开场景不等于已证明上游能到达；这种入口只可标局部专题。
