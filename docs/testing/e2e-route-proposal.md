## 用户追加裁决（当前有效）

- **无人智能依赖是最终验收门**：AI视觉/推理只用于开发阶段查证、编路线、校准、诊断和维护。
  最终E2E脚本必须脱离Agent独立运行完整已声明流程；执行器不调用模型/API，不等待AI读截图决定下一步，
  不把异常分支交给AI临时探索。允许普通寻路、状态机、图像比对等确定程序算法，未知状态须失败停线。
- 两套游戏双线推进，主线优先并纳入大型支线。一阶段用户已多次手动通关，作为较成熟的路线验证先行线；
  不据此声明无bug，不要求两边按同一进度锁步。二阶段阻断不阻塞一阶段。
- 普通路上遇敌直接速胜，但仍用正式战斗结算/奖励/后续链；涉及剧情的Boss逐场分析，
  保留对话/回合/召唤/变身/胜败等必要条件。旧“任何战斗直接胜利”不再适用。
- 对话不跳过：只经正常确认/翻页输入推进，verify可较快按键，保留不可跳的尾停顿与选择逻辑。
  用户不用提供回车次数、像素坐标或迷宫逐步按键。Codex负责语义目标→数据锚点→实际校准。
- 主线各引擎均继承自己前段真实结束存档；等级/装备/道具/旗标不手造，checkpoint不能跨引擎移植。
- 用户可观看独立测试窗口，后续支持暂停/失败现场/单段重跑；这些是执行器需求，不宣称已实现。
- E2E后续服务Playwright分段录制与Content Studio宣传素材；验证与录制共用分段语义，录制模式另设正常节奏。

## 建议：把探索成本支付一次，后续机械重放

1. **路线编制**：每段先列目标NPC/出口/机关/道具门、前置条件、结束条件；从当前内容与地图定位，
   本席只对含糊处向用户确认。先001/002验证成本，再由Codex起草003–010边界，不要求用户写攻略或手玩通关。
2. **路线执行**：有限动作词表`walkTo / interact / choose / useItem / waitFor / assert`。
   每步先验前置→执行→验后置；NPC移动/碰撞/菜单变化用状态等待，不写固定睡眠时间或盲发几十个确认键。
3. **迷宫自动导航**：静态地图先规划途经点及路径，再以真实方向键/生产移动链前进；按实际位置收敛，
   动态障碍只能有限重规划，超预算失败。机关、跨层/换图出口、强制触发区必须作显式路线节点，不能用最短路绕掉。
   不能传送过墙、直接触发隐藏函数、改flag或塞任务物品来宣布正常路线通过。
4. **合法检查点链**：第一段从新游戏真实开始；本段结束断言通过才导出下一档。
   输入与输出hash、项目/内容/save版本、前驱fragment及源码候选一起记录，受影响链从最近可信上游重建。
   从独立档重跑验证局部；从头连续跑验证跨段累积。两者分别出报告，互不冒充。
5. **失败按段诊断**：常态仅输出段名/状态/耗时/断言数；失败才加载对应地图、输入轨迹、精简状态及截图，
   不每帧截图/读全世界。没有进展、未知弹窗、超出重规划次数、超时即停，不让模型无限探索。

## 三条验证线，不能相互替代

| 线 | 验什么 | 加速边界 |
|---|---|---|
| Q1剧情链 | 场景、交互、剧情条件/取物、队伍变化、存读档、结局接续 | 普通重复战斗可按已批准合同速胜，仍须真实入战/正式结算；不跳剧情副作用 |
| Q2战斗专项 | 真实输入、回合、AI、状态、规则、音画、战后状态 | 固定seed/预设与战斗模拟器等窄入口；不使用Q1结果旁路 |
| 编辑器闭环 | 创建/编辑→保存→重开→试玩，冲突/权限/恢复 | 专用项目/浏览器存储，不能靠直接写文件代替被测UI动作 |

必败/逃脱/坚持回合/特殊敌方hook的战斗不能机械判胜；先核目标段实际内容。
用户已确认剧情Boss个案处理；未分类战斗停止核查，不用探针替用户改剧情。
同理，测试用例能直开场景不等于已证明上游能到达；这种入口只可标局部专题。

## 双引擎组织方式

一份剧情语义目录（fragmentId、主/支线身份、上下文、目标和关键事件），两套adapter和两条checkpoint链。
可共享的是“去厨房取得餐盘”这种业务目标；场景ID/地图/站位/按键时序/断言实现/存档格式均各自适配。
第一阶段运行记录可帮助定位二阶段缺失事件，但不是二阶段内部状态真值或已通过证据。
二阶段某段失败，保存该段输入档与证据并阻断其下游链；第一阶段继续推进。不得靠捏档跳过二阶段阻断。
专题fixture与已有独立检查点可以继续验证其它功能，但明确不算连续通关进度。
不同浏览器上下文/存储/产物目录；可并行工作，不要求实际渲染/录像同时争资源，稳定性测量和录制按需串行。

## 可独立运行的交付验收

固定版本/资产/环境、合法起档后，由独立进程启动引擎/测试浏览器、执行已登记语义路线与输入，
自动处理已建模的对话/选择/机关/迷宫/战斗分类、核断言、导出检查点和回执，返回明确exit code。
关闭Agent会话、没有模型凭据也能跑；正常成功路径不需要人工批准下一步。入口命令尚待实现，不能提前宣称存在。
所有必须的分支必须落成机器可执行条件，不能用“AI看情况操作”作脚本动作。
截图/trace/视频是证据，不能成为常规运行依赖AI解读的控制信号；发生偏差输出失败，不通过请求AI继续来掩盖。
人工审美/宣传成片审核在E2E执行链之外，verify与后续capture执行均不依赖在线模型。
开发小样通过不等于完整通关验收，最终还要从新游戏连续跑完声明的主线/大型支线范围。

  READ-FIRST铁律6保持：修对应内容编排，不因本案例给Reforge增加“所有对话全局冻结NPC”的耦合。

### 默认记录协议（待实现）

1. 每段声明watchActors：队长、参与剧情的重要NPC与关键交互对象；语义角色分别映射本引擎实际实体ID，
   不要求用户给坐标。起段/结束/关键事件强制取小快照，记录场景/角色位置朝向/可见性及输入控制态。
2. NPC每次**实际已提交**的位置变化才产生move事件（from/to）；朝向/显示隐藏/动作开始结束、
   对话显示/换页/结束、选项出现选择、切场景、玩家控制权转移也各在变化时记录。
   场景实例/运行ID、单调序号、本引擎逻辑tick/单调时间、剧情事件键用于排序，跨引擎不要求时间戳相同。
3. 诊断模式另附原生script/auto来源、目标、阻挡/控制权与取消/完成原因；命令开始不等于角色真的移动。
   不能只抓moveParty/moveEntity调用而漏掉实际auto步进，也不能只低频轮询漏掉“移动后又走回”的中间过程。
4. 两边在相同语义节点（某句对话出现/关页、NPC到门口、消失）对齐；自动检查偏序与段内条件。
   不强求走了同样步数/同样毫秒；站定合同按本引擎位置精度明确容差，不能因浮点抖动误报，也不能容忍完整移动。
5. 关键例：在已确认应站定的李大娘对话区间，检查实际moveCount/最大离开起点距离，而不仅比较首尾位置。
   同时检查朝向、说完后的恢复移动与最后离场。只对所声明角色/区间要求静止，不把场景内其它NPC巡逻一概判错。
   若逻辑位置不变而画面仍滑动，升级该段采集相机/实际绘制脚底锚点或短录像，区分相机变化、帧锚偏移与真实位移。
6. 正常输出段级摘要/断言与关键事件，细节用有界环缓冲或按段流式文件，不把每条日志发给模型。
   失败保留首个违约点前后窗口/必要截图/原生诊断；逐帧详细模式仅手动针对短段开启。
   事件覆盖/序号缺口、溢出、截断必须显式计数，证据不全不得以“没看到move日志”证明静止。

以上断言全部由独立执行器检查，正常运行不需AI看日志或截图。失败时AI只用于后续诊断/修复；
日志说明“何时偏离”，内容修复仍需查实际脚本/上游迁移，不能根据一条计划日志直接断定根因。

## 对话与素材合同

- `verify`：观察当前行/页/打字/等键/选项，正常确认→等状态变化→继续；不按固定次数盲发。
  打字瞬显仍是正常输入效果，不能直接清dialog或移动脚本游标。选择题按语义选项，出现未知选项即停。
  一阶段尾停顿、二阶段autoAdvance各按本引擎合同等待，不能为“加速”删掉触发副作用。
- `capture`：同一段同一语义目标，正常打字与可读停留，不显示调试面板；不把快速回归录像直接作为宣传成品。
  战斗展示用真实策略，不用路上秒胜镜头冒充战斗表现。剧情结果/关键事件与verify相符，
  HP/MP/随机掉落等非合同字段不要求跨profile逐字节相同；capture输出不覆盖verify主线检查点。
- 每段从现在起登记：引擎/fragmentId、地点/角色、剧情简述、关键事件/可录起止、剧透/主支线标签、
  源码/内容版本和checkpoint来源，避免之后给大量无标签视频补语义。影片/图片/台词等素材授权另核，不因E2E通过自动具备发布权。
- Playwright画面录制、BGM/音效采集与同步、分辨率/裁剪/无debug UI须做一个短片端到端验证；
  不把能显示画面等同于音画录制链已完成。录制与Content Studio活动/发布保持原门槛，不在本轮启动。
- 本会话Content Studio `get_project_view`工具不可用；按onboard-project技能无法读取实际项目快照。
  不猜projectId，不登记活动/素材/发布计划；本轮仅Type Pal内冻结接口需求。
