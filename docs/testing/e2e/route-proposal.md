# 双阶段快速通关 E2E：路线驱动方案

Status: proposed
Owner: Codex（路线设计与核验；实施按原任务卡分派）
Last reviewed: 2026-10-18
Template: design-spec-v1 / 1.0.0

## 问题与目标

把已确认剧情目标编成可独立执行、可失败定位、可重复生成检查点的路线：从合法起点，经正常输入和逐步断言，到本段真实结束状态，再交给下一段。最终已声明范围的主线和大型支线须脱离 Agent 与模型独立跑通；本页设计不宣布这些范围已完成。

本页是 catalog 中 `e2e-route` 的候选方案。设计状态 `proposed` 与 catalog 发布状态 `proposal` 分属两轴，都不授予产品 build；实际范围、Owner 和实施准入取[当前看板](../../ops/board.md)及 [R4 原卡](../../ops/tasks/E2E-R4-1-route-and-checkpoint-foundation.md)或对应子卡。

## 真值与约束

### 用户已定的七项规则

1. **运行不依赖在线智能。** AI 只参与开发、查证、路线校准和失败诊断。执行器不用模型/API 看截图决定下一步，不把异常交给 AI 临时探索；普通寻路、状态机、图像比对等确定程序可用，未知状态须有限失败并留证。
2. **两阶段双线推进。** 主线优先，并明确登记大型支线的时限、互斥与遗漏条件。一阶段的手动通关经验可帮助先编路线，不能证明无 bug 或替代自动化证据；二阶段阻断不阻塞一阶段，两边不要求锁步完成。
3. **按战斗用途决定加速。** 普通路上遇敌可按已核速胜合同执行，仍须真实入战、正式结算、奖励与后续脚本。剧情 Boss、必败、逃脱、坚持回合、召唤/变身与特殊 hook 逐场核；未分类先停，不把“所有战斗直接胜利”当方案。Q2 与战斗展示不能用剧情速胜旁路。
4. **对话经正常输入完整推进。** verify 可较快确认或翻页，但要等真实消费与状态变化，保留固定尾停顿、选项与剧情副作用；不盲发固定次数 Enter，不清 dialog 或改脚本游标加速。Codex 负责语义目标、数据锚点和实际校准，不要求用户提供像素坐标或逐步按键。
5. **两条真实检查点链。** 第一段从正常新游戏开始，后续各自继承本引擎前段真实结束档；等级、装备、道具、旗标不手造，存档不跨引擎移植。局部 fixture 可以验证专题，不能计作上游已到达或连续通关进度。
6. **独立窗口与失败操作是执行器需求。** 可观看、暂停、失败现场和单段重跑需要各自验证；本页核过部分入口源码，不据此宣布这些交互全部实现。
7. **录像是后续消费者。** 验证与录制共享 fragment 语义和关键剧情结束契约；capture 使用正常打字与可读停留，需要展示的战斗走真实回合与策略。快速回归录像不能直接成为宣传成品，Content Studio 对接另守录制与发布准入。

### 当前版本、证据与阶段边界

[content 常量](../../../packages/content/src/character.ts)当前为 content22 / minimumSave12，[Reforge 存档常量](../../../packages/reforge/src/save/types.ts)为 SAVE_VERSION=12。Game 与 Reforge 保存形状和起态各自适配，不能把 RF 的 version12 字段要求套到 Game。开发期只消费当前 canonical；版本切换重建受影响输入，不新增旧存档 upgrader、fallback 或跨版本兼容链。

顶部 testing-meta、[catalog](../catalog.json) 和[配对 evidence](evidence/e2e-route.json)仍保留 `d02278dc…`、content22 / minimumSave11 的历史发布审计身份、候选与日期。这与现行源码版本分开；`source-backed`、`document-audit` 和 performed=false 不证明本次游戏执行，不能将旧字段改号成 SAVE12 通过。

两轨共享剧情语义身份，各自拥有地图、站位、按键时序、断言和真实存档。第一阶段是重要对照，也可能有 bug；二阶段用干净显式编排表达已核意图。按[共同演出标准](contract.md#演出验收标准意图优先差异不等于缺陷用户2026-10-07)比较相关 NPC 完整位置、朝向、显隐、实际绘制帧、等待与控制权，不只比起终点；不强求内部指令或重复绘制次数相同。既定目标位置、必要同步与剧情结果精确验证，不采用旧建议中的坐标宽松容差。

参与剧情、自动脚本可能造成提前进场或离场的 NPC，须在相关窗口显式接管并正确释放；无关 NPC 与环境动态继续；确认对白不证明可见槽已清除。动作、等待、剧情 auto 启动或释放前的对白段落结束及后续实际 draw，按共同合同分别取证。每段还须按[编辑器预览起点准则](contract.md#每段核对编辑器预览初始状态用户2026-10-12)核执行前现场、全部相关实体、状态方案/步骤关联和保存重开复验，游戏 runner 的 passed 不代替这份回执。

## 方案

### 路线与交接流程

1. 以稳定 `fragmentId` 登记主/支线身份、前因后果、场景/角色/物品、必需与可选触发、起止契约和可录时刻。阶段边界与正式报告从 [E2E 总览](README.md)进入，剧情与[检查点目录](../../../projects/pal/e2e-checkpoints/README.md)按实际确认范围写回。
2. 每轨分别把语义目标落到真实地图、NPC/出口/机关、原生输入和断言。动作遵循前置条件→正常动作→输入消费/状态变化→后置条件；转向、对白等待和位置提交分别观察，命令发出、planned.to 或路线末采样不能冒充真实位移及剧情终点。
3. 地图规划必须经过必需机关、跨层出口、强制触发区；动态阻挡与真实生产移动链仍需核验。`walkTo / interact / choose / useItem / waitFor / assert` 是原方案的概念词表，不宣称存在同名公共 API 或完整通用迷宫 runner。未来有限重规划须另核适用片段；当前已冻结输入不能靠未记录的改路、传送、改 flag 或塞物品掩盖失败。
4. 本段真实结束断言通过后才导出本轨下一档，绑定项目/源码候选、内容与存档版本、前驱 fragment、输入输出 hash 和正式回执。独立段重跑验证局部，连续执行验证累积与交接，两者分别记录，不能互相充数。
5. 按段输出进度与首个失败，保留最后可信状态、原始输入、必要截图和有界诊断。事件序号缺口、溢出、截断或缺实际 draw 使相应义务缺证；不能以“日志没看到移动”证明站定，也不默认对全世界无限逐帧导出。

### 已核公开入口的窄范围

| 入口 | 当前源码所表达的输入与判断 |
|---|---|
| `pnpm e2e:001:both` | [opening-both](../../../scripts/e2e/opening-both.mjs)分别启动两轨，核子报告、同 revision、matrix 和 NPC 比较；任何一轨失败不能写成双轨成功 |
| `pnpm e2e:002:both --game-report GAME_001_REPORT --reforge-report REFORGE_001_REPORT` | [inn-both](../../../scripts/e2e/inn-both.mjs)把两份本轨 001 报告分别传给对应单引擎 `--from`，再核两轨路线/正文/来源与 NPC 比较 |

[前驱验证](../../../scripts/e2e/inn-contract.mjs)拒绝 capture profile，要求 passed 的本引擎 001 报告、固定 `001.end.save.json`、保存字节 hash 和本轨起态；RF 分支核 version12 / content22 / pal。它对 revision 只核 40 位 SHA 语法，不比较当前 HEAD，也不独自证明报告来自真实执行；完整候选、内容与恢复可信度还须沿正式报告、实际执行和后续断言核验。

这两个 `:both` 入口均拒绝 `--capture`。已核单引擎 story 源码有局部 capture 分支，其用途与 verify 存档恢复不同；capture 产物不作 verify 前驱、不覆盖主线检查点。上述是源码核读，未启动入口，也未证明当前环境、全部后续片段或整局已经通过。

### 覆盖方向与执行用途分别登记

| 覆盖方向 | 必须保留的业务义务 |
|---|---|
| Q1 剧情链 | 场景、交互、剧情条件、取物、队伍、正式存读档与结局接续；支线单列分叉覆盖 |
| Q2 战斗专项 | 真实输入、回合、AI、状态、规则、音画与战后状态，不能用 Q1 速胜代替 |
| 编辑器闭环 | 专用工程/浏览器存储内创建或编辑→保存→重开→试玩，不能用直接写文件代替 UI 动作 |

verify 用正常消费输入和断言证明流程；visual sample 保留需要用户判断的正常节拍画面；capture 产出带 fragment/剧情标签的独立素材。三者不能互相代授通过，normal capture 的 HP/MP 等非合同字段也不要求与加速 verify 逐字节相同。具体 profile 与输出依[共同合同](contract.md#4-验证档与录像档)。

## 边界与风险

- 未知状态/选项、无进展、超时、错引擎/版本/前驱、未分类战斗、缺关键日志或未解释演出差异，停止受影响段并留证，阻断其下游链；另一轨可按自己的准入推进。不能临时交 AI 盲玩、捏档跳段或把工具失败统计成产品缺陷。
- 原始录制和旧回执不可改写。按[最小重跑规则](contract.md#录制与判定分离最小重跑用户2026-10-08)，比较规则错误先离线重算，缺必要字段才补采，产品行为改变才复跑受影响片段；起态改变从最早受影响边界向后验证，不默认整链从 001 重录。新判断另存比较器/输入 hash 与影响分析。
- 普通路线或工具回归绿不能关闭某段的完整帧、对白显隐、存档、编辑器预览或用户视觉反例。公共根因与独立差异按[问题族](cross-stage/common-issues.md)分别回链，不按 NPC 编号豁免，不以总时长接近抵消漏动作、等待或错姿态。
- 本页不核定通用迷宫、暂停/恢复 UI、速胜 host 或完整音画生产链的实现状态。旧“尚无 runner”、旧设施容量、旧 N6b 排期与某次 Content Studio 工具不可用只在原日期/会话范围成立，不作今天能力结论；后续实施继续按当前卡核实。
- [001–006 连续卡](../../ops/archive/tasks/done/E2E-CONTINUOUS-001-006.md)的最终接受和早期失败各属所列冻结候选/日期，不能概括为今天完整 E2E 已通过。当前发布状态取 catalog、执行取原回执，导航与文档静态门不补运行信用。

## 验收

设计被实施时，声明范围内须从合法起档由独立进程启动、消费已建模输入、核剧情与战斗分类、导出真实检查点和回执，返回明确 exit；关闭 Agent、无模型凭据仍可执行，成功路径不等人批准下一动作。短样或前几段通过不能代表完整主线/大型支线范围完成。

逐段收口必须有 canonical 正式报告、当前候选机器回执与真实 checkpoint、适用两阶段关键 NPC 完整日志、编排/命名审查及编辑器预览逐入口回执；缺一项或存在未闭合用户反例，按[收口硬门](contract.md#e2e-收口硬门用户2026-10-042026-10-12补充)保留 rework。实际输入消费、剧情结果、存读链与相关对象完整呈现才是业务 oracle，单测、exit0 或模板结构不能替代。

visual sample 的用户观感、capture 的正常节奏、音视频同步、无 debug UI、DOM 清单与窄录制适配器分别核验；达到[自动录像门槛](contract.md#8-自动录像准入门槛)后，才按对应范围对接 Content Studio。Type Pal 维护 fragment 事实，Content Studio 维护 activity/clip/成品及发布，二者显式映射；E2E 不自动授素材发布权或新活动授权。

Owner 由原任务卡指定，Codex 负责核来源、具体范围、证据缺口和独立验收；用户保留真实产品/视觉取舍。下一步先在当前卡选定待推进片段或公共问题，再核现行输入、前驱与实际证据；本页 proposal 不自行扩范围。本轮仅改写设计正文、保全原文并验文档 consumer，未运行产品、E2E、编辑器预览、视觉或 coverage，也不宣布全量治理完成。

> ## 双引擎组织方式
>
> 一份剧情语义目录（fragmentId、主/支线身份、上下文、目标和关键事件），两套adapter和两条checkpoint链。
> 可共享的是“去厨房取得餐盘”这种业务目标；场景ID/地图/站位/按键时序/断言实现/存档格式均各自适配。
> 第一阶段运行记录可帮助定位二阶段缺失事件，但不是二阶段内部状态真值或已通过证据。
> 二阶段某段失败，保存该段输入档与证据并阻断其下游链；第一阶段继续推进。不得靠捏档跳过二阶段阻断。
> 专题fixture与已有独立检查点可以继续验证其它功能，但明确不算连续通关进度。
> 不同浏览器上下文/存储/产物目录；可并行工作，不要求实际渲染/录像同时争资源，稳定性测量和录制按需串行。

> ## 可独立运行的交付验收
>
> 固定版本/资产/环境、合法起档后，由独立进程启动引擎/测试浏览器、执行已登记语义路线与输入，
> 自动处理已建模的对话/选择/机关/迷宫/战斗分类、核断言、导出检查点和回执，返回明确exit code。
> 关闭Agent会话、没有模型凭据也能跑；正常成功路径不需要人工批准下一步。入口命令尚待实现，不能提前宣称存在。
> 所有必须的分支必须落成机器可执行条件，不能用“AI看情况操作”作脚本动作。
> 截图/trace/视频是证据，不能成为常规运行依赖AI解读的控制信号；发生偏差输出失败，不通过请求AI继续来掩盖。
> 人工审美/宣传成片审核在E2E执行链之外，verify与后续capture执行均不依赖在线模型。
> 开发小样通过不等于完整通关验收，最终还要从新游戏连续跑完声明的主线/大型支线范围。
