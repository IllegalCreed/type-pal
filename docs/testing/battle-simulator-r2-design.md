## 1. 已确认与待确认

用户已确认：不同战斗相关页面共用模拟器；配置我方/敌方、装备、技能、等级、数值与道具；
保存可复用预设；业务页选择完整方案后显示本场调整；真实战斗且不读写正常存档；无需选择开局。

本轮建议如下，**预选项不等于用户批准**：

- UI：独立一级“战斗模拟器”，默认“试打方案”，另外三个目录为“我方预设 / 敌方预设 / 背包预设”。
  试打是方案页按钮；真实战斗在同源独立试玩窗口运行，不另造试打管理页。
- 持久化：命名预设与方案随工程保存、备份、重开；战斗消耗/奖励/进度永不落盘。
- 未保存内容：首版先保存工程内容再启动；仅本场临时配置不必先存成命名预设。
  不支持悄悄运行磁盘旧版，也不在本批增加未保存整工程的资源快照协议。

2026-09-19已向用户提出后两项选择，等待答复；本轮可点击草图用于确认 UI 结构，不替代产品功能验收。
若任一选择改变，更新受影响设计后再签 r2；已经确认的隔离/复用方向不重复询问。

## 2. 首批范围与分工

`原技能固定链接、可能直接胜利且临时授技进入普通存档 → 通用方案配置、真实战斗、正常存档零 IO。`
代表场景：自有工程中选择自建我方与敌队，临时给某队员加入当前技能，看到真实目标/消耗/效果，退出后正常进度不变。

本卡首批按四个实现切片连续完成，**不是四次重新设计签字**：

| 切片 | 交付 | 首批之外 |
|---|---|---|
| S1 模型与保存 | 四目录稳定 ID、结构守卫、命名记录 CRUD、引用诊断、统一撤销、事务保存/重开 | 跨工程预设导入、任意文件迁移 |
| S2 独立运行 | 配置解析、实际战斗、隔离结算、取消/重开、结果回报、存档零 IO | 世界剧情、时间旅行、录像、批量平衡跑分 |
| S3 工作区与入口 | 四目录编辑页、快速面板，技能/敌队接入；敌人旧入口改用同一单敌预填，避免遗留旧链 | 角色/道具/毒/战场的新按钮与高级状态面板 |
| S4 验证与收口 | 保存/重开、实际施法与道具/配装使用、负控、最小功能视觉、统一质量门 | Q2 全量战斗验证、Q1 全通关 |

基础配置已支持背包和配装，所以首批能从方案试用道具/装备；其他业务页的快捷按钮可下一批接入，
不必等全部入口铺完才能使用。敌方逐槽残血/毒/状态与高级属性覆写放第二批，必须先设计正式初始化输入，
不把未支持字段先存入文件或显示成已经有效的控件。第一批敌方使用原定义满体力、无额外初始毒/状态。
完整三批复用不是自动新增的 E2E 前置门槛；原 D-04/D-05 闭环仍是本卡目标。

## 4. 配置模型与编辑交互

首批四类记录都含工具生成的稳定 `id`、显示名和说明。保存定义引用与显式覆写，不常驻复制整份 ActorDef/EnemyDef。

- **我方预设**：成员引用与顺序；等级、七项基础属性的继承/覆写；各现行装备槽的继承/指定/空槽；
  习得技能继承/替换；初始体力/真气使用满值、绝对值或比例的互斥表达。
  拒绝重复角色模板（当前世界按模板维持唯一实例）、非 battler、悬空/不合法配装。
  首批按现行站位表可表达的1～5人限制，不借此扩容；完整1～5人菜单/选择/结算须在实施验证，不以有坐标表代替测试。
- **敌方预设**：引用正式敌队，或5个明确槽位的临时编队；允许同种敌人多个槽，保留 null 空槽，至少一个真实敌人。
  修改引用队伍成员时显式转为预设内临时编队；不反写正式敌队。首批不复制 AI 编辑器或虚构敌方装备/真气池。
- **背包预设**：物品 ID 与非负整数数量，零数量在规范序列化时去除；同 ID 合并规则须显式且有上限/溢出校验。
  库存与穿戴装备分别保存；只在战外可用的物品可作消耗材料，但不能显示成战斗使用/投掷合法。
- **试打方案**：三类配置源（命名预设引用或内嵌临时配置，判别联合而非两套并行真源）、战场、音乐、金钱、
  手动/自动与 Boss 开关、显式本场覆写。音乐用默认/资源 ID/静音三态，不能用 truthy 丢掉静音。

解析顺序：正式定义→所选预设→本场覆写→正式装备/技能派生→按有效最大值解析当前 HP/MP。
集合继承/替换、技能临时加入、数量替换分别显式表示；不靠对象 spread 的顺序隐式规定业务语义。
无效绝对数值报错，不静默截成另一个测试条件；HP=0 是合法配置，但整队不可行动时必须显示原因而非假造战斗。
初始低血不等于触发濒死/死亡事件；用户要测触发必须通过真实行动。

命名记录编辑经现有 EditSession Command/全局历史 owner，不加第三套 undo 栈；编辑即纳入工程 dirty，顶部“保存工程”统一落盘。
临时方案由工作区草稿 owner 保管，不混入命名记录；支持显式另存、切工程/关闭时提示，不能无提示丢失。
从业务页来时选完整方案、指定队员/槽位，显示仅本场调整，提供“开始试打 / 到模拟器详细配置”。
无方案可用时进入临时配置，不要求先建四份记录。首次从当前项目对象选值，不猜 PAL ID。

## 5. 持久化方案（推荐，等用户确认）

固定路径 **`editor/battle-simulator.json`**，编辑器专属文档：`kind`、当前格式 `version:1` 与四类记录。
不写 `.type-pal`（整个 namespace 受身份保护），不写 localStorage/游戏 SaveStore，也不把测试配置塞进 runtime content table。
库本身不保存 workspaceId；整工程另存后仍能使用。跨工程不可直接粘贴 ID；启动包另带当前工程/工作区身份并严格匹配。

推荐本批不变更 content/save 版本：运行内容与存档类型没有新字段；编辑器文件有独立严格格式。
这属于待 r2 审查的设计结论，不沿用旧 r1“无需升级”的签字。未来改变该文件格式仍按开发期 canonical 纪律，不预造 upgrader。

落盘必须闭合：

1. 本地、HTTP/种子、沙盒和转可写的编辑器打开链，都在稳定读取/对应锁域内通过被观察 FileSource 读该文件；
   现有 httpSource（file-source.ts:37）已将404转为 NotFoundError，无需为本功能改写文件源接口。
   只有真正 NotFoundError 代表未使用过模拟器；HTML200、权限/网络错、坏 JSON、未知版本不可吞成空库。
2. 有文件的读字节须在 `observeAuthorSource.finish` 之前进入磁盘基线；缺席首次创建时使用现有 plan 的 null 预期，
   对外部创建/修改冲突明确拒绝。不能只在 UI mount 临时读文件而漏掉保存并发防护。
3. EditorState、toEditorState、serializeProject、保存恢复快照、准备写集的正式重开校验一并接入。
   同一个作者事务写内容和模拟器文件；任何失败不留下半份预设。没有命名数据且从未使用时不额外生成空文件。
4. 结构损坏先 fail-loud 拒绝本次编辑器打开并给具体文件路径/可重试入口，原文件不变；
   不自动清空/修复。普通游戏不读取该文件，不被编辑器附属数据损坏阻断。
5. 悬空**内容引用**不等于结构损坏：记录仍可打开修复，列出精确目录/对象/字段，禁止启动。
   这类测试引用只警告，不追加正式内容删除阻断；原生产引用守卫不降低。
   删除预设提示受影响方案，确认后保留失效引用以便修复，undo 能原样恢复。
6. 工程另存/克隆/作者 ZIP 原样携带；外部篡改/同 ID 不同 workspace 不得越过既有身份和锁校验。
   A8 运行发布不应依赖此文件，是否剔除作为发布装配范围登记；不擅自改现行作者 ZIP“只排恢复目录”合同。

实现前冲突扫描：固定路径若已被 manifest、catalog 或其他作者文档占用则拒绝，不覆盖；
不放宽 `writeProject` 身份域保护或 path collision 检查。附属文件也必须过新专属结构校验，不能因非 catalog 而绕过。

## 6. 独立运行边界

编辑器只产生可序列化的本场配置，Reforge 提供严格解析和独立宿主；共用小型运行配置合同放在 Reforge，
命名库与 CRUD 留编辑器。现有 editor 已依赖 Reforge，不新增反向依赖或一个巨大公共配置包。

- 点击时冻结配置/来源页对象，复核当前工程身份与所有作者 dirty（包含脚本会话、资源导入）；dirty 时提示保存后重试。
  对话框开启期间切工程、删对象或保存失败，提交时重验，不能用开窗时的旧判断。
- 新同源 play 窗口仅 URL 携带严格模式标记、现有工程/工作区身份和一次性随机 launch ID；
  **完整配置仅走内存握手，不塞 URL / localStorage / 临时存档槽**。
  同步开窗避弹窗拦截；`postMessage` 校验精确 origin、window.source、launch ID、工程/工作区身份，
  成功后 MessageChannel 单次交付、回执消费；拒绝重复/失效/畸形包与混合普通调试参数。
- 接收器在普通 boot、标题、SaveStore 构造和存档元数据读取之前早分流；握手缺失/刷新/错误明确提示从编辑器重新开始，
  **不得回落正常 boot**。禁止正常存档 F5/F9、菜单、自动存档、checkpoint 等出口；工作区句柄数据库读取仍合法。
- 通过现有 loadPlayProject/工作区身份门载入已保存工程，稳定读 token 与本次配置绑定；不从场景入口取队伍，
  不运行 onEnter/探索循环，也不靠地图中心。准备前后核 project revision，期间工程保存变更则取消重新开始；
  正式必要资源准备完才开战，迟到资源遵守同一 session epoch/AbortSignal。
- 从配置建立新临时 world；最小提取 main 的玩家派生/准备/结果适配给正常战斗与试打共用，
  不复制公式、不整体拆 main；提取前后普通战斗参数、writeBack 与奖励效果要钉等价。
  敌方首批只走既有 EnemyDef/null 槽位输入，不改 battle-core 初始状态接口。
- 实际 BattleSession/菜单/目标/AI/动画/声音；使用正式 writeBack、grantBattleRewards 与结算展示，仅作用临时 world。
  未实现或已知 Q2 问题原样暴露，不用结果面板计算“理想结果”。不运行场景战后剧情；方案注明该边界。
- 准备、运行、结束、错误、取消的同一 owner，幂等回收 rAF/监听/音频/通道/对象 URL。
  重复开始有 single-flight 门；关闭任一端取消该次请求，迟到不得启动/播音/覆盖下一次结果。
  正常完成可留真实结果，重开以同一已解析初始快照重新建立世界，随机序列不保证相同；工程变化时提示重新准备。
- 停用旧技能授技 URL 捷径；旧地址显式说明重新从编辑器打开，不能保留静默 MP999 兼容分支。
  旧敌人/敌队编辑页入口同步改共享启动链；普通开发调试入口独立，不借本卡扩大其存储保证。
