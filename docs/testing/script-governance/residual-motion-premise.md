# 剩余自动动作与动画节拍核查

本报告核查当前作者工程中的漏动作、错误循环和动画节拍，供[SCRIPT-GOV-3](../../ops/tasks/SCRIPT-GOV-3-residual-families-and-regression.md)决定产品修改范围。
基线为`8efe04861`，状态为只读取证完成，尚未修复产品。原始脚本和第一阶段仅用于确认动作内容与观感；
本报告不要求新引擎复活旧自动脚本解释器、全局对白冻结或脚本地址分派。

已确认四个初始自动绑定都缺少正文；新增擂台三动作和一组三轮交替循环也有正常可见入口下的缺陷。
同一法事两次安装相同自动入口还暴露了复播问题：当前方案选择保留已完成游标，第二次动作不会执行。
这些短暂剧情动作适合放进正文中的显式顺序编排。独立环境循环继续由自动行为或页预制动作承担。

## 节拍和原子动作

第一阶段探索和普通事件逻辑是100毫秒一拍，战斗是40毫秒；见
[主循环:42](../../../packages/game/src/shell/main-loop.ts)和共享`FRAME_MS_EXPLORE`。
[tickAutoScripts:1208](../../../packages/game/src/core/event-system.ts)每拍执行一条普通自动指令；
`end.advance`及`end.reset`也各占一拍，而普通`goto`跳转当拍继续执行目标。
[自动控制:1276](../../../packages/game/src/core/event-system.ts)和`goto`分支明确区分这两类。
因此同样是换帧，连续0x14可每100毫秒换一次，0x14与advance交替则每200毫秒换一次；
goto的次数上限不是等待毫秒数。

[0x14姿势:4018](../../../packages/game/src/core/event-system.ts)在一拍内同时设置朝南和指定帧。
当前若翻成`setEntityFacing → wait100 → setEntityFrame → wait100`，便把同一个姿势拆成两拍。
全量当前auto扫描发现743个方案中有2483处这种形状，含001至005已作者改写内容。
这个数量只是筛查范围：必须先确认源指令及调用域，不能全量删等待，也不能统一给所有等待乘2.5。

[第一阶段0x24:3796](../../../packages/game/src/core/event-system.ts)每次安装都创建新IP游标。
本次实际执行16组后，新安装均清除此前0或9的idle计数，动作时序相同；新内容不能继续依赖旧计数残留。
当前[方案选择:237](../../../packages/reforge/src/script-world.ts)在有效方案未改变时保留游标，这是合理的方案选择合同，
不能为旧0x24的动作重启用途而全局改成每次选择都重新开始。

### 法事的第二次播放

源第一次动作结束后，正文写frame0，再做frame13/14两轮、15、16、17、18，接着19519重新安装19629。
这些是同一动作被法事正文有意使用两次，不是两个不同剧情时期的方案。

当前真实`ScriptProjectRuntime`首次执行返回true，帧序为`[3,4,5]`并保存completed。
继续执行当前onEnter真实body37至53后，有效selection仍为legacy-001，completed被保留；第二次执行返回false，帧序为空。
此反例与是否补全3至12无关：即使补帧但保留重复select，也仍会丢掉第二次动作。

建议把短动作保留在人物可查询的编排中，两次正文各显式播放，而不是再给作者引入重启状态指针。
若使用单次精灵动作，动作结束后的pose要由正文明确设置；当前临时动作覆盖完成时会被播放器清除，
不能把“动作最后一帧”误当成永久姿态。若使用顺序换帧和等待，这个问题天然由最后一条setEntityFrame负责。

### s126召神动作与对白边界

源0x24后先等6拍，幻影e2220出现，再等1拍并出现呼救对白；第二段继续动作和返程发生在呼救之后。
旧引擎对白等待会暂停自动调度，新引擎应在正文明确切分这些动作段。

## 替代解释与可证伪观察

- 运行器或命令分类有误：当前真实schema、编译器、`RuntimeScriptRunner`都将正文中明确的等待执行出来，
  本次没有在模拟解释器中重写该合同。若实际编译器把补全正文丢掉，应转公共层修复，不能删等待绕过。
- 对第一阶段观感理解有误：原0x14原子姿势、advance/reset与goto差别已读代码且调用真实函数；
  若游戏正常caller触发得到与本表不同的帧序，需核caller并行或可见性，不以本次独立auto采样替代完整演出。
- 提取或资源错误：原实体、入口、帧与源RLE实际帧数均有直接证据，不能只看静态`nSpriteFramesAuto=0`。
  原输入hash改变或源RLE帧数与该批断言不符即停止，不使用旧结论覆盖新输入。
- 审计模型错误：页动作不是缺auto；相位不是周期；完成后原park不是动画100ms循环；
  静态未证caller不是可玩入口。这些反例分别保留，不把宽筛查计数当已修分母。
