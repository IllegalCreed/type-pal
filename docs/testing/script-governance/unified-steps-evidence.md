## 自隐藏之后的等待

候选扫描到 122 个自动正文将自身状态设为 0。105 处随后只剩机械展开的新添 100ms 等待和完成指令，没有新的动作或原作者显式等待。这种尾等待会在新运行器的实体执行门暂停，阻止当前步骤结算。因此删除它们，让隐藏后直接完成；隐藏之前的节拍、最后可见动作时刻和隐藏时刻均保留。

这 105 处是明确的结束时长例外：隐藏后完成不再延迟 100ms。自动轨迹 oracle 的动作与条件 hash 保留原预期，并不包含没有后续事件的尾等待；新增逐条回归检查隐藏后立即遇到完成指令，四族回归还断言隐藏时刻和完成时刻相同。不能把这个例外写成全批总耗时严格相同。

另有 17 处不能按这条规则删等待，完整路径和保留原因见台账：

| 范围 | 保留理由 |
| --- | --- |
| s003/e63、e64；s004/e101 至 e104；s005/e134、e135、e137、e138 | 隐藏发生在永久条件轮询内，循环回边仍需判断另一实体；没有完成指令 |
| s038/e624；s097/e1782；s192/e3302 至 e3304；s246/e4349 | 隐藏发生在永久动作循环内，回边仍有移动、帧或位移动作；保留后台续跑语义 |
| s048/e797 | 所在分支退出后仍有对 e796 的行为、触发方式、朝向、帧和声音写入；它不是纯完成尾 |

这 17 处保留原正文等待。后续若剧情验证证明它们应永久结束或共同尾部应该合并，应单独调整作者编排并覆盖再激活情形，不能以本轮机械尾清理的规则扩大删除。
