## 什么算"演出"

**演出 = 连续自动脚本**(用户定义,2026-06-07):一段被触发后**自动连跑**、编排了对白/走位/转场/战斗/特效的脚本。**路边 NPC 一两句对话不算**。

枚举口径(宽松,排除两类噪声):

- ✅ **算演出**:含 ① 动画过场(RNG/FBP/结局)② 剧情 Boss 战 ③ 自动战斗 ④ NPC 走位编排(≥1 走/骑/追/动画 op + 对白)⑤ 场景转场 + 对白 ⑥ 给物/授术 + 对白 ⑦ ≥4 句连续对白(长叙事/对话)⑧ ≥3 处 NPC 走位编排。
- ❌ **不算**:① 纯**场景初始化**(只 0x46 放队伍位 + 0x50 淡入 + 0x49 设对象初态 + 环境音 —— 进场都有,非演出)② **路边对话**(1–3 句、无动作的 NPC trigger)③ **随机遇敌**(接触怪 triggerMode≥4、只 0x07 开战、无对白的野怪)。

> 三大入口:**进场**(scene `onEnterLabel`,56 段)· **触发**(eventObject `triggerLabel`,玩家走近/交互,442 段)· **归隐脱出**(scene `onTeleportLabel`,9 段)。

## 图例

### 触发(kind)
- **进场** = 场景 `onEnterLabel`,载入场景即自动跑(场景开场演出)。
- **触发@objN** = 编号 N 的 eventObject 的 `triggerLabel`;`triggerMode` <4 需主动交互、≥4 走近自动触发。
- **归隐脱出** = 场景 `onTeleportLabel`(0x38 传送出场景时跑,多为出口转场演出)。

### 复核风险(= 与原版出现表现差异的可能性,**非**机制对错)
- 🔴 **高**:含动画过场 / Boss 战 / 多处转场 / 大量走位+淡屏 —— **镜头/走位/时序/淡屏最易和原版有出入,优先逐帧核**。
- 🟡 **中**:中等节拍(几句对白 + 1-2 动作 / 单转场)。
- ⚪ **低**:节拍少(纯短对白演出 / 单一战斗触发)。

> 风险按**演出复杂度**算(过场×4 + 战斗/转场×3 + 走位/淡屏×2 + 对白/授物/状态×1),是**复核优先级三角**,不是已测结论。

本表所有演出的 **opcode 机制**均已实现(见 [opcode-status.md](./opcode-status.md) 164 opcode 全收口),故不单列"机制✅/❌"。**真正的 bug 面是视觉/时序/编排细节**(对白分页节奏、走位停顿、淡屏时长、镜头、精灵帧、音画同步)—— 这些**静态读码无法判定真假**,需对真档逐帧验收,故本表用 **🔴/🟡/⚪ 复核风险**替代"状态"列做 triage。已知差异在末节累计。

## 方法与局限

- **来源忠实**:演出清单 100% 来自脚本反汇编(scene 表入口 + eventObject trigger + 全局脚本),非凭印象;节拍由 opcode 信号统计,Boss 名由 `BOSS_ROSTER` 交叉确认。
- **粒度**:1 入口脚本 = 1 行(按 ip 去重)。一段跨多场景的长演出(如锁妖塔 149→151→174)会拆成各场景的入口分别列出,可循 →sceneK 串读。
- **局限**:① 章节带边界近似(见上)② 风险是复杂度启发,非实测 ③ 动画过场仅计脚本内触发(开场 AVI/片头另算)④ 反汇编只跟主线性链(`0x04` 子脚本调用计数但不展开,`goto` 记录不跟随)——极个别靠深层 call 编排的演出节拍可能少计。
