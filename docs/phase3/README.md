# docs/phase3/ — 第三阶段：官网、离线发行与用户系统

> 第三阶段在第二阶段（现代化引擎 + 内容编辑器 + 迁移器）收口后启动。
> 目标是把项目从"开发者工具"升级为"可分发、可在线使用的平台产品"。
>
> 当前主线仍是**第二阶段**（引擎 + 编辑器 + 迁移器三件套），见 [../phase2/](../phase2/README.md)。

## 第三阶段目标（2026-07-18 用户定调）

| 子方向 | 内容 | 技术方向建议 | 优先级 |
|---|---|---|---|
| **项目官网** | 介绍第一阶段忠实还原引擎（在线试玩链接）、第二阶段新引擎 + 编辑器（功能截图/视频）、文档入口、技术博客 | VitePress（Markdown 驱动、部署简单） | P0 |
| **离线 EXE 发行版** | 引擎 + 编辑器封装为桌面应用，用户下载后无需联网即可使用 | Tauri（Rust 壳 + WebView，~5MB）或 Electron（成熟但重 ~80MB） | P1 |
| **用户系统** | 用户认证（OAuth/邮箱注册）、云存档管理、个人主页 | 后端 API + 对象存储（S3/OSS） | P2 |
| **在线编辑器** | 浏览器内直接打开编辑器、工程托管、分享链接 | 在 P2 用户系统基础上扩展工程存储与权限 | P3 |

### 设计原则

1. **离线优先**：引擎和编辑器的核心功能不依赖后端服务。离线 EXE 版本是无后端功能降级子集，不是独立代码库。
2. **在线功能可选**：云存档/用户系统/在线编辑器是增量能力，不污染第二阶段的本地优先架构。
3. **渐进式上线**：先官网 + 离线 EXE（无后端），再加用户系统 + 云存档，最后做在线编辑器平台。
4. **MMO 留口**：用户系统的认证/存储层为远期 MMO 预留复用空间，但第三阶段不设计 MMO 玩法。

### 建议推进顺序

```
第二阶段收口（W7G + A7-2 + A7-4 + Q1 E2E）
    ↓
P0 官网（VitePress，~1周）
    ↓
P1 离线 EXE（Tauri 壳，~1-2周）
    ↓
P2 用户系统 + 云存档（后端，~3-4周）
    ↓
P3 在线编辑器平台（工程托管 + 分享）
    ↓
远期 MMO
```

## 远期：MMO + 深度玩法

MMO 及其玩法系统（种族 / 门派 / 御灵 / 炼化 / 阵法 / 五灵矩阵 / 因果轮回 / 羁绊…）从第二阶段移出，
存放在 [future-gameplay-and-mmo-backlog](future-gameplay-and-mmo-backlog.md)。
性质 = 愿望清单 / 白日梦，不是承诺。

第三阶段的用户系统/云基础设施完成后，MMO 的技术前提（认证、存储、状态分层）才算具备。
