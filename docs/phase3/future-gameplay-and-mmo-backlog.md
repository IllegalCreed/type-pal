## A. MMO（最远期）

第三阶段愿景 = 基于第二阶段成果做 MMO。个人开发者、缺网络编程经验，这是远期、甚至未必启动的目标。**第二阶段不为它留任何口**（不预先设计实例 / 碰撞 / 同步抽象）——真到那天，那时学到的足够支撑重写，今天的「留口」反而是包袱与焦虑源。

### D5 · MMO 碰撞 / 重叠（原 phase2 决策，移交）

**原决定**：碰撞 / 重叠的 MMO 玩法（互撞与否、网络同步）是第三阶段的活，第二阶段不实现；曾计划在单机就立好三个架构前提让口子自然留住（移动=纯函数判定 / 稳定 id+空间索引 / 碰撞分世界几何与实体两类）。
**方向（非定论）**：玩家间不硬碰撞、可重叠，仅对世界几何 + 特定实体（NPC / 怪 / 交互物）碰撞；重叠按深度基线叠画。理由：俯视角窄通道硬碰撞 = 堵门卡位 + 同步抖动，且是 MMORPG 惯例。
**2026-06-25 处置**：MMO 框架整条移交本目录、**第二阶段不再为 MMO 留口**。其中「移动=意图→纯函数判定→结果」「稳定 id + 空间索引」本就是干净的现代架构，可作为第二阶段的设计取向保留——但**理由改为「好架构 / 可测」，不再是「为 MMO」**，且按内容实际需要决定复杂度，不为未来场景过度设计。

## B. 战斗 / 成长系统（移交：MMO/RPG 量级玩法，第二阶段不碰）

> 第二阶段做「故事内容 + 引擎 + 编辑器」，不重做战斗 / 成长系统（可复用原版战斗，甚至少打架）。下面是曾经的设想，留待第三阶段。

### D6 · 回合制保持 + 身法为策略轴（原 2026-06-24）

**决定**：战斗保留回合制（仙剑风格，不切 CTB / ATB / 半实时）；把「身法」做成可被技能 / 装备 / 阵法 / 状态主动调控的策略资源（参考梦幻西游抢速博弈）；原版辅助类「无条件优先出手」改为受身法影响。
**理由**：原版身法系数（防御×5 / 合击×10 / 辅助施法×3 / 逃跑÷2）本就是 CTB 思想雏形，天然能升级成策略轴且不破坏原版数据；辅助无条件优先出手削弱了抢速博弈的意义。

### D7 · 多难度绑定 AI 强度（原 2026-06-24）

**决定**：支持多难度档（简单 / 普通 / 困难 / 噩梦），难度参数化作用于敌方 AI 强度（aggressiveness / 决策质量 / 资源消耗倾向），而非简单改血量。
**理由**：原版单一难度 + AI 是 fallback 表，太傻；数据驱动 AI（行为树 / 节点图 + Boss 多阶段）是仙剑历代特色，难度绑定让同一套内容服务不同玩家。

### D8 · 仙术熟练度 / 重数取代属性经验值（原 2026-06-24）

**决定**：用仙术熟练度 / 重数（常用某仙术 → 熟练度↑ → 突破第 N 重，威力 / 效果 / 消耗变化）取代原版「隐藏属性经验 + 等级」系统。
**理由**：原版隐藏属性经验藏在底层、玩家不可见，且身法槽是死字段；熟练度让成长可见、可选择，把隐式机制显式化为玩家能感知的成长轴。

### D9 · 战斗数值维度扩展（原 2026-06-28，作者灵感）

**设想**：在 D6「身法策略轴」基础上扩展战斗数值维度——
- **不要行动值**：出手顺序由身法（D6）管，行动值冗余。
- **暴击**：可变暴击率（取代原版固定概率）。
- **命中 / 闪避**：成对属性（攻方命中 ↔ 守方闪避）。
- **防御拆分**：单一防御拆成「物理防御 + 各类抗性」（抗性维度呼应议题 7 标签克制 / 议题 18 五灵矩阵——抗性即标签的一种）。

**前提**：这些属性服务于战斗机制，而机制本身（暴击 / 命中公式、克制倍率）尚未设计；属性的确切形态待机制定时一并确定。**第二阶段不碰**，菜单的角色 schema 只放通用核心（HP/MP/攻防法速/等级/装备），留扩展口即可。
