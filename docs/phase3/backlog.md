## 候选内容

以下保留原愿景与理由，不以措辞“决定”授予当前产品实施。

### A. MMO（最远期）

第三阶段愿景 = 基于第二阶段成果做 MMO。个人开发者、缺网络编程经验，这是远期、甚至未必启动的目标。**第二阶段不为它留任何口**（不预先设计实例 / 碰撞 / 同步抽象）——真到那天，那时学到的足够支撑重写，今天的「留口」反而是包袱与焦虑源。

#### D5 · MMO 碰撞 / 重叠（原 phase2 决策，移交）

**原决定**：碰撞 / 重叠的 MMO 玩法（互撞与否、网络同步）是第三阶段的活，第二阶段不实现；曾计划在单机就立好三个架构前提让口子自然留住（移动=纯函数判定 / 稳定 id+空间索引 / 碰撞分世界几何与实体两类）。
**方向（非定论）**：玩家间不硬碰撞、可重叠，仅对世界几何 + 特定实体（NPC / 怪 / 交互物）碰撞；重叠按深度基线叠画。理由：俯视角窄通道硬碰撞 = 堵门卡位 + 同步抖动，且是 MMORPG 惯例。
**2026-06-25 处置**：MMO 框架整条移交本目录、**第二阶段不再为 MMO 留口**。其中「移动=意图→纯函数判定→结果」「稳定 id + 空间索引」本就是干净的现代架构，可作为第二阶段的设计取向保留——但**理由改为「好架构 / 可测」，不再是「为 MMO」**，且按内容实际需要决定复杂度，不为未来场景过度设计。

### B. 战斗 / 成长系统（移交：MMO/RPG 量级玩法，第二阶段不碰）

> 第二阶段做「故事内容 + 引擎 + 编辑器」，不重做战斗 / 成长系统（可复用原版战斗，甚至少打架）。下面是曾经的设想，留待第三阶段。

#### D6 · 回合制保持 + 身法为策略轴（原 2026-06-24）

**决定**：战斗保留回合制（仙剑风格，不切 CTB / ATB / 半实时）；把「身法」做成可被技能 / 装备 / 阵法 / 状态主动调控的策略资源（参考梦幻西游抢速博弈）；原版辅助类「无条件优先出手」改为受身法影响。
**理由**：原版身法系数（防御×5 / 合击×10 / 辅助施法×3 / 逃跑÷2）本就是 CTB 思想雏形，天然能升级成策略轴且不破坏原版数据；辅助无条件优先出手削弱了抢速博弈的意义。

#### D7 · 多难度绑定 AI 强度（原 2026-06-24）

**决定**：支持多难度档（简单 / 普通 / 困难 / 噩梦），难度参数化作用于敌方 AI 强度（aggressiveness / 决策质量 / 资源消耗倾向），而非简单改血量。
**理由**：原版单一难度 + AI 是 fallback 表，太傻；数据驱动 AI（行为树 / 节点图 + Boss 多阶段）是仙剑历代特色，难度绑定让同一套内容服务不同玩家。

#### D8 · 仙术熟练度 / 重数取代属性经验值（原 2026-06-24）

**决定**：用仙术熟练度 / 重数（常用某仙术 → 熟练度↑ → 突破第 N 重，威力 / 效果 / 消耗变化）取代原版「隐藏属性经验 + 等级」系统。
**理由**：原版隐藏属性经验藏在底层、玩家不可见，且身法槽是死字段；熟练度让成长可见、可选择，把隐式机制显式化为玩家能感知的成长轴。

#### D9 · 战斗数值维度扩展（原 2026-06-28，作者灵感）

**设想**：在 D6「身法策略轴」基础上扩展战斗数值维度——
- **不要行动值**：出手顺序由身法（D6）管，行动值冗余。
- **暴击**：可变暴击率（取代原版固定概率）。
- **命中 / 闪避**：成对属性（攻方命中 ↔ 守方闪避）。
- **防御拆分**：单一防御拆成「物理防御 + 各类抗性」（抗性维度呼应议题 7 标签克制 / 议题 18 五灵矩阵——抗性即标签的一种）。

**前提**：这些属性服务于战斗机制，而机制本身（暴击 / 命中公式、克制倍率）尚未设计；属性的确切形态待机制定时一并确定。**第二阶段不碰**，菜单的角色 schema 只放通用核心（HP/MP/攻防法速/等级/装备），留扩展口即可。

##### 从第二阶段移入的增强（2026-09-03 用户拍板）

以下增强统一由第三阶段承接，均未开实现任务：

1. **真实时间与天气**：在第二阶段已完成昼夜氛围之上增加流动时钟、天气状态及场景/渲染响应。
2. **预制库主动更新（A6）**：用户显式检查服务器新版并选择是否导入，不得自动覆盖现有工程。
3. **试玩前置世界状态（X5 增强）**：启动试玩前配置世界变量、剧情标志等测试前提。
4. **随机笔刷与自动拼接地图块（W7 增强）**：提高地图绘制效率，不改变第二阶段已完成的地图模型。
5. **时间旅行调试（D13 增强）**：按效果来源回放或回退状态；第二阶段已有的控制台、检视器、
   战斗构建器、图层显示与帧步进保持完成。
6. **无障碍设置与脚本树键盘导航**：统一设计文字速度、对话回看、高对比、输入重映射和脚本树导航；
   可参考第一阶段生产工具面板、对话历史和物理键到抽象输入的实现，但不照搬旧架构。
7. **内容语义补标**：继续整理 C1 剩余人物语义候选和 C2 未自动迁移精灵的人工动作语义；第二阶段
   已完成的数据模型、编辑能力和用户批准批次保持不变。
8. **意图式创作扩展**：在第二阶段窄版 N6b 完成后，继续设计作者自定义模式、
   局部变量、表达式、返回值、嵌套组合与模式分发；完整对话工作台和场景演出编排工作台也在本阶段建设，
   但都只作为同一 canonical 脚本 AST 的专用编辑视图，不产生第二份数据真值。

这些是第三阶段能力，不反向降级第二阶段已经完成的 W6/W7/X5/D13-1。A1 服务器版本化预制资源库仍是
第二阶段最终收口项，与 A6 分属不同阶段。

第二阶段窄版 N6b、敌队大目录虚拟滚动和 E2E 完成后的 `capture`/Content Studio 录制协作仍属于
第二阶段，未移入本节；本节第 8 项只接 N6b 的通用化与专用工作台扩展。

##### 本地化工作台与多语言内容管理（2026-08-22 用户记录）

第三阶段增加统一的本地化工作台。目标不是只翻译脚本中的对话，而是让作者能在一个地方查找、审阅和维护
**所有玩家可见文本**，包括：

- 对话、旁白、选项及脚本内引用的文本；
- 角色、物品、技能、任务等内容名称与说明；
- 菜单、界面标签、按钮、提示和错误信息；
- 获得道具、战斗反馈、系统通知等运行时显示文本；
- 后续新增模块产生的其他玩家可见文本。

工作台至少应提供按语言、来源和内容域检索/筛选，原文与译文并排编辑，翻译状态和缺失语言检查，
重复、孤立或失效文本诊断，以及从文本条目跳回脚本指令、内容字段或界面定义的来源定位。

**数据边界**：第二阶段已经确定玩家可见文本使用稳定 `TextId + locale` 查表；第三阶段工作台应索引并编辑这份
canonical locale 数据，不再复制出第二套文本真源。实际多语言译文、翻译协作流程和工作台实现均留到第三阶段，
当前第二阶段只维持既有文本机制，不提前扩 schema 或实现。

#### 设计原则

1. **离线优先**：引擎和编辑器的核心功能不依赖后端服务。离线 EXE 版本是无后端功能降级子集，不是独立代码库。
2. **在线功能可选**：云存档/用户系统/在线编辑器是增量能力，不污染第二阶段的本地优先架构。
3. **渐进式上线**：先官网 + 离线 EXE（无后端），再加用户系统 + 云存档，最后做在线编辑器平台。
4. **MMO 留口**：用户系统的认证/存储层为远期 MMO 预留复用空间，但第三阶段不设计 MMO 玩法。

#### 建议推进顺序

```
    ↓

    ↓

    ↓
P1 离线 EXE（Tauri 壳，~1-2周）
    ↓

    ↓

```
