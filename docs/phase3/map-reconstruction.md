## 1. 已确认的创作目标

1. 以完整门、窗、墙段等**美术构件**创作，不要求作者逐块拼切碎的菱形瓦片。
2. 选中一扇门，按住鼠标扫过，按锚点/拼接步距连续刷出一排；快拖不漏段，同位置不重复堆叠。
   一笔可整体撤销，落下的每个实例仍可单独选中/移动/删除。
3. 同一最终 tile 的左右或其它区域可以属于不同构件；不能继续把完整视觉槽的独占当作作者操作边界。
4. 用户基于多份素材确认的生成规则：从构件底部基准向上，按错排格行递增局部遮挡高度；
   **同一目标图层/目标格内，参与合成的有效图像部分取最大高度**。透明空白不贡献高度。
   原作者编辑器制作流程不作为本方案开工前置，不把未取得的工具源码写成已逆向事实。
5. 渐进路线：原图作只读参照，新图用构件重绘；先样例、再逐图/逐依赖闭包替换，不要求先逆恢复全部素材。
6. `map-012` 用户指出由六个房间拼接；目标允许一房一张作者地图，因此不能默认坐标和场景引用原样不动。
   1:1 指布局/交互/剧情语义对照，不要求 tileId、切片方式或文件字节保持原样。

## 3. 建议技术边界（须经试点决定，不是已完成设计）

### 3.1 作者数据与运行产物

优先验证“基础瓦片 + 构件源/实例 → 局部确定性合成 → 当前瓦片/高度/碰撞运行输入”的路线，
尽量复用运行时，不预先承诺完全零引擎改动，也不先决定整图重切或全新渲染器。

- **单一真源**：被构件管理的区域以源/实例为准，生成瓦片是可重建产物；不得源和产物任意双写。
  普通瓦片笔刷在受管区域的行为、显式“拆开为瓦片”及撤销必须定义；未接管区域仍按原方式编辑。
- 保存必须携带重建所需的基础贡献、遮罩、实例与资源引用；不能只保存合成图片。
  删除最高片后应重算剩余片高度，不能留下旧最大值；移动要同时清理旧区域和生成新区域。
- 同图层内才适用本次最大高度规则，不把不同遮挡层、房顶/地面一律压平。相交像素的先后序必须显式稳定；
  门洞/地面透明、阴影、楼梯/桥等例外单列，不靠任意切更细网格掩盖未定语义。
- 碰撞、地形、触发区与图像透明度/遮挡高度正交；沿用明确的“不参与/可通行/阻挡”写入语义。
  视觉合成取 max 不授权碰撞也一律取 max。
- 当前模板放下后不被模板编辑静默回写的合同保持；是否增加显式更新实例另行定规则。
  资源用稳定身份和内容 hash，更新/去重/引用扫描/垃圾回收同时覆盖作者源与运行产物。

### 3.2 构件提取与刷绘

- 从原始数据以 1:1 像素重建指定来源图层，不裁带网格/高亮/缩放插值的截图。
  允许矩形/多边形遮罩与人工修边；保留可用原像素，不声称能恢复被遮挡或已与背景混合的未知部分。
- 每个构件需明确图像/遮罩、锚点、底部基准高度、拼接步距、目标层/碰撞约束和来源。
  步距不能直接拿含透明 padding 的图像宽度代替；朝向变体、转角/端帽、旋转/镜像不是自动成立。
- 先支持明确方向的重复刷绘；自动转角、随机变体等与既有第三阶段随机笔刷议题协调，不默认全纳入首版。
- 手工工作集中在构件入库时的边界/锚点/例外确认，之后多图复用；批量识别只出候选，未经核验不批量落盘。

## 4. 拆房与脚本迁移：遗漏风险清单

### 4.1 地图拆分不等于已决定逻辑场景拆分

“一个房间一张作者地图”已是目标，但逻辑 scene 的边界、过门是否产生新的 loadScene/session，
必须在单房试点明确。当前一个 scene 绑定一个 map，不能假设把图片切开后原 scene 的行为天然不变。
保持同一逻辑场景与拆成多个场景会影响加载、自动行为、离场取消和持久状态，不能靠临时兼容 offset 蒙混。

### 4.2 必须有显式映射和干跑报告

| 类别 | 要迁移或核对的内容 |
|---|---|
| 空间 | 房间边界、坐标原点/基向量、地图/碰撞矩阵、实体/物件/触发区、入口/出口、相机位置与范围 |
| 脚本位置 | 绝对移动/设位置/相机点按目标房间变换；相对位移、方向、速度、等待不因平移改变；高度单独核 |
| 身份与引用 | 旧map/scene/entity/entry到新身份的映射，所有入站/出站引用、场景换图覆写、共享脚本调用上下文 |
| 生命周期 | onEnter/teleport、自动脚本、状态机cursor、实体页/生命周期、一次性奖励、关门/开门及剧情变体 |
| 场景环境 | BGM、ambience、默认战场/战斗音乐、传送出口等归属；不能拆图后悄悄落默认值 |
| 世界状态 | 已拿物品/开过宝箱、共享flags/vars、离房再进、跨房间角色与机关；不能重复生成或丢状态 |

工具按当前 canonical AST/明确字段改写，不能全局搜索数字替换。共享脚本可能服务多房间，
隐式当前场景与显式 target.scene 要分别分析；一个实体跑到区域外不代表应按静态坐标移交另一房。
不明归属、跨房间连续演出、运行时算出的坐标必须列为人工核定项，不用“全部自动”掩盖。
跨图入口可利用已存在 entryId；普通移动当前仍是 GridPos，不冒称已有通用命名路径点系统。

### 4.3 迁移事务与回退

- 先生成完整影响清单和 dry-run，引用闭包/守卫通过后以一个依赖闭合的包切换。
  粒度可以是一房，也可能因共享脚本而是几房；不能为了“一房一提交”留下半套引用。
- 地图、资产、场景、脚本、目录索引和必要baseline一起原子发布；过程中断可恢复。
  第二次执行零计划/零diff，输入不漂移；回退必须连同引用/资源回退，不仅恢复一张图片。
- 作者重建成果不得被日后PAL重迁覆盖。正式接入现有作者保存/事务发布与冲突机制，
  禁止把手工改生成目录当完成；迁移有根因缺陷仍先修上游。
- 上线前沿用单一当前 canonical 纪律：第三阶段若升版本，在开工时统一决定并重建当前工程，
  不预占版本号、不保留长期旧坐标/旧schema运行时双读。旧开发档和受影响E2E checkpoint重建。

## 5. 渐进里程碑与验收出口

阶段归属已记，下面是建议实施顺序；每段开工仍须明确 Owner、写入范围、用户可见取舍和可证伪验收。

| 切片 | 交付出口 | 不带入的工作 |
|---|---|---|
| P3-M0 源与范围冻结 | 选一个房间/一扇门；冻结原图/场景/脚本/入口及参照图，列坐标与依赖影响，决定逻辑scene边界 | 不扫描完全部地图才启动，不立即升级schema |
| P3-M1 构件最小工具闭环 | 像素提取、底部/步距、连续刷绘、同格拼片max高度、单门删移、一笔undo、保存重开、运行产物确定性 | 不批量逆恢复素材、不做大通用美术工作站 |
| P3-M2 单房拆分迁移 | 先保留旧美术，用当前合法地图/场景输出完成坐标/引用迁移；入口往返、剧情状态、异常回退和二跑幂等 | 不同时重画布局以免混淆问题 |
| P3-M3 单房构件化重绘 | 使用M1素材在M2固定坐标里重绘；叠图/像素差分、碰撞、人物遮挡、剧情E2E与再进房通过 | 不把同mapId偷换用于一拆多，不跳过共享场景检查 |
| P3-M4 主题资源包扩展 | 室内门窗墙柱等可复用素材按房间复用，逐依赖包替换并有回退；报告实际每房人工作业量 | 不把全PAL地图重绘设为第二阶段或第三阶段所有方向共同前置 |

### 验收不能只有截图

- 画面：来源/生成像素、接缝/透明边界、原始尺度与放大、门前/后/边缘角色遮挡；max政策例外显式记录。
- 编辑：不同缩放下快拖无漏项/重复；删除高片后低片图像/高度正确；旧位置清理；失败不丢草稿；
  undo/redo、保存重开、克隆/导出导入不丢作者源。
- 编译：同输入同hash，局部更新与全量重建结果一致；未动区域不漂移；资源闭包、派生资产GC、损坏cache可重建。
- 运行：入口/出口和角色位置、物品只取一次、往返与读档、跨房剧情/默认音乐/战场、脚本取消/重入无语义漂移。
- E2E：保留片段ID和业务断言，更新房间路由/命名入口与版本相关checkpoint；明确哪些截图变化是批准的美术差异，
  不整体放宽oracle。录像素材和指纹也更新，不能复用旧图旧档冒充新验证。
- 性能：连续刷大量实例、局部合成/历史内存、资源数量与产物体积各设测量预算，再决定是否需要缓存或引擎优化。
  实际预算在M0/M1测样后定，不发明百分比/帧率门槛。
