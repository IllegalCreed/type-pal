# 编辑器整体翻新与质量审查后续备忘（2026-08-14）

Status: backlog（已记录产品方向，不是 build authority）

## 用户拍板

- 当前最满意的视觉与信息架构参照是 **角色模块**：层级合理、功能分区清晰、样式清爽。
- 当时工作重心保持 **B2 战场条目 CRUD 七环**；B2 已于 2026-08-15 用户验收 done，当前转入
  **ED-DS-1 设计规范先行**，仍不得扩大为一次性重写整个编辑器。
- B2 完成后，必须先形成一份可执行、可验收的完整编辑器设计规范，再沿三条独立主线系统审查并
  拆卡实施：视觉统一、创作七环、代码质量。禁止在规范冻结前逐模块凭感觉翻新。

## 设计规范先行（用户拍板，2026-08-15）

Normative v1.0.0：[`editor-design-system-v1.md`](../../specs/editor-design-system.md)。ED-DS-1 已于 2026-08-15
完成 Codex 自审、GLM accept、Kimi 用户豁免及用户六项产品裁决；后续编辑器任务必须引用具体条款。

整体翻新的第一张任务卡应是编辑器设计规范，而不是某个业务模块改版。规范至少必须冻结：

1. **设计基础**：颜色语义、字体层级、字号/行高、间距阶梯、圆角、描边、阴影、图标尺寸、动效与
   disabled/focus/error/warning/success 状态；不得只给几张效果图。
2. **布局语法**：应用壳、模块导航、对象列表、主工作区、Inspector、抽屉/弹窗、滚动归属、最小/理想
   宽度，以及 1280 / 900 / 720 三档响应式规则。
3. **组件模式**：列表头与数量、搜索、tab、卡片/分组、字段行、选择器、引用卡、创建/复制/删除、
   空状态、加载/错误状态、危险操作、媒体预览画布等标准形态。
4. **交互规则**：选择与深链、焦点/键盘、dirty/save、undo/redo、删除阻断、跳转回执、长任务反馈、
   文案与命名规范。
5. **媒体规则**：图像/精灵/地图/战场预览的 fit、缩放、平移、1:1、重置、透明背景与元数据布局。
6. **实现合同**：tokens、CSS variables、共享 primitives、允许的模块级扩展、禁止的局部魔法数与反模式；
   角色页和战场页作为参考输入，但最终也必须接受同一规范复核，不能自动成为不可质疑的标准答案。
7. **验收样板**：为宽/中/窄三档、长中文/英文、空库/大库、无图/宽图/高图、错误/禁用/聚焦状态提供
   可重复的 fixture 或 reference page，并列出视觉与交互检查表。

规范冻结后，所有模块翻新卡必须引用具体规范条款；若实现需要偏离，必须记录例外理由并回写规范或取得
产品裁决。仅“看起来更好”不能作为验收依据。

## A. 视觉与交互统一审查

以角色模块为基准，而不是只统一颜色或圆角。审查对象包括一级模块、列表/工作区/摘要区的信息层级、
标签页、表单密度、响应式布局、空状态、错误状态、长文本和资源预览。

首批明确反例：

1. **资源 / 图像**：当前图像全部压缩在面板上方，缺少作为主内容的预览空间；不能缩放、平移、适配窗口或
   1:1 查看。后续应有稳定预览画布、缩放控制、尺寸/引用信息与资产操作分区。
2. **战斗模块**：当前各页布局、信息优先级和操作分组不统一。B2 只先把战场条目工作台做成可复用参考纵切，
   不在 B2 内顺带重写技能、敌人、毒、队伍等全部战斗页面。
3. **全局一致性**：导航、列表头、数量、标签页高度、卡片/分组、选择器、危险操作、窄屏换行和滚动区域
   必须采用统一规则；不得让媒体预览或核心操作被摘要面板挤压。

未来视觉验收至少覆盖 1280 / 900 / 720 三档、长中文/英文名称、空库/大库、无图/超宽图/超高图，
并为图像预览钉缩放、平移、适配窗口、1:1 和重置行为。

## B. 全模块创作闭环审查

沿用 [ED-1 七环](editor-authoring-closure-audit-2026-07-13.md)，不另造口径。每个可管理对象必须逐项核验：

1. 发现 / 选择；
2. 创建；
3. 引用 / 绑定；
4. 编辑；
5. 预览 / 运行；
6. 保存 / 重开；
7. 删除约束。

只会修改迁移后的既有条目不算闭环；UI 看似可操作但 serializer、loader、引用图或删除保护不闭合也不算。
审查需覆盖场景、地图、剧情、角色、物品、战斗、资源、工程八个一级模块，并以空白工程与保存重开证据
恢复 capability-map 状态。

## C. Reforge / Editor 代码质量审查

在功能真值稳定后独立进行，不用“重构”替代缺失功能。检查范围至少包括：

- `@type-pal/content` / `@type-pal/reforge` / `@type-pal/editor` 职责与依赖方向；
- 领域逻辑、命令/状态、I/O、引用图、运行时与 React 视图的边界；
- 高内聚低耦合、稳定公共接口、合理复用，避免巨型组件、跨域工具箱和重复分支；
- 模块拆分、命名、错误语义、不可变更新、事务/撤销边界与测试可替换性；
- 注释解释“为什么、约束和不变量”，不重复代码表面行为；
- 删除死代码、临时兼容层与无 owner 的抽象；以复杂度、依赖和回归证据拆分后续重构卡。

## 排期与边界

1. **历史前置：B2（done）**。战场条目七环与第二个视觉参考纵切已完成。
2. **B2 后：设计规范（done）**。ED-DS-1 已冻结 v1.0.0：tokens、布局/组件/交互合同与 reference
   fixtures 均有明确条款。
3. **规范后：实现地基与整体审计**。先由 ED-DS-2 代码化 tokens/primitives/Design Lab，再按 A/B/C
   三线以规范为尺形成现状矩阵和优先级，不直接开一个“重做全部
   编辑器”的巨卡。
4. **分批实施**。每张会改变用户可见行为、schema、公共接口或 capability 状态的任务，必须先完成
   AGENTS.md 的四向前提真值矩阵和三方签字。

本备忘只记录方向，不授权修改实现、schema、save、资源管线或 capability 状态。
