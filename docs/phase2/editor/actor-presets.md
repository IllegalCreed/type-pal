# 人物预制与场景实体创作说明

> 对应能力：C1-1。人物预制只复用身份与资源，不是带行为继承的完整 NPC prefab。

## 三种放置方式

- **预制人物**：先在“角色”模块建立人物，再在场景中放置。实体保存 `actor` 引用；姓名、默认大世界
  精灵、立绘组、小头像和可选战斗资料来自人物定义。
- **自定义实体**：直接选一个大世界精灵放置。实体保存 `sprite` 引用，适合门、箱子、机关、装饰、
  一次性群众或暂时不需要稳定人物身份的对象。
- **触发区**：没有视觉资源，只提供触碰或交互脚本入口。

三者只描述作者如何得到实体，不代表 NPC、敌人或物件等玩法职责。职责仍由页面脚本、`hostile`、
碰撞等实例结构表达。

## 什么会共享，什么不会共享

人物定义共享：

- 显示名称与稳定人物 id；
- 默认大世界精灵；
- 对话立绘组与菜单小头像；
- 可选的队伍、战斗、成长和关系资料。

场景实例独占：

- 实体 id、位置、朝向、碰撞、显隐和层级偏移；
- 页面、触发脚本、自动行为；
- 敌对配置与场景内生命周期。

因此，同一人物可以放进多个场景。修改人物的默认精灵会让仍关联的实例统一换形象；移动其中一个实例或
修改它的脚本，不会改变人物定义，也不会影响其他实例。

## 解除人物关联

选中 actor 实例后，检查器提供“解除人物关联，保留当前精灵”。该操作把当前 `actor` 解算为人物此刻的
默认 `sprite`，并原样保留全部实例字段。它是单一可撤销操作：

1. 解除后，人物未来改名、换立绘或换默认精灵不再影响该实例；
2. 撤销后恢复原人物引用；
3. 不会复制或删除共享精灵、立绘、locale 文本等资源。

如果对象仍应代表一个稳定人物，只是需要另一套共享资源，应复制或新建人物；只有确实要脱离共享身份时
才解除关联。

## 创建、复制和删除

- 新建人物至少需要无首尾空格的稳定 id、显示名称和已存在的默认精灵。
- 创建时名称 locale 与人物定义在同一个撤销事务中写入，失败不会留下半条数据。
- 复制会深拷贝人物定义和该人物的升级习得表；精灵、立绘等共享资产仍只复制 id 引用。
- 删除前会列出所有外部引用并阻止留下悬空 id。引用按钮可跳到对应场景、入口、人物、物品、敌人或脚本。
- 删除人物不会自动回收 locale、精灵、立绘、小头像或战斗精灵；这些可能仍被其他作者对象使用。
- 显式加载的运行态队伍/后备成员属于只读存档数据，也会阻止删除，但不会被编辑器静默改写。

悬空 actor 实体在当前运行时会因为无法解算精灵而不渲染；这不是安全兜底。作者工作流依赖删除门禁和
加载/保存诊断保证悬空引用不能进入合法工程。
