# 脚本库与可复用脚本作者手册

可复用脚本用于“改一处，所有调用方同时生效”的项目级逻辑。它不是减少录入步骤的万能容器，也不会替代结构化能力、普通指令和编辑器模板。

脚本库界面同时承担两种内容的查看入口，但二者身份不同：

- **可复用脚本**：作者可命名、可独立调用的项目公共 API，登记在 `content/scripts/index.json` 的 `library`。
- **迁移内部实现**：迁移器为旧版分支、跳转和回环保留的控制流块。当前仅作为过渡诊断入口，
  不是作者公共 API，也不是终态内容模型。

“被另一个脚本调用”不等于“可复用”。只有具备稳定业务语义、需要由多个作者调用点共同使用的逻辑，才应该提升为可复用脚本；仅为承接一条旧版跳转边或循环而拆出的块继续属于迁移内部实现。

## 什么时候用哪一种

| 需求 | 选择 | 原因 |
|---|---|---|
| 只在一个事件里出现的对话、给物品、移动 | 普通指令 | 行为直接留在事件中最容易阅读 |
| 多次录入同一类流程，但文本、物品、数量等参数各不相同 | 模板 | 模板插入后展开为普通指令，各处可独立修改 |
| 物品回复、状态、传送出口等已有结构化能力 | 结构化能力 | 可编辑、可校验，运行时不必再解释脚本 |
| 多个场景或实体必须执行同一段固定逻辑，修改后要全部同步 | 可复用脚本 | 所有调用方只保存稳定脚本引用，不复制命令体 |

当前版本只提供 `self` 执行实体上下文，不提供通用参数、返回值或局部变量。需要不同参数的流程应继续使用模板，不要为复用而把差异藏进全局变量。

## 创建与编辑

1. 在编辑器“剧情”模块打开“脚本库”，选择“可复用脚本”。
2. 点击列表标题栏的 `＋` 新建脚本，填写显示名、说明和 `self` 契约。
3. 在指令树中插入并编辑指令。位置无关脚本直接编辑，不显示无意义的地图；调用链含实体、坐标、面向判断、当前场景出口或场景切换时，先选择一个真实场景再预览对应分支。
4. 显示名可以修改，`shared/user/...` 稳定 id 创建后不会随名称变化。
5. “复制”会创建新的稳定 id 和独立命令体；它不是原脚本的别名。

`self` 契约含义：

- `不使用`：脚本不依赖执行实体，调用时不需要指定 `self`。
- `可选`：有调用实体时继承或覆盖，没有时也允许执行。
- `必须提供`：调用点必须能继承当前实体，或显式选择一个场景实体；否则工程校验失败。

## 调用与跳转

在场景或实体脚本的插入菜单选择“调用可复用脚本”，再选择作者脚本。调用行只保存目标稳定 id、派生 chunk 提示和可选 `self`，不会复制脚本体。

调用行的“打开目标”可直接进入脚本库。脚本库的“扫描调用位置”按需扫描工程，列出场景、实体、其他可复用脚本和迁移内部实现中的直接调用方；点击调用位置可回到源位置。

## 删除与错误

- 有直接调用方的作者脚本不能删除；先根据引用列表处理调用点。
- 无引用脚本删除后，空分片会自动收敛；撤销可完整恢复元数据和命令体。
- 作者可复用脚本之间不允许形成 `callScript` 调用环。
- 在作者可复用脚本体中硬编码 `e12` 之类的场景实体 id 会产生警告。跨场景逻辑应优先使用 `self`。
- 保存会阻止悬空引用、缺失命令体、非法作者 id 和作者调用环。

## 迁移内部实现

脚本库的“迁移内部实现”页签暂时列出当前工程中的 `shared/scc-*` 控制流块，并显示原版入口和
直接调用方，用于查清迁移数据、追踪旧调用链和修复当前工程。它们没有作者侧创建、命名、删除和
稳定引用闭环；作者不得新建对它们的引用，也不得把这个页签当成共享脚本库。

这是一项已确认的迁移债务，不是长期保留方案。后续由
[`N3-1`](../../ops/tasks/N3-1-script-control-flow-modernization.md) 从上游把它们分别还原为场景/
实体的具名本地行为、结构化控制流或真正的可复用脚本；物理分片和运行时块将退出作者心智模型。
在 N3-1 三方设计签字与迁移完成前，现有页签只代表“可诊断的过渡态”，不得据此宣称脚本创建/
编辑闭环已经完成。

## 待迁移诊断

无法无损翻译为结构化能力或脚本命令的旧版用途，必须留在“问题与高级”作为待迁移诊断。它们既不是空的可复用脚本，也不是已经可运行的迁移内部实现，不能混入脚本库冒充完成。

作者可复用脚本保存在 `content/scripts/index.json` 的 `library` 元数据和现有分片命令体中。MG2 重迁会按稳定 id 三方合并：作者独有内容保留，双方同时修改同一命令体时显式报冲突，不会静默覆盖。
