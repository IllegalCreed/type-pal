# 编辑器创作闭环与一级模块审计（2026-07-13）

状态：历史审计快照。ED-1 三方设计签字已于 2026-07-14 集齐；一级模块由 ED-2 落地。

> **地图结论已更新（2026-07-14）**：W7E 双格式方案已取消，W7F 已用 ProjectMapV2、
> `SceneDef.mapId` 和 MapIndex 统一迁移图与作者图。下文 OwnMap/reuseOriginalMap 只记录审计当时的
> 缺陷，不再是现行设计；当前真值见 `content-schema.md` §5 与 W7F 任务卡。

配套任务卡：[`ED-1-editor-authoring-closure-audit.md`](../../ops/tasks/ED-1-editor-authoring-closure-audit.md)

## 1. 结论

当前编辑器已经具备一套可靠的技术外壳：工程打开/保存/导出、Command/undo、场景画布、
脚本编辑、若干数据表单和实时预览都真实可用。但它目前更接近“修改迁移后 PAL 工程的工具”，
还不是“从空白工程制作完整 RPG 的创作平台”。

这不是缺几个按钮，而是三类系统性问题叠加：

1. **资产与引用没有分层**：地图没有独立资产索引，地图只能跟着当前场景出现；场景也不能显式选择已有自有地图。
2. **空白工程只做到能启动，没有做到能持续创作**：第二个场景会退回不存在的原版地图 0；角色、物品、音乐、战场、过场等领域缺少创建或删除闭环。
3. **信息架构仍按实现历史组织**：顶层只有“场景 / 角色 / 地图 / 数据”，而“数据”再塞入 15 个不同工作域，业务边界和作者心智不一致。

因此本轮不应只补“地图列表”。应先建立统一闭环判据、重排一级模块，再按依赖修地图资产、
引用安全、场景/实体生命周期和各领域 CRUD。已经闭环的工程生命周期、共享脚本和脚本编辑器保留，
不推倒重做。

## 2. 闭环判据

今后“编辑器能编”不再只表示“能修改一条已有记录”。每个可创作领域至少检查以下七环：

| 环 | 判据 |
|---|---|
| 发现/选择 | 能从明确列表找到对象，能按 id/名字过滤并看到引用状态 |
| 创建 | 空白工程可创建第一条；已有工程可新增、复制，不依赖手改 JSON |
| 引用/绑定 | 使用方通过选择器引用稳定 id；可从引用处打开目标，也可查看反向引用 |
| 编辑 | 核心字段有结构化编辑入口，所有改动经过 Command/undo |
| 预览/运行 | 能在合适语境预览，或一键进入真实引擎验证 |
| 保存/重开 | 保存后由正式 loader 重开仍可发现，FSA/另存为/zip 不丢数据与资产 |
| 删除约束 | 被引用对象禁止静默删除；解除引用后可删除，文件清理规则明确且可撤销 |

状态口径：`✅` 七环在本领域适用范围内闭合；`⚠️` 可用但至少一环缺失；`❌` 空白工程无法完成该领域的基本创作。

## 3. 主要发现

### P0-1：空白工程新增第二个场景会得到不可用地图

- 空白工程的起始场景使用 `content/maps/start.json` 自有地图：`packages/editor/src/core/seed.ts:130`。
- “新建场景”却执行 `reuseMapNum(scene.map) ?? 0`：`packages/editor/src/ui/App.tsx:580`。
- `AddSceneCommand` 固定生成 `{ reuseOriginalMap: mapNum }`：`packages/editor/src/core/commands.ts:1734`。
- 空白工程不带原版地图 0；因此从自有地图场景新建场景后，正式画布/引擎加载链没有可加载资产。

影响：产品宣称“空白工程可创作”，但最基本的第二场景就会断链。该问题优先级高于地图工具增强。

### P0-2：地图不是独立资产，场景到地图的绑定没有闭环

- `MapMode` 只接收当前 `scene`，再从 `scene.map.ownMap` 推导唯一编辑对象：
  `packages/editor/src/ui/App.tsx:491`、`packages/editor/src/ui/MapMode.tsx:84`。
- 场景检查器对原版地图只给数字输入；对自有地图只显示只读路径，没有选择器：
  `packages/editor/src/ui/App.tsx:1426`。
- 创建自有地图会直接写死 `content/maps/<scene.id>.json` 并同时改当前场景：
  `packages/editor/src/ui/MapMode.tsx:382`、`packages/editor/src/core/commands.ts:351`。
- loader 只扫描场景引用来发现地图，并明确把“场景引用”当索引：`packages/reforge/src/loader.ts:335`。
- serializer 虽会写 `state.maps`，但重开时未被场景引用的地图无法再次发现：
  `packages/editor/src/core/project-io.ts:99`。

影响：不能列出全部地图、不能创建未绑定地图、不能让多个场景复用一张自有地图、不能安全换绑、
复制、重命名或删除地图。把地图列表加在现有 UI 上仍会被底层“无索引”卡住。

### P0-3：空白工程的核心内容 CRUD 不完整

- 角色模块只有列表和 `UpdateActorCommand`，无创建/复制/删除：
  `packages/editor/src/ui/ActorMode.tsx:79`、`packages/editor/src/core/commands.ts:1183`。
- 物品页只有 `UpdateItemCommand`，空白工程的 `items: []` 无法从 UI 产生第一件物品：
  `packages/editor/src/ui/ItemTab.tsx:292`、`packages/editor/src/core/seed.ts:127`。
- 技能可创建但不可安全删除：`packages/editor/src/ui/SkillTab.tsx:419`。
- 战场只能修改已有条目；音乐只能改别名；过场页完全不进入 EditSession：
  `packages/editor/src/ui/BattleFieldTab.tsx:118`、`packages/editor/src/ui/MusicTab.tsx:34`、
  `packages/editor/src/ui/CutsceneTab.tsx:31`。
- 毒、氛围、商店可以创建，但没有正式删除入口与引用处置流程。

影响：作者可以调整迁移数据，却无法只靠编辑器构造一套新的角色、物品、战斗与世界内容。

### P0-4：若干“资源库”仍是原版资产浏览器，不是工程资源管理器

- `MusicDef` 只有数字 id 和别名，运行时把 id 隐式拼成 `<NNN>.mid`：
  `packages/content/src/index.ts:19`、`packages/reforge/src/audio/bgm.ts:57`。
- 过场页硬编码 1-6 号视频，并直接读取 `/extracted`：
  `packages/editor/src/ui/CutsceneTab.tsx:17`、`packages/editor/src/ui/CutsceneTab.tsx:38`。
- 路线图已经把 A7 工程资源闭包与 R7 稳定资源注册表列为后续主线，当前 UI 不应继续把这些页标成完整创作能力。

影响：克隆 PAL 工程时看起来可用，空白/独立工程却没有导入、登记、替换和删除资源的链路；也会阻塞后续资源自包含和替代资源工作。

### P1-1：“数据”是历史容器，不是合理的一级模块

- 顶层只有四个模式：`场景 / 角色 / 地图 / 数据`：`packages/editor/src/ui/App.tsx:456`。
- `DataMode` 内有 15 个标签，混合精灵、技能、物品、敌人、毒、氛围、商店、战场、音乐、
  瓦片集、过场、入口、变量、指令手册和共享脚本：`packages/editor/src/ui/DataMode.tsx:41`。

这些对象的工作流、画布、引用关系和使用频率都不同。继续在“数据”里加标签会让地图资产、剧情脚本、
资源导入和工程设置都找不到稳定归属，也使每个页面被迫复用不合适的三栏布局。

### P1-2：删除策略和反向引用实现不一致

- 共享脚本删除会先查调用方并阻止悬空引用：`packages/editor/src/core/commands.ts:1139`。
- tileset 删除不检查 `OwnMap.tileset`；精灵删除允许先删再由底栏报错：
  `packages/editor/src/core/commands.ts:732`、`packages/editor/src/core/commands.ts:2028`。
- 多数领域没有删除命令，另一些领域可删但没有“被谁引用”的统一面板。

影响：同一个编辑器里有三种互相矛盾的删除语义：不能删、直接删、引用时拦截。需要统一工程引用图，
而不是每个页面继续手写一套。

### P1-3：底部“引用完整性 OK”覆盖面不足，文案会造成过度承诺

- 底栏直接把 `validateReferences(state)` 的空结果显示为“引用完整性 OK”：
  `packages/editor/src/ui/App.tsx:867`。
- 当前校验只覆盖部分 actor/sprite/item/skill/enemy 引用，没有校验地图文件、地图 tileset、
  场景/入口、音乐、氛围、商店、战场、过场资源等完整工程图：
  `packages/content/src/validate-refs.ts:72`。
- 脚本分片另有更完整的专用引用图，但尚未成为统一工程引用系统：
  `packages/editor/src/core/script-references.ts:48`。

影响：作者可能在出现“OK”时仍保存一个无法重开的地图或悬空资源引用。短期应把文案改为“已检查的引用无问题”，长期合并为可跳转的工程问题面板。

### P1-4：场景与实体生命周期仍偏向既有内容修补

- 场景可新增但不能复制、重命名、删除，也没有入口场景/跨场景引用的删除处置。
- **2026-07-15 ED-4A 已修**：放置工具可从 ActorDef 或 SpriteDef 创建可见精灵，也可创建
  touch/interact zone；zone 自带合法空脚本，统一进入命令栈并支持保存重开。
- 实体职责模板仍未设计；NPC、敌人、物件、宝箱等职责不得从 sprite 推断。门归物件模板，
  不作为平级职责。
- 实体删除仍没有先展示脚本或共享引用影响；场景生命周期也未闭环。

影响：新实体形态已无需手改 JSON；E1 仍因场景生命周期、职责模板和引用删除守卫保持 ⚠️。

## 5. 一级模块信息架构

“数据”一级入口应退役。一级导航按作者任务而不是 JSON 文件类型组织：

| 一级模块 | 主要内容 | 从现有位置迁入 |
|---|---|---|
| 场景 | 场景列表、实体、入口、场景属性、场景脚本、地图/音乐/氛围绑定 | 现“场景” + 场景相关选择器 |
| 地图 | 地图资产列表、图层/碰撞/尺寸、瓦片集、使用场景 | 现“地图” + 数据/瓦片集 |
| 剧情 | 共享脚本、变量/flag、指令手册、过场编排、全局文本引用 | 数据/共享脚本、变量、指令手册、过场 |
| 角色 | 角色库、世界精灵、头像/立绘、战斗形象、成长/初始技能 | 现“角色” + 角色相关精灵入口 |
| 物品 | 物品、装备效果、商店/当铺、物品引用 | 数据/物品、商店 |
| 战斗 | 技能、敌人、敌队、毒/状态、战场配置、隔离试打 | 数据/技能、敌人、毒、战场 |
| 资源 | 精灵、音乐/SFX、图片/视频、字体/UI、导入与反向引用 | 数据/精灵、音乐；A7/R7 后续资源注册表 |
| 工程 | 入口点、工程设置、locale、问题面板、保存/导出/资源闭包报告 | 数据/入口 + 顶栏工程功能 |

约束：

- 一级是业务域，不是把 15 张表变成 15 个窄图标。
- 当前 52px rail 改为可折叠 `ModuleNav`：展开时显示图标+中文名称，折叠时保留图标；宽度状态继续复用现有面板持久化机制。
- 每个对象只有一个权威编辑页。其他模块的选择器提供“打开目标”深链，不复制第二套表单。
- 各模块可有 2-5 个紧密相关子页，但“数据”这个无业务含义的总容器不再存在。
- 切换模块保存当前对象 id 与子页，返回时不丢选择和滚动位置。

## 6. 地图资产与场景绑定建议

### 6.1 推荐数据形状

地图需要独立注册表，路径不再充当身份。建议新一版 schema 明确区分稳定 id 与文件位置：

```ts
interface MapAssetDefV1 {
  id: string
  name: string
  path: string
}

interface MapIndexV1 {
  version: 1
  maps: MapAssetDefV1[]
}

type SceneMap =
  | { ownMapId: string }
  | { reuseOriginalMap: number; room?: RoomRect } // 只服务 PAL 兼容工程
```

- `manifest.content.maps` 指向 `content/maps/index.json`。
- `EditorState` 以 map id 存工作副本；serializer 按注册表 path 写文件；loader 先读 index，再按需/全量读地图。
- 当前 `{ ownMap: "content/maps/start.json" }` 不可静默改语义。应提升 `contentVersion` 或提供显式兼容迁移，
  把路径转换为稳定 id；同路径冲突必须报错。
- 原版复用地图是 PAL 内容包兼容边界。空白/自有工程默认只展示自有地图，不把“原版地图号”当创作模型。

### 6.2 用户工作流

1. 地图模块左栏列出全部地图，支持新建、复制、改显示名、删除和搜索。
2. 新建地图不会强制绑定场景；创建后可从“使用场景”区绑定，也可回场景模块选择。
3. 场景检查器的“地图”改为对象选择器：选择已有地图、创建并绑定、复制当前地图后绑定、打开目标地图。
4. 多个场景可以引用同一地图；场景的实体、入口和脚本仍独立。
5. 删除地图前展示全部使用场景；有引用时阻止删除。解除引用或选择替代地图后才能删除。
6. 保存/重开后，即使地图暂时没有场景引用，也必须仍出现在地图列表中。

## 7. 共用地基

### 7.1 工程引用图

建立单一 `ProjectReferenceIndex`，把 `scene -> map`、`map -> tileset`、`actor/entity -> sprite`、
脚本命令到 scene/item/skill/music/shop/ambience/battlefield/cutscene，以及共享脚本图统一成带来源路径的边。

用途：

- 删除前阻断与替换建议；
- 详情页“被谁使用”；
- 工程问题面板跳转；
- 保存前 fail-loud；
- A7 资源闭包报告。

引用图应按需或增量构建，不能在每次输入时全量扫描大型 PAL 脚本库。N6 的
`buildScriptReferenceIndex` 已经给出可复用的按需模式。

W7F 目前以 `mapAssetSceneReferences(scenes, mapId)` 扫描 `scene.mapId`，供地图使用场景与删除阻断使用。
ED-3 验收必须把该调用改接统一 `ProjectReferenceIndex`，随后删除这个 helper；
禁止在临时 helper 中继续加入 tileset、sprite、script 等引用域。引用边同时携带
`block / warn / replace-suggest` 删除策略元数据。

### 7.2 空态即验收入口

每个模块必须用空白工程验收：列表为空时不是一句“无数据”，而是可创建第一条、导入或解释为什么该领域不适用。
任何新增模块都至少有一个 `blank -> create -> bind -> save -> reopen -> delete` 集成测试。

### 7.3 资源与内容分层

- 内容对象引用稳定资源 id，不再猜文件名。
- 资源注册表记录 id、显示名、path、类型和必要元数据；实际二进制始终位于工程目录。
- A7 负责资源闭包，R7 负责音乐等隐式编号升级；本轮只把编辑器入口和依赖关系设计对，不抢跑资产迁移。

## 10. 总验收矩阵

- 空白工程：新建第二场景、新建地图、绑定、放 actor/prop/zone、写对话、创建物品/技能/敌人，保存后重开可继续编辑。
- 地图复用：两个场景引用同一地图；改图后两处生效；复制地图后只影响新引用；有引用时删除被阻止。
- 引用安全：删除任一角色/精灵/物品/技能/tileset/地图前能看到调用方；替换后无悬空边。
- PAL 兼容：`projects/pal` 全量打开、切场景、脚本预览、保存/重开不改变未编辑内容；原版地图兼容入口仍可用。
- 工程 I/O：HTTP 种子、FSA 本地工程、另存为和 zip round-trip 一致；未引用但已登记资产不丢。
- 视觉：1280、900、720 三档无重叠；一级模块栏可折叠；各模块空态和长列表均可操作。
- 门禁：content/reforge/editor 单测与 typecheck；根 `pnpm check`；关键创作流程 Playwright E2E。
