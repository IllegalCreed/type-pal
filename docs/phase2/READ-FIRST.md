## 目的

在开始 Reforge 引擎、编辑器、内容 schema 或演出工作前，确定阶段方针、知识来源和停止线。本页是 [AGENTS 操作路由](../../AGENTS.md#操作与必读)要求的现行 L1 规则；它不证明某项实现或执行已经通过。

## 范围

本页约束第二阶段工作。第一阶段忠实还原的知识可供核验，第三阶段的愿景不能自动变成二阶段预留需求。背景与工作入口见[路线](roadmap.md)、[能力地图](capability-map.md)和[阶段决策](decisions.md)；当前任务准入和状态由[活动看板](../tasks/board.md)及原任务卡维护。

## 当前状态

以下十一条规则是现行阶段准入；实现、任务状态与执行结论仍由各自正文和证据维护。

编辑器界面或交互变更还必须先读[设计系统与交互规范](specs/editor-design-system.md)的规范语义及本次命中条款，再读[编辑器UI开工与验收](specs/editor-architecture.md#编辑器ui开工与验收)，核对应共享组件、尺寸上下文与既有同类页面；交付前在实页检查受影响的整行和窄宽布局。不得只读阶段方针、只检查本次点击的按钮，或以静态门通过代替界面一致性验收。

### 十一条铁律

1. **全新重写。** 新引擎和编辑器是全新制作，不是改造旧 `game`；重新实现知识时先明确新架构的职责。
2. **演出差异先归因。** 原版脚本意图与合理呈现优先；第一阶段是重要对照，也可能有 bug。双轨必须比较相关 NPC 的完整位置、朝向、显隐、绘制帧、等待与控制权，不能只比起终点；内部状态和浏览器绘制次数不要求机械一致。差异按[共同演出标准](../testing/e2e/contract.md#演出验收标准意图优先差异不等于缺陷用户2026-10-07)区分缺陷、比较器错误、合理差异与证据不足；不以总时长相近抵消漏动作或等待，不擅改一阶段基线让比较过门（用户2026-10-07）。
3. **移植知识，重新设计模块。** 战斗公式、opcode 语义和渲染数学可以重新实现；旧模块结构和隐式耦合不能随知识搬入。
4. **架构第一，主动审过渡态。** 现代化、解耦、可扩展是判断标准，不能以“迁移语义相等”代替架构审核。脚本写 `sys:*`、跨场景隐式残留、运行时 mutate 静态定义、下标身份出现一项就查同类。静态配置宜用场景→实体→调用参数的明确层次；运行时可变需求走世界状态的显式覆写与重放（X1模式），不复活全局变量。战场全局变量案是2026-07-06的反例，不是恢复 `sys:battleField` 的授权；历史设计中的过渡实现须另核后继。
5. **稳定身份。** 对象、引用和状态键使用稳定 id 或语义名；数组位置与下标不作身份。
6. **显式编排演出，保留资产约定。** 不为重现旧引擎怪癖引入对白与 NPC 移动的全局耦合。参与剧情、自动脚本可能抢先进场或离场的 NPC 在相关窗口须显式接管，并及时释放；无关 NPC 和环境动态精灵继续活动，同时核漏接管与多余冻结（用户2026-07-03、2026-10-10）。对白确认不等于画面消失，动作/释放前的段落清除按共同标准第7项核验（用户2026-10-11）。D20将原版仙剑定位为试炼场和首份内容包，旧“100%复刻即验收”不恢复。

   资产坐标约定必须继承，不能用“不复刻怪癖”解释画错。逐帧位图各自以脚底中心为锚，不能用组首帧尺寸替代；二阶段绘制与命中使用 [spriteBlitRect](../../packages/reforge/src/render.ts)，其统一7px偏移不能被解释成所有一阶段绘制都相同。最终精灵blit不重复叠加sLayer偏移；排序键与cover遮挡几何仍按各自实际合同消费相关层信息，不能简写成“只进排序”；走位朝向按像素轴差判象限，须与新逻辑菱形格轴分清。修此类问题先核[一阶段知识收获](reference/phase1-knowledge-harvest.md)和实际旧实现，如 [toSpriteImages](../../packages/game/src/present/draw-sprite.ts)；本页不重授视觉或原版实测。
7. **分清第一阶段知识的适用层。** [第一阶段入口](../phase1/README.md)所指“忠实、sdlpal、对齐原版”的方法论是旧引擎参考，不是二阶段方针。AGENTS 的协作、质量与授权规则仍适用，不能以阶段隔离跳过。
8. **保留已有 UX 形态，按意图核演出。** 有一阶段对应的界面、交互或演出，先读 `packages/game` 的对应渲染和菜单状态机，再用干净架构表达。没有用户特殊说明时保留图标/文字、网格/列表、布局结构等形态；“更简洁、风格统一、数据少”不足以自行更换。无对应的新 UI 先给 mockup，由用户定形；既定素材偏好为烤九宫格。演出仍按铁律2核实，不强行复制有问题的帧或时序（用户2026-07-04、2026-10-07）。
9. **重写前先 harvest。** 每次动能力格，先读[一阶段知识收获](reference/phase1-knowledge-harvest.md)对应领域，再回读相关代码注释、修复史与工程记录，形成审计清单。战斗和数值先读[机制真值](../phase1/game-mechanics.md)对应专题；它对已核原版机制的具体一手结论优先于 harvest 的二手摘录，但不是二阶段必须采用旧模块/调度的理由。演出、动画、菜单等同样先收获再实现（用户2026-07-05、2026-07-06）。
10. **先核维护权，再修真源。** 来自仍受供应链维护的提取、映射、overlay或生成写盘缺陷，先修可重复的上游，再重导、验根因先红后绿、非白名单不变与第二次零 diff；做不到则 blocked 或明确临时诊断，不报 done（用户2026-07-13）。但路径位于 `projects/pal` 不代表它仍是原版生成产物：[2026-09-30 作者真源裁决](../tasks/archive/done/ARCH-PAL-SUPPLY-1-author-publication-and-import-retirement.md)已令场景/共享/技能/敌AI正文由 canonical 作者维护，合理化直接修改作者工程，不同步或复活退役的原版脚本转换。资源、地图、商店、六角色等明确原始源分区及四伤亡/两提示窄输入，仍按实际供应责任修上游。
11. **开发期只消费当前 canonical。** 正式上线前，编辑器、运行时、当前内容工程与开发期存档不背历史版本兼容。版本切换在同一任务重迁/重生成，并删除旧 upgrader、旧类型、专属 fixture/test、版本分支、升级入口、双读双写和兼容 fallback。仅当仍有无法重建的真实输入，且用户批准、唯一调用方和删除条件明确，隔离转换器才可临时保留；“以后可能用到”或“测试还覆盖”不足以准入。审查主动搜索这些残留；正式发布后政策另行设计（用户2026-08-15）。

### 串台自查与停止线

| 触发情形 | 立即核什么 | 继续条件 |
|---|---|---|
| 要逐状态/逐次绘制复制第一阶段，或为对齐保留缺陷 | 原始意图、完整帧与差异归因 | 按共同演出标准有证据地决定修复层；意图不明或新产品取舍交用户 |
| 重写子系统却未读一阶段对应领域 | harvest、注释与修复史 | 形成可核清单后再实现，不让用户重新报告已知坑 |
| 用“链路已齐”认可全局变量、隐式残留或下标身份 | 铁律4/5的职责与身份模型 | 标明过渡态并给干净承接，不当合格现状 |
| 只改生成结果，或反过来把作者正文强制同步旧转换器 | 字段维护权、供应分区和09-30后继 | 各修真实维护源；原始源需重导幂等，作者正文不复活退役规则 |
| 以兼容旧开发数据保留 fallback/升级器 | 当前真实输入、调用方与用户批准 | 无法重建的例外须隔离并有删除条件，其余随当前版本收口 |
