# 第二阶段（Reforge）· 开工前必读

> **你现在在做第二阶段。第一阶段的「忠实还原」思维全部作废。**
> 这份是铁律，开任何 Reforge（新引擎 / 编辑器 / 内容 schema）工作前先读。背景与分解见 [roadmap.md](roadmap.md)。

## 十条铁律

1. **全新重写**：新引擎、编辑器都是全新制作，不是改造旧 `game`。
2. **不对齐旧引擎 / 原版行为**：不要求逐状态一致，**没有「双引擎对照 / 真值锚」**——那是第一阶段打法。旧引擎和原版只回答「这场戏原本啥样」，是**内容参考**，不是实现要对齐的真值。
3. **逻辑知识可移植，模块结构不照搬**：战斗公式 / opcode 语义 / 渲染数学可以拿来重新实现；但别原样搬旧的模块结构，那会把旧架构的耦合一起带进来。
4. **架构第一**：现代化、解耦、可扩展是最高标准（要给时间 / 天气 / 地图多层这类新功能留位置）。
   > **2026-07-06 补（战场全局变量案）——迁移语义 ≠ 架构合格，过渡态要主动审**：迁移器为行为等价把原版 1995 管线平移成运行时形态（如脚本写 `sys:*` 全局变量）是**过渡态**，不是目标态；描述 reforge「现状」前先自问「这个形态出现在全新引擎的 code review 里过得了吗」，过不了就标「过渡态，应重构成 X」并主动提出——**别等作者指出**（本案：`sys:battleField` 被作者当场点破「放全局变量明显是不良架构」）。
   > **高危模式清单**：脚本写全局变量（`sys:*` 类）、跨场景隐式残留（"忘设吃上一个的值"的约定式正确性）、运行时 mutate 静态 def、下标身份。**发现一个就嗅探同类**（grep `sys:` / 枚举全局槽），批量列出。
   > **干净模型的常见形状**：静态数据分层（场景属性 → 实体属性 → 调用点显式参数）+ 解析优先级链；迁移期把原版的全局变量舞蹈**烘干成静态层**（hoist 进场默认 / fold 调用点参数 / 传播填继承依赖）；运行时可变需求走 world 覆写重放（X1 模式），不复活全局变量。范例：战场编号三层化（scene.battleFieldId / 明雷怪实体属性 / startBattle.fieldId），`sys:battleField` 与 `setBattleField` 命令随迁移退役。
5. **杜绝「下标 / 数组位置当身份」**：对象、引用、状态键一律稳定 id / 语义名。
6. **演出用合理的新脚本还原，不复刻原版的怪癖机制**（2026-07-03 拍板）：还原目标是**观感**，手段必须是干净的显式脚本编排；不许为复刻演出把原版的隐式机制搬进引擎（例：原版「对话等按键期 GameUpdate 停 → NPC 走位冻结」造成开场李大娘读对话时停步回头——引擎**不做**对话↔NPC 移动耦合；要这个停顿，将来在内容层用显式 wait/暂停指令编排）。演出细节暂时丢失可接受，引擎脏耦合不可接受。
   > **2026-07-04 补（[D20](decisions.md)）**：原版仙剑整体降级为「试炼场 + 第一份内容包 + 迁移器练手对象」，**不再是验收标准**（旧 roadmap §8「100% 复刻 = 验收」已废弃）。本条铁律是这条降级的具体执行口径：怪癖不进引擎，撞到靠脏耦合才能跑的原版编排，标回归沙盒「需重写脚本」。
   **边界——「资产级约定」不是怪癖，必须继承**：精灵/瓦片资产是按原版坐标系画的，凡「不跟就画错」的都属资产约定，照一阶段考证抄：精灵 blit = 脚底中心、**每帧自锚**（当前帧 w/2,h，组锚配变尺寸帧组会瞬移——爬行 193 高 31~73）、blit y **+7**（sLayer×8 只进排序不进 blit，scene.c:301-316）、走位朝向象限判**像素轴**差（非菱形格轴）。
   **修渲染/演出 bug 先查一阶段同坑**：这轮三个 bug（朝向轴/+7 错缝/组锚瞬移）一阶段全解决过且写了注释（`game/src/present/draw-sprite.ts:16-24`、`present.ts:540-546`、`event-system.ts:5199-5205`）——先 grep 旧引擎再动手，别从 sdlpal 重推。
7. **根 `CLAUDE.md` 正文不适用于此**：它的「忠实 / sdlpal / 对齐原版」方法论是第一阶段的，第二阶段**只当旧引擎的参考资料**，不是方针。
8. **一阶段 = UX 真值（展示效果默认照原版/一阶段，形态不许自作主张）**（2026-07-04 拍板）：凡「一阶段已有对应」的界面/交互/演出观感，先读 `packages/game` 对应实现（`present/` 渲染 + `core/menu/` 状态机），布局/坐标/形态/交互行为**照抄当 UX 真值**，再用干净架构重写——铁律 2 的「不对齐旧引擎」指**代码架构**，不是 UX。**「形态级」选择（图标 vs 文字菜单、网格 vs 列表、布局结构）没有用户特殊说明就是原版形态**；「风格统一 / 更简洁 / 项目当前数据少」都不是换形态的理由，想换先问。无一阶段对应的全新 UI → 先出 mockup 与用户定形再实现（用户像素级审、资源偏好烤九宫格而非运行时切）。
   > 反面案例存档：战斗 UI 曾把原版「4 图标主菜单+杂项盒」自作主张换成文字竖排、「3 列法术网格」换成列表（2026-07-04 被打回）；使用面板曾自创交互行为连续返工两轮（2026-07-01）。
9. **重写一阶段打磨过的子系统前，先 harvest 一阶段知识**（2026-07-05 立，2026-07-06 补 game-mechanics）：一阶段 792 commit / 432 fix 是几十轮打磨的血泪，散落在代码注释、git message、`engineering-notes`。reforge 重写时跳过 = **必然重新踩坑**（战斗已实证：召唤神双重减锚、音效全缺、屏幕特效整类缺失，全是一阶段修过的）。**动任何能力格前，先读 [phase1-knowledge-harvest](foundation/phase1-knowledge-harvest.md) 对应领域段**——它按 reforge 8 领域摘出了一阶段的踩坑 + 可移植知识 + 架构红线，每条带锚点（commit hash / 文件:行号）。读完再动手，别 reimplement-then-等用户报 bug。
   > **★★★ 战斗/数值/机制真值的首选参考（2026-07-06）**：[`docs/phase1/game-mechanics.md`](../phase1/game-mechanics.md)（1218 行）= 作者亲自逐行核对原版+sdlpal 的底层机制真值，带源出处行号 + 原版早期 bug vs 后期修复考证。覆盖 20+ 专题（伤害/暴击/防御援护/五灵毒抗性/合击/身法/吉运/特殊技能成功率/炼丹/毒系统七大毒相生相克/怪物刷新/大世界状态带入战斗）。**动战斗/数值格前必读这份**——它是亲手考证的一手真值，比 harvest 从 commit 二手摘取权威。冲突时 game-mechanics 赢。
   > 方法论沉淀（来自战斗审计）：重实现打磨密集的子系统（战斗/演出/动画/菜单/过场）前，先 harvest 代码注释 + git 修复史成审计清单，不是可选步骤。场景演出与菜单的同型审计随做随补进 harvest 文档。
10. **迁移问题先修上游，生成产物禁止单点打补丁**（2026-07-13 用户拍板）：只要缺陷来自提取器、迁移器、数据映射、脚本生成、纯函数 overlay 或生成写盘，优先级高于下游手工演出微调。修复必须落在可重复的上游真源，随后全量重迁、跑门禁并确认双跑幂等；`projects/pal` 等生成目录中的直接修改只有在同步回迁移器/overlay 后才成立。**只把李大娘走位之类的结果改对、下一次迁移又会覆盖，等于没修。**
    > 完成定义：根因测试先红后绿；重迁产物包含修复；非脚本白名单无越界变化；连续运行迁移器第二次零 diff。若暂时无法修上游，任务必须标 `blocked` 或明确“临时诊断补丁”，不得报 done，也不得以此为基础继续堆叠内容修改。

## 串台自查

如果你发现自己冒出这些词——**停，你串台了**：

> 「真值锚」「双引擎对照」「必须和原版一致」「对齐 sdlpal」「字节级 / 帧级回归」「忠实复刻」

第二阶段没有这些。要的是**架构干净、好扩展、编辑器好用**；能正确跑迁移来的仙剑内容是底线，怎么实现由新架构自己定。

另一种串台——**重写时不读一阶段**（2026-07-05 立）：

如果你发现自己正打算「从零重写某个子系统」而**没先读 [phase1-knowledge-harvest](foundation/phase1-knowledge-harvest.md) 对应段**——**停**。一阶段在那个子系统踩过的坑（432 个 fix），你不读就会重新踩，逼用户再当一遍测试员。先读 harvest，再动手。

第三种串台——**把迁移过渡态当合格现状**（2026-07-06 立）：

如果你发现自己在用「现状链路已齐 / 照原版语义接好了」描述一个**原版管线形态**（全局变量、隐式残留、下标身份）——**停**，先过铁律 4 的架构审视再下笔。二阶段引擎的首要目标就是架构优化，这类问题应该由你主动发现。

第四种串台——**只修生成结果，不修迁移真源**（2026-07-13 立）：

如果你正在直接改 `projects/pal` 的迁移产物来修剧情、走位、脚本或数据，却没有同时定位并修复提取器 / 迁移器 / overlay——**停**。先让上游稳定产出正确结果，再做下游内容工作；否则下一次重迁会覆盖修复。
