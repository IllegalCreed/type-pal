## 目的

本指南供场景作者选择人物、精灵实体或触发区，并在需要共享身份时维护人物定义。C1-1 的人物预制只复用身份和资源；行为仍在场景实例上编排，不能据此期待完整 NPC prefab 的行为继承。

## 前置条件

- 新人物使用无首尾空格、稳定且非空的 id、显示名称和已存在的默认大世界精灵；不要把数组位置或显示名当身份。
- 先判断对象是否需要跨场景共享人物身份。门、箱子等只需要外观的对象可用 sprite；无视觉交互范围用触发区。
- 本轮核读 `character.ts:168–170` 的当前 contentVersion 22 / SAVE12 常量，只确认版本轴，不重跑人物 UI、保存或撤销。下文 C1-2 的 content14 是原文的当时落地快照。
- 显式加载的队伍/后备成员属于只读运行态存档数据。不要通过删除人物来静默重写它们。

## 步骤

### 三种放置方式

1. 需要稳定人物时，先在“角色”模块建立人物，再放进场景，实例保留 `actor` 引用。姓名、默认大世界精灵、立绘组、小头像及可选战斗资料从人物定义解算。
2. 只需要一份外观时，直接选择精灵放置自定义实体，实例保留 `sprite` 引用；适合门、箱子、机关、装饰、一次性群众等对象。
3. 只需要触碰或交互入口时建立触发区，不为它虚构视觉资源。

放置方式不决定 NPC、敌人或物件职责；继续用实例页面脚本、`hostile`、碰撞等结构表达玩法。

### 什么会共享，什么不会共享

人物定义共享显示名、稳定人物 id、默认大世界精灵、对话立绘组、菜单小头像，以及可选的队伍/战斗/成长/关系资料。实例独占实体 id、位置、朝向、碰撞、显隐、层级偏移、页面、触发脚本、自动行为、敌对配置和场景内生命周期。

因此，同一人物可以分布在多个场景；修改默认精灵会改变仍关联实例的形象，移动一个实例或改它的脚本则不应改变人物定义或其他实例。创作时先决定修改的层级，再选择人物页或场景实例，避免误改所有引用方。

### 解除人物关联

确实不再需要共享身份时，在 actor 实例检查器使用“解除人物关联，保留当前精灵”。操作把人物此刻的默认 `sprite` 解算到实例，原样保留实例其余字段；它应作为一次可撤销操作。

解除后，人物未来改名、换立绘、换默认精灵不再影响该实例；撤销恢复原 actor 引用。解除不会复制或删除共享精灵、立绘、locale 文本等资源。仍代表稳定人物、只是想换一套共享资源时，应复制或新建人物，而不是用解绑绕过身份。

### 创建、复制和删除

创建人物时，名称 locale 和定义在同一撤销事务中写入，失败不能留下半条数据。复制深拷贝人物定义及其升级习得表，精灵、立绘等共享资产只复制 id 引用，不能把复制人物解释为复制全部资源或行为。

删除前处理外部引用；引用入口可跳转到对应场景、入口、人物、物品、敌人或脚本。仍被引用或被只读存档队伍/后备成员使用时应阻止删除。删除人物不自动回收 locale、精灵、立绘、小头像或战斗精灵，这些资源可能还被其他对象使用。

## 失败处理

悬空 actor 当前可能无法解算精灵而不渲染，这不构成安全兜底。出现悬空引用、资源缺失、半条 locale 或撤销未恢复引用时，停止该创作操作并保存实际错误与调用入口，交对应产品任务核因；不要借文档治理修改产品或跳过加载/保存诊断。

### 尚未包含的能力

原文记录 C1-2 在当时 content14 已将对话区分为 narration / actor / unbound；Actor cue 姓名默认来自人物，可另设显示称谓，立绘仅取该人物的主立绘或命名表情；历史 PAL cue 为无损而进入 narration/unbound，不按名字或图片猜人物。这里保留的是当时记录，不能把旧14当作当前输入。

PAL 既有 NPC 不应按姓名、精灵或立绘 hash 自动猜身份；原文将人工归档和可审计迁移列入 C1-3 设计。“把当前自定义实体保存为人物”在原文中尚未实现。此次窄读没有验证这些后继 UI 今日是否完成，继续保持待核，不因模板化补写已完成或恢复旧版本兼容。

## 完成定义

一次人物创作应能说明选择了哪一种放置入口、改动属于共享定义还是实例、解绑/复制保留了哪些引用、删除为何允许或拒绝，并有对应保存/撤销的真实证据。文档章节与源码常量校验不能代替这些产品操作结果。

本次只迁移指南：三种入口、共享与独占、解绑、复制/删除和历史能力边界均已展开；未操作编辑器、未跑产品/旧测试、runtime、E2E、视觉或 coverage。新 Owner/date 是治理责任，不倒填原作者或原日期；候选由非作者逐篇验收，中央账本由 Codex 接入。
