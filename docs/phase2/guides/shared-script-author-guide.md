# 脚本库与可复用脚本作者手册

## 目的

供作者选择可复用脚本、实体行为、场景 hook、物品私有脚本或模板，并维护一份稳定业务语义的正文。可复用脚本用于“改一处，所有调用点生效”的固定逻辑，不是减少录入步骤的万能容器，也不替代已有结构化能力。

## 前置条件

适用版本为 contentVersion 22 / SAVE12；直接使用 `AuthorCommand`、`AuthorScriptFlow`、`AuthorScriptLibrary`、`WorldScriptState`。正式上线前只消费当前 canonical 工程，脚本分片、旧地址 sidecar、旧 upgrader 和“迁移内部实现”已经退役；旧开发工程重新生成，不恢复产品升级工作台。

第二阶段窄版 [N6b 强类型脚本模式库](../design-backlog.md#n6b-强类型脚本模式库)已拍板但尚未实现，排在薄 E2E 基线后。当前 N6 v1 没有参数，不得把模板或 callScript 当作已支持参数化；通用扩展属第三阶段。链接里的旧排期是历史，不为本指南预占下一版本。

## 步骤

### 什么时候用哪一种

| 需求 | 选择 | 存储位置 |
|---|---|---|
| 某个实体自己的交互、巡逻或演出 | 具名 Behavior | 场景实体 `behaviors.trigger/auto` |
| 场景进场或传送出口 | 具名 Hook variant | 场景 `hooks.onEnter/onTeleport` |
| 只服务一件物品的复杂用途 | 物品私有脚本 | 该物品的 `itemPrivateScript`，在物品工作台内联编辑 |
| 回复、传送、配方、资源池等已有机制 | 结构化能力 | 对应能力字段 |
| 多个场景、实体或物品必须执行同一段固定逻辑 | 可复用脚本 | `content/shared-scripts.json` |
| 文本、物品或数量不同但结构相同的重复录入 | 模板 | 插入后展开为各处自己的普通作者内容 |

“被另一个行为调用”不足以证明应该共享。先确认多调用点确实需要同步修改同一稳定业务逻辑，再提升到脚本库；文本、物品或数量不同但结构相同的录入，使用展开为普通内容的模板。

### 创建与编辑

1. 在“剧情 → 脚本库”选「新建可复用脚本」，填写显示名和稳定 id（默认 `shared/user/…`），self 初始为“不使用”。
2. 创建后在右侧作者元数据维护说明与 self 契约；稳定 id 不随显示名更改。
3. 在统一指令树写正文。位置无关的逻辑不需要地图；需要实体、坐标、面向或切场语境时，从具体调用点进入场景工作台预览。
4. 当前没有复制入口，需要独立副本就另建脚本并重写正文；不要虚构复制按钮。
5. 保存 validator 检查悬空引用、非法实体地址和 self 词表，但不对 canonical callScript 做调用环 DFS。

canonical 文件保持以下形状，compiler 的内存 executable blocks 不进入作者工程；没有额外作者索引、分片或 chunk 归属：

```ts
// content/shared-scripts.json
type AuthorScriptLibrary = Record<
  ScriptId,
  {
    name: string
    description?: string
    self: 'none' | 'optional' | 'required'
    body: AuthorCommand[]
  }
>
```

### 统一编辑器与场景工作台

共享、物品私有、实体 Behavior 和场景 Hook 共用 canonical 指令树；Behavior/Hook 的步骤和默认去向共用流程编辑器。各入口只负责自己的 id、名称、选择、删除守卫与引用列表，不另开整段 JSON 编辑器。

场景工作台上半是真实地图；同一按钮切播放/暂停/恢复，旁边有单步、重置和引擎试玩。普通对话按文本长度推进，可提前点“下一句”，暂停冻结阅读计时，是/否必须手选。单步从首条开始，每次放一条，分支、共享调用、清框也算指令，工具栏显示指令序号；已开始的移动/淡幕/等待完成后停在下一条前，倍速同时影响动作与阅读时间。

下半为可调高脚本抽屉，含“进场脚本 / 传送出口”，选实体后增加“交互脚本 / 自动行为”。预览只读降级 canonical flow 和共享调用，不把生成块或播放器状态写回作者内容。统一的是正文/流程能力，不要求所有入口外观相同；脚本库不常驻地图，私有脚本仍留物品用途卡，空间语境从调用点进入。

### `self` 契约

- 不使用：callee 屏蔽 caller self，正文不能依赖执行实体。
- 可选：显式 `EntityAddress` 优先，否则继承 caller self，也允许最终为空。
- 必须提供：显式地址优先，否则继承；运行时仍为空则拒绝。保存/发布是否因缺调用实体同样 fail-loud 仍待证，不能从运行时拒绝推成完整保存门。

实体地址必须是 `{ scene, entity }`。多个场景同名实体也要明确选择，不存裸 `e12` 让运行时猜场景。

### 调用与跳转

从 Behavior、Hook、物品私有或其他共享脚本插入“调用可复用脚本”，选择目标后保存：

```ts
{ kind: 'callScript', script: 'shared/user/door-sequence' }
{ kind: 'callScript', script: 'shared/user/npc-line', self: { scene: 'village', entity: 'elder' } }
```

调用点只存稳定 script id 和可选 self，不存 chunk；callee 正常结束或 `returnScript` 返回 caller，当前作者命令没有 jumpScript。“打开共享脚本”进入目标，右侧列出场景 Behavior、Hook、物品和其他共享脚本的直接调用方，没有单独“扫描调用位置”按钮。

当前界面不显示“迁移内部实现”页签；旧分片、地址或版本字段由 loader 拒绝，使用当前工程重生成。共享/私有根不能用 finishStep 改 caller 步骤，也不能跨根 break/continue；决定 NPC 下次步骤的条件和 finishStep 应放在该 NPC 方案本身。

### 存读与离场后的脚本续跑

SAVE12 的合同保存 NPC 实际位置、朝向、定帧、步态、动作进度，以及自动脚本续跑位置和剩余等待。离开场景暂停，不后台巡逻；返回恢复现场，正常进场 hook 按绑定运行，读档不重跑进场 hook，已选共享分支不重选、等待不从整段重新开始。

`playEntityAction` 的等待完成和循环播放是两件事；不等待时动作安装后指令即推进，不保存“已启动却待重启”的半提交状态。等待中的非循环动作续已存进度，兑现过的动作不重播；即使所属自动行为已结束，后台动作仍保留可取消归属。作者不复制初始化来修引擎恢复，也不把运行现场当可编辑方案或剧情阶段；详见[当前存档合同](../specs/save-system.md)。这些是原合同范围，本轮未重跑存读、离场或动作续跑。

### 物品私有脚本

私有正文归物品，稳定 identity 是 `itemId + scriptId(use)`，在用途效果卡内展开；不进共享库、不提供“打开共享脚本”反跳。复制物品深拷贝其正文，删改由物品自己的 undo、引用、保存闭环负责。后来确需跨物品复用时再显式提取共享脚本，把用途改成 runScript。

### 剧情入队角色的当前状态

先 setParty 改阵容，再“施加角色当前状态”，清除用对应命令；中文表单选择稳定角色、毒和状态，不用队伍下标。剧情施毒显式必中，仍遵守自毒相克/致死；定时状态仅八种可从世界带入战斗的状态，回合1..999，不开放死人专用“傀儡”；临时毒抗填正整数，同类取高。

目标必须已实例化，未入队先 setParty；世界里这些状态不自行倒计时，入战再消费，战后与读档清理按帮助文案。不要从当前指南推导其他状态入口。

## 失败处理

### 删除与错误

有直接调用方时先处理引用，不能删除共享脚本；无引用才删，撤销恢复稳定 id、元数据和正文。共享 callScript 环仍应禁止，但当前保存门只查稳定 ScriptId 等引用，没有 canonical 调用图 DFS，不能写成“保存前已拒绝所有环”。

实体地址悬空、目标缺失、v4 jumpScript 或动态 binding 按原合同保存/发布 fail-loud。required self 的空调用实体已由本轮窄读运行时确认会拒绝；保存/发布完整路径没有在本轮证明，保持待证。出现新证据冲突先停止相关断言，另开产品核验，不改源码或旧测试迎合文档。

### 重迁与当前发布

发布以 ScriptId、PageId、BehaviorId、HookId、StageId 为作者冲突键，不用生成块或数组位置。作者独有共享正文保留；双方改同一 canonical identity 时显式冲突并保持零写。原版完整脚本转换核退役，作者正文直接维护；窄资源/地图供应分区仅在当前工程发布，完整预检后 manifest 最后写入，不常驻旧升级链。

## 完成定义

一次复用工作应说明为何共享、稳定 id/self/显式地址、真实直接调用方、删除引用以及保存或发布结果；N6b 参数化、调用环 DFS 和 required-self 全保存门的缺口不能被正文符合模板所掩盖。遇到恢复或发布问题按各自当前合同与实际证据处理。

本次保留原六行选择表、全部原 live 标题/例子/链接和完整 source，只做五章迁移与必要窄源码核读，没有执行保存、发布、产品/旧测试、runtime、E2E、视觉或 coverage。Owner/date 是治理责任，原文无这些字段；非作者逐篇验收后由 Codex 统一接账，不自标完成。

````text
5. 保存前 validator 会检查悬空引用和非法实体地址，并核验 `self` 字段是

canonical 文件是：

```ts

## 统一编辑器与场景工作台

共享脚本、物品私有脚本、实体 Behavior、场景 Hook 使用同一个 canonical 指令树；Behavior
和 Hook 的步骤及默认下次去向也使用同一个流程编辑器。各入口自己的面板只负责稳定 id、
显示名、选择、删除守卫和引用列表，不能另设整段 JSON 编辑器。

场景入口不是独立的“第四套脚本编辑器”，而是在通用编辑器外保留场景专属工作台：

- 上半区是真实地图预览，同一个按钮切换播放/暂停/恢复播放，旁边保留单步、重置和引擎试玩；
  普通对话按文本长度自动推进（可点“下一句”提前确认），暂停冻结阅读倒计时，是/否必须手选。
  单步从首条指令开始，每次放行一条；分支、共享调用和清框也是指令，工具栏显示当前指令序号。
  已开始的移动/淡幕/等待先完成当前动作，再停在下一条之前；倍速同时影响动作和对话阅读时间。
- 下半区是可调高度脚本抽屉，页签为「进场脚本 / 传送出口」，选中实体时另有「交互脚本 / 自动行为」；
- 预览只读降级 canonical flow 和共享调用，不会把生成块或播放器状态写回作者内容。

因此，通用的是正文/流程编辑能力，不是强迫所有入口拥有相同外观。共享脚本库无需常驻地图，
物品私有脚本仍留在物品用途卡中；二者若需要空间语境，应进入具体场景调用点预览。

## `self` 契约

- `不使用`：callee 作用域屏蔽 caller self；脚本正文不能依赖执行实体。
- `可选`：调用点可显式给 `EntityAddress`；未给时继承 caller self，也允许最终为空。
- `必须提供`：显式地址优先，否则继承 caller self；运行时仍为空则拒绝。保存是否因缺
  调用实体而 fail-loud 目前待证，不得写成已实现的保存门。

实体地址总是 `{ scene, entity }`。同名实体出现在多个场景时必须明确选择，不能存裸 `e12`
让运行时猜当前场景。

## 调用与跳转

在 Behavior、Hook、物品私有脚本或另一段共享脚本中插入“调用可复用脚本”，选择目标后保存：

```ts
{ kind: 'callScript', script: 'shared/user/door-sequence' }
{ kind: 'callScript', script: 'shared/user/npc-line', self: { scene: 'village', entity: 'elder' } }
```

调用点只保存稳定 `script` id 和可选 `self`，不保存 `chunk`。callee 正常结束或执行
`returnScript` 后返回 caller；当前作者命令没有 `jumpScript`。

「打开共享脚本」进入目标脚本；右侧引用列表列出场景 Behavior、Hook、物品和其他共享脚本中的
直接调用方，没有单独的“扫描调用位置”按钮。contentVersion 22 作者界面不显示“迁移内部实现”页签；若项目仍含脚本分片、旧地址或
旧版本字段，当前 loader 会直接拒绝，使用当前版本重新生成开发工程，不提供产品内升级工作台。

共享和私有命令根不能使用finishStep去改变调用方步骤，也不能跨调用根break/continue循环。
需要决定某NPC下次步骤时，条件和finishStep应编排在该NPC方案自身的步骤正文中。

## 存读与离场后的脚本续跑

SAVE12由引擎同步保存NPC实际位置、朝向、定帧、步态和动作进度，以及自动脚本的续跑位置与等待剩余时长。
离开的场景暂停，不在后台继续巡逻；返回恢复现场，正常进场hook仍按当前绑定运行。读档不重跑进场hook，
已选择的共享分支不重新选择，自动等待也不从整段时长重新开始。

`playEntityAction`的“等待完成”与“循环播放”是不同设置；不等待的动作安装后，当前指令即推进，
引擎不保存“已经启动却还要重新启动一次”的半提交状态。等待中的非循环动作按已保存进度接续，
已兑现动作不重复播放。后台动作即使在所属自动行为完成后仍播放，也保留可取消的所属关系。
作者无需为存读/离场恢复复制初始化指令；也不应把引擎现场当作可编辑状态方案或剧情阶段。
这不改变共享脚本的调用归属和复用方式，详细边界见[当前存档合同](../specs/save-system.md)。

## 物品私有脚本

物品私有脚本归物品拥有，稳定 identity 为 `itemId + scriptId(use)`。它在用途效果卡内展开正文：

- 不进入共享脚本库；
- 不提供“打开共享脚本”反跳；
- 复制物品时随物品正文深拷贝；
- 删除/修改走物品自身的 undo、引用和保存闭环。

当同一逻辑后来确实需要跨物品复用时，再显式提取为共享脚本并把用途改成 `runScript`。

## 剧情入队角色的当前状态

“加入队伍”和“带着什么当前状态加入”是两个动作。先使用 `setParty` 完成阵容变化，再插入“施加角色当前
状态”；清除时使用对应的“清除角色当前状态”。表单按中文名称选择稳定角色、毒或状态，不录入队伍下标。

- 中毒：选择毒定义；剧情显式施毒必中，但仍遵守自毒的相克/致死规则。
- 定时状态：只开放可从大世界带入战斗的八种状态，回合为 1..999；死人专用“傀儡”不在此入口。
- 临时毒抗：填写正整数；同类多次施加取较高值。
- 目标必须已经实例化；若尚未入队，应先 `setParty`。世界中这些状态不会自行倒计时，进入战斗后才按
  战斗规则消费；战后与读档清理规则见状态帮助文案。

## 删除与错误

- 有任何直接调用方的共享脚本不能删除；先从引用列表处理调用点。
- 无引用脚本可删除，撤销会完整恢复稳定 id、元数据和正文。
- 共享脚本之间仍应禁止形成 `callScript` 环；这是现行设计约束，不是已实现的保存保护。
  当前保存只查稳定 ScriptId 是否缺失等引用问题，不对 canonical `callScript` 图做 DFS。
- 实体地址悬空、引用目标缺失或作者正文含 v4 `jumpScript`/动态 binding 时，保存和发布
  fail-loud。`self: required` 缺调用实体由运行时拒绝；保存/发布是否同样 fail-loud 待证。
````
