# 场景入场呈现编辑说明

> 对应能力:X3-1。数据真值见
> [当前脚本合同：场景入场呈现](../specs/script-system.md#场景入场呈现)。

## 界面结构

选中场景的“进场脚本”时，流程的初始节点可用三个区域编辑入场契约:

1. **入场准备**:编辑 `stage.entry.prepare`。只显示能在目标画面尚未呈现时安全执行的命令。
2. **呈现**:选择逐像素、淡入淡出或直接切换，并编辑毫秒参数。
3. **呈现后脚本**:编辑 `stage.body`；对话、走位和普通演出均属于这一区。

## 作者规则

- 未显式启用入场契约时，界面显示“默认场景淡变”，数据中不写空 `entry`。
- 显式契约属于 **onEnter 流程的初始节点**，不是整个场景的永久特效；不能给每个后续阶段单独设置。
- “恢复默认”会删除 `stage.entry`，后续由引擎走普通 fade；不会在 body 中塞入隐式命令。
- 入场准备的命令菜单与 content 安全目录共用同一判定源。不安全命令既不出现在菜单，
  也会在保存校验时 fail-loud。
- 普通实体脚本、auto、传送出口和共享脚本不展示该三区；独立 `ditherScreen` 仍作为正常命令编辑。

## 开场样例

PAL `s001` 第一段在界面中应读作:

- 入场准备:`音乐 31` → `队伍瞬移 (59,-23)`；
- 呈现:`逐像素 2160ms`；
- 呈现后脚本:从李大娘对话开始。

作者无需阅读 `s000` 或运行时代码，即可从该 stage 本身理解完整入场行为。
