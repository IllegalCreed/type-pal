# 场景入场呈现编辑说明

> 对应能力:X3-1。数据真值见
> [当前脚本合同：场景入场呈现](../specs/script-system.md#场景入场呈现)。

## 当前编辑器入口

在“场景编排”打开底部“📜 脚本”抽屉，选“进场脚本”及相应方案。若流程的当前步骤已有
`entry.prepare`，编辑器显示“画面出现前 / 脚本正文”两个页签，分别编辑 `prepare` 与 `body`；
没有 `entry` 时只显示正文。当前页面**没有独立的“呈现”编辑区**，不能在此设置 `entry.reveal`
的方式或时长，也没有新建/删除 `entry` 的“恢复默认”按钮。数据合同仍保留 `prepare → reveal → body`
执行顺序；不要把数据中的 `reveal` 误读为现行 UI 已提供的控件。

## 作者规则

- 数据中不写空 `entry`；没有 `entry` 时引擎走普通切场淡变，但当前页面不显示“默认场景淡变”提示。
- `entry` 只允许属于 **onEnter 流程的初始步骤/状态**，不是整个场景的永久特效；其它步骤、实体行为、
  auto、传送出口和共享脚本的当前合法数据不能声明它。进场、传送和实体方案共用流程编辑器，
  不能用“只有进场页渲染三块控件”描述当前界面。
- `prepare` 只应放能在目标画面出现前安全执行的命令。安全目录是
  `SCENE_ENTRY_PREPARE_SAFETY`（例如音乐、队伍瞬移为 safe；对话、fade、切场、队伍走位为 blocked）。
  **当前编辑器插入菜单和作者保存校验尚未按这份目录过滤/拒绝**；菜单中能选到或保存成功，
  不代表命令适合放在 `prepare`。此缺口待产品层单独修复。

## 开场样例

PAL `s001` 入库“默认进场行为”方案的初始步骤数据是:

- 入场准备:`音乐 31` → `队伍瞬移 (59,-23)`；
- 呈现:`逐像素 2160ms`；
- 呈现后脚本:从李大娘对话开始。

当前页面可在“画面出现前 / 脚本正文”两页签查看准备指令与李大娘对话；
`逐像素 2160ms` 是数据中的 `reveal`，目前没有对应的第三个编辑区。
