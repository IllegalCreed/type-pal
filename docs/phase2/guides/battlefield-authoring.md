## 目的

供作者创建和引用战斗环境，并排查显式选择与继承结果。每条 `BattleFieldDef` 用稳定数字 id 标识，包含可选名称、可选背景 `AssetId`、常驻屏幕波动强度及风/雷/水/火/土五灵修正。我方和敌方站位分别由战斗数据管理，不写进战场定义。

## 前置条件

通用 id 为非负安全整数，现代 id `0` 合法；背景只能引用 `battle-background` 类型资产。隐式默认是 `#24`，不是 manifest 中可配置的默认字段。先核调用点是否显式选择，再核场景继承；不要从表的第一条记录猜默认。

### PAL 旧数据的领域分离

原指南记录 PAL `BattleField` 沿 FBP 共索引，raw `0..5` 属 UI、开场、主菜单背景槽；其当时 current 工程只发布 `6..57` 共52个真实战场，历史58槽 parent 仅用于可逆迁移与校验。本轮保留此 PAL 专用来源说明，没有重认证 raw/图像字节或执行迁移。

这不限制通用作者 schema。现代工程可显式创建 id `0`；当前 `validateBattleFields` 核的是非负安全整数，不允许把 PAL 的旧槽含义扩成 UI/validator 的 `id >= 6` 规则。

## 步骤

### 创建、复制与删除

1. 空工程首次创建时，在同一可撤销操作中登记 `manifest.content.battleFields = "content/battle-fields.json"` 并创建表。建议首 id 是24；已有列表建议 `max(id) + 1`，提交前可改，提交后 id 为稳定引用，不能原地改号。
2. 复制条目时分配新 id，背景仍共享原 `AssetId`；不会复制或重导图像。
3. 删除前处理引用。默认 `#24` 或仍有内容引用的条目不能删除；从右侧引用栏进入调用位置清理显式引用，再回表操作。
4. 删除条目不会删除背景。已声明表删除最后一条后保留空 `battle-fields.json`，避免 manifest/file 半态，便于继续创建。

### 三层战场选择

一场战斗使用 `startBattle.fieldId → HostileBehavior.battleFieldId → SceneDef.battleFieldId → #24` 的优先链：脚本显式值只影响这次剧情战，明雷显式值只覆盖该怪，场景值为下层默认，全部未设才用24。

三处编辑器使用同一选择器。清空显式值表示继续继承，不能把当前继承结果烘焙回上层。窄读中明雷 caller 显式传 options.fieldId，战斗准备再读取场景值与24；本轮只核调用边界，没有运行战斗。

### 背景资产

通过图像资源工作台维护普通图片导入、PAL 标准色量化、替换和删除保护，沿用 A7-2 资源闭环。战场只持有 `battle-background` 的 `AssetId`；未设置背景时运行时显示黑底。删除战场不回收背景，需要删除资产时到资源工作台处理它的全部引用。

## 失败处理

悬空选择显示“战场 #N（缺失）”，保存门按内容引用拒绝该工程；不要把显示缺失占位当作合法引用。工程未提供默认24时，编辑器会提示战斗可能回落黑底；黑底兜底不证明引用安全。空表、错误资产类型、重复/负数/非安全整数 id 或删除仍被引用条目，都应先核真实错误与 caller 再处理，不改默认优先级迎合结果。

PAL raw 的领域说明、现代合法 id 与实际资产是否存在是不同问题。若需要改迁移、资产供应或默认合同，应另开相应任务；本次文档迁移不执行重导、删除资产或改变产品。

## 完成定义

### 验收示例

保留原五步为作者需要实际验证的流程，本轮未重跑：

1. 创建 `#24` 和 `#25`。
2. 场景默认选 `#24`，明雷选 `#25`，某条 `startBattle` 临时选 `#24`。
3. 保存并重开，三个选择保持不变。
4. 删除 `#25` 时，从右侧引用栏跳到明雷并清除专属值。
5. 回战场页删除 `#25`，保存重开只剩 `#24`，背景仍在资源库。

## 背景资产

背景选择复用图像资源工作台。普通图片导入、PAL 标准色量化、替换和资产删除保护仍由 A7-2 资源闭环负责：

- 战场只引用 `battle-background` 类型的 `AssetId`；
- 不设置背景时运行时明确显示黑底；
- 删除战场不会回收背景；要删除背景资产，必须到图像资源工作台处理其全部引用。
