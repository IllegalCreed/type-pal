# 战场作者工作台

战场是战斗画面环境对象，不是阵型或角色站位。每条 `BattleFieldDef` 用稳定数字 `id` 标识，只保存：

- 可选名称；
- 可选战场背景 `AssetId`；
- 常驻屏幕波动强度；
- 风、雷、水、火、土五灵修正。

我方与敌方站位继续由战斗数据分别管理，不能写入战场条目。

## PAL 旧数据的领域分离

原 PAL `BattleField` 表沿用 FBP 共索引，raw id `0..5` 实际属于 UI、开场和主菜单背景槽，不是现代战场。
PAL current 工程因此只发布 `6..57` 共 52 个真实战场；历史 58 槽 parent 仅用于可逆迁移与校验。

这是 PAL 专用迁移事实，不是通用 schema 规则。现代工程仍可显式创建 id `0` 的战场，通用编辑器会正常
显示它；不得在 UI 或 validator 中写死 `id >= 6`。

## 创建、复制与删除

- 空工程第一次创建会在同一个可撤销操作中登记
  `manifest.content.battleFields = "content/battle-fields.json"` 并创建战场表。
- 第一个建议编号是 `24`；已有列表建议 `max(id) + 1`。提交前可改编号，提交后编号作为稳定引用不可原地修改。
- 复制会分配新编号并共享原背景 `AssetId`；不会复制或重新导入图像资产。
- 删除只删除战场条目，不删除背景资产。系统默认战场 `#24` 或任何仍被内容引用的战场都不能删除；右侧引用栏可跳到调用位置。
- 删除已声明表的最后一条后保留空 `battle-fields.json`，便于继续创建，也避免 manifest/file 半态。

## 三层战场选择

一场战斗按下列优先级解析战场：

1. `startBattle.fieldId`：只影响这一次剧情战；
2. `HostileBehavior.battleFieldId`：明雷怪专属配置；
3. `SceneDef.battleFieldId`：场景默认；
4. 都未设置时使用项目隐式默认 `#24`。

场景、明雷怪和 `startBattle` 编辑器都使用同一战场选择器。清除显式值表示继续向下继承，不会把当前继承结果烘焙进上层。选择器若遇到悬空 id 会显示“缺数据”，保存门会拒绝该工程。

当前 `#24` 是运行时合同，不是可配置 manifest 字段。工程未提供 `#24` 时，编辑器会明确警告战斗将回落为黑底；不会把运行时兜底当作引用安全。

## 背景资产

背景选择复用图像资源工作台。普通图片导入、PAL 标准色量化、替换和资产删除保护仍由 A7-2 资源闭环负责：

- 战场只引用 `battle-background` 类型的 `AssetId`；
- 不设置背景时运行时明确显示黑底；
- 删除战场不会回收背景；要删除背景资产，必须到图像资源工作台处理其全部引用。

## 验收示例

1. 创建 `#24` 和 `#25`；
2. 场景默认选择 `#24`，明雷怪选择 `#25`，某条 `startBattle` 临时选择 `#24`；
3. 保存并重开，三个选择保持不变；
4. 删除 `#25` 时从右侧引用栏跳到明雷怪并清除专属值；
5. 回到战场页删除 `#25`，保存重开后只剩 `#24`，背景资产仍在资源库。
