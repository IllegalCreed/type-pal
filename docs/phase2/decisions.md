## D1 · 第二阶段开工：垂直切片先行（2026-06-24）

**决定**：第一阶段（v1.0.0，功能无 todo，剩长尾视觉 / 听验）视为可收尾，第二阶段开工；策略 = roadmap §5「骨架先行 + 垂直切片」，不瀑布。
**理由**：两阶段并行不阻塞（新引擎另起 package、冻结旧 `game`，验收 bug 继续在 game 修）；第二阶段主动拆掉了 sdlpal 真值锚，最大风险是架构空转，垂直切片用「能跑的真实内容」当新标尺。
**影响**：下一步 = 写第一个切片 spec，**不是**先写完整 P1 spec 或先把 P0 schema 定稿。

## D2 · 首个垂直切片边界（2026-06-24）

**决定**：起 `@type-pal/content` + `@type-pal/reforge`，手写一个最小室内场景（约 20×15），新引擎跑通走路 + 撞墙 + NPC 对话翻页。**不含**编辑器 / 迁移器 / 战斗 / 菜单 / 存档。
**理由**：editor 依赖引擎 + schema 先稳定（roadmap §3 第 4 条「引擎先吃通 schema 再做编辑器」，优先于 §5 把 editor 算进首 milestone 的说法）；迁移器等 schema 被切片验证后再写，免返工。
**影响**：架构红线 ——
- 三层状态分离 / 可实例化零模块单例 / OpcodeHandler 注册表 / entity 统一模型 + 稳定 id（对照 audit P0-1/3/4/5 切干净）。
- **移动 = 意图 → 纯函数碰撞判定 → 结果**，不直接 mutate 坐标（切片的"走路 + 撞墙"就按这个流做；为 MMO 碰撞权威可迁移留口，见 D5）。
**状态**：边界已 present，待最终点头后写成切片 spec。

## D3 · 地图尺寸可变（2026-06-24）

**决定**：每张地图自带 width/height，不是全局常量。**层次 A**（每图有限矩形网格、尺寸可变）现在做；**层次 B**（超大无缝 / 分块流式）MMO 级，留口不做。
**理由**：原版被 `Tiles[128][64][2]` 焊成恒定 64×128，小场景背满空格；渲染 / 碰撞本就按 width/height 跑，层次 A 近乎白送；编辑器必需。
**影响**：已补进 [p0-content-schema §5](p0-content-schema.md) + [backlog 议题 4](design-backlog.md)；切片手写场景按真实小尺寸写。

## D4 · 渲染管线走 RGBA，palette 降级为解码资产（2026-06-24）

**决定**：运行时渲染走 **RGBA + GPU**；palette 从「每帧渲染状态根」降级为「解码期把原版 indexed 美术烘成 RGBA 的色表」，运行时不碰。昼夜 / 天气 / 淡入淡出 / 红屏 / 光照 → **后处理着色器**（tint / LUT / color-grading），不再换盘。像素风靠美术资产 + 可选限色 LUT「软」保留。
**理由**：palette-as-state 是 1995 VGA 硬件遗产、audit P1-1 的天花板（无半透明 / blend / 光照）；RGBA + 后处理解锁 backlog 议题 2（时间→光照）/ 3（天气）/ 6（遮挡半透明）；对第一刀反而更省（免移植旧 indexed framebuffer + repairTilemapSeams CPU 光栅债）。
**影响**：
1. reforge 渲染选 **GPU**（WebGL2 起步，WebGPU 留升级口），textured quad 批渲染——顺手解 audit P1-3 的 tilemap CPU 光栅 + 接缝 workaround 债。
2. **后处理 pass 是渲染管线一等公民**：第一刀就留插入点（哪怕是 identity pass）。
3. 原版 palette 轮转类效果（对话图标闪烁 / 水波 / 红屏）列入 P1「需用 shader / 帧动画重做」清单，**不能直接搬**。
4. 迁移器 / content 格式要定 indexed→RGBA 解码时机（构建期烘焙 vs 运行期解码）——P1 再定。

## D5 · MMO 碰撞 / 重叠留口（2026-06-24）

**决定**：碰撞 / 重叠的 MMO **玩法**（互撞与否、网络同步）是第三阶段的活，第二阶段**不实现**；但单机就立好三个架构前提，让口子自然留住：
1. **移动 = 意图 → 确定性纯函数碰撞判定 → 结果**，不直接 mutate 坐标（判定器单机在本地、MMO 在服务器，**同一套逻辑** + 客户端预测 / 服务器校正）。← 已补进 [D2](#d2--首个垂直切片边界2026-06-24) 切片红线。
2. **实体用稳定 id + 空间索引**（格子用 uniform grid）查询「周围有谁」，不用全局下标数组（绕 audit P0-2/3）。
3. **碰撞分两类**：世界几何碰撞（地图碰撞层，静态共享，客户端可本地预测）/ 实体碰撞（动态，服务器仲裁）。
**方向（第三阶段最终拍，非定论）**：**玩家间不硬碰撞、可重叠**，仅对世界几何 + 特定实体（NPC / 怪 / 交互物）碰撞；重叠按深度基线叠画（可选轻微散开 / 半透明）。理由：俯视角窄通道硬碰撞 = 堵门卡位 + 移动同步抖动，且是 MMORPG 惯例。
**理由**：三前提全是已定铁律（稳定 id、effect 边界 audit P0-10、碰撞分层 schema §5）的自然结果，**不为 MMO 额外设计**。
**影响**：第二阶段照此做即留口；玩家碰撞具体玩法待第三阶段。
