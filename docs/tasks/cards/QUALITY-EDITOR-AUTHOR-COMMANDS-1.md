### 角色立绘表情名

`PortraitEditor` 接受非空且首尾无空格的命名，并仅将已登记的表情判为重复。Content 同样接受实际登记的同名项。Codex 以真实编辑会话核对重命名和撤销。若继承键误报重复，按现行自有键合同补失败反例后修复，不扩大作者格式或修改脚本调度。

### 角色升级表的记录归属

角色 ID 由作者工程登记。复制、删除和首次设置升级技能时，缺少伴随行等同空表；同名自有行仍照常处理。Codex 先验证合法角色及现用派发和撤销路径，再按既定自有键合同收窄三条查询和相同表写回。

### 编辑器资源目录与读取

沿当前资源目录合同核定存在性、名称、文件角色和真实字节来源。MediaAssetNameField、音频／图像工作台及同步撤销层消费同一登记。只修资源记录的存在性判定；目录格式、路径解析和磁盘写入由原合同负责。

### 内部退役与生产调用

敌队全表替换签名仅由三份专测引用，真实 EnemyTeamTab 新建、复制、变更槽位和删除均走单队命令。Editor 为私有工作区，整表命令无包级入口和真实消费者。退出旧整表命令及其快照和缺表专测，现用敌队的不变 ID、孔位、原位置、引用拒绝和 redo 合同保留。只验证旧 barrel 的专测退出；历史探针用本卡 Git 基点还原，不作为现行 gate。
