## 目标

登记的场景、实体编号与对象继承属性同名时，用物品或脚本写入仍产生该实体的状态与坐标。确认持久状态的写入边界、地图投影与原消费判据。

## 范围

用物品放置实体、基础脚本宿主写入场景实体字段、启动和换场读入场景记录及其专测。高风险域为现行世界状态的写入所有权。数据结构及合法编号域取现行作者与运行时合同。已保存的场景快照按同一身份查询。

## 前提与证据

- 合法域由 `packages/content/src/scene-index.ts` 的 `isSceneId`、`author-script-core.ts` 的 `checkEntityAddress` 与正式项目加载共同决定。稳定地址由场景和实体 ID 组成。
- 物品先按前格地形判定，再由 `main.ts` 的 `executeItemUse` 提交世界坐标和状态，刷新投影，成功后才由执行器完成扣库存。第一阶段地形条件已有[前一窗口](QUALITY-REFORGE-WORLD-CONTROLS-1.md#逐文件裁定)核证。这里处理二阶段地址的记录语义。
- 从正式项目加载及局内物品菜单复现。初始坐标为 (4,3,0)，目标前格是 (3,2,0)。库存扣减后活体坐标收到空对象。定向用例在指定坐标断言失败。第一回探针的默认朝向指向地图外，触发既有拒放，单独存原件。
- 关键对照是是否实际拥有场景记录及实体字段。真实同名字段可被写入，缺记录遵循原创建规则。覆盖参数按边界复制。

## 验收

保留正式入口红例和普通地址绿例，核两层稳定键、写入后的实际投影、输入未被改写及失败时序。相邻脚本命令用同一存储合同。用当前结构验证写入结果。涉及其他场景生命周期、存档格式或新产品取舍时另停线核证。

## 状态与交接

2026-11-27 Codex build allowed。已有合法地址合同及真实业务失败，单一写入 Owner 和定向验收范围已固定。随[当前治理窗口](QUALITY-REFORGE-SCENE-OWNERSHIP-1.md)收尾。

同日验证真实启动入口。正式加载器接受场景 `constructor`，初次进入时没有实体记录，投影尝试复制继承函数并抛 `DataCloneError`。扩入临时投影和正式换场对缺失快照的查询。现行合法编号、内容与存档结构是判据，Codex 为这段入口的单一写入方。

## 定向验收

从 `main.item-flows.test.ts` 的实际物品菜单核前格位置、实体门与库存，从 `main.entity-host-flows.test.ts` 的实际初始化及剧情执行核写入、首次场景、换场和回场。两个回场反例分别覆盖合法场景名和合法实体名。前者启动先后命中临时投影复制以及缺失的场景快照，两个失败点均保留。离场获取实际姿态以稳定数据键写入，回场从已保存的本场景记录恢复。

同一范围的地图预检确认了另一个读点。其他场景有覆写时，名为 `constructor` 的场景必须读取自己的默认地图；真正登记覆写时继续从该覆写加载。两种输入都通过正式项目加载和 `ScenePreparer`，地图和提交依赖读取同一份快照。

用物与脚本位置/状态写入和离场记录共用同一表操作，数据落在现有 `WorldScriptState` 与场景快照结构中。定向证据覆盖启动、脚本执行、离场与重访。活动剧情路线的实页验收和自动行为状态写入归各专项。原件及逐文件实际裁定见[窗口证据](QUALITY-REFORGE-SCENE-OWNERSHIP-1.md#复验与集成)。集中门随该窗口收尾。

同一稳定地址合同扩及脚本行为与钩子的选用记录。正式运行根分别验证缺定义、合法同名定义、合法同名地址的持久选择和缺省变量。已独立持有的绑定快照与新的坐标参数共用两级地址写入，分别由绑定写入者和坐标入口负责复制。原执行和完整字节索引见[脚本切片](QUALITY-REFORGE-SCENE-OWNERSHIP-1.md#脚本宿主与执行关口)。

正式物品、启动、脚本、离场与重访的定向证据均已验收。父卡的集中门同时核验这些入口，任务收口。见[集中收尾](QUALITY-REFORGE-SCENE-OWNERSHIP-1.md#集中收尾)。
