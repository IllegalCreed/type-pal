## 目标

让 PAL 作者工程的现行凤纹手绢剧情通过发布校验，保持原始种子和作者工程的方案归属检查。

## 范围

高风险资产管线变更。限 `s273/e4724` 无现行选用路径的自动方案、正式发布的已知方案总数、对应标签与引用专测，以及自动轨迹的退役台账。作者剧情正文由现行工程持有，原始种子仍由迁移基线持有。

## 前提与证据

[#75 的剧情提交](https://github.com/IllegalCreed/type-pal/commit/aab54db0f443b44e4b864788b25c8d583a4cde1b) 将物品 292 改成直接运行 `s273/e4724` 触发行为。转身、帧和等待已经在该行为主体内，原 `c8-a0ab54723b62` 自动选择被移除，旧方案仍留在作者目录。核实体默认页与现行脚本引用未找到该 ID 的活入口。原始种子保有旧方案与调用，Reforge 轨迹原件仍保有四个输入组合的历史哈希。

用正式合并计划和发布校验读入实际作者工程。只替换四份 Git 前驱输入可以成功。当前数据在此旧方案得到零物品根，仅在内存删去旧方案则得到 48 != 49。单独方案图核出 48 个唯一归属方案、11 个物品根、零不透明标签。包含旧流程的前驱发布仍报告 181 条资产检查存量结果，方案复现与修复未将该字段当作零诊断。原始首次全包失败、单一正式失败回归和只读对照在[战斗治理统一归档](../evidence/QUALITY-REFORGE-BATTLE-1.tar.gz)。

## 验收

- 同一真实发布入口先能拒绝旧孤儿数据，修复后能发布实际作者工程。根缺失、多根、悬空、循环和禁止的名称沿用原判据。只有当物品 292 直接触发船商、现行方案地址存在且本次旧自动方案已退役时才精确核 48，其余核 49。两个数据面仍各核 11 个物品根。移除直接调用，以及原有“其它节点和选择边成对丢失”回归，均须继续拒绝 48。
- 作者覆盖只删除具体自动方案。原种子、现行 `runEntityTrigger` 及其主体和入口保全。旧四组合轨迹留根源，现行内容专测核旧注册不存在。候选的 s273 与物品表字节均匹配 Q2 实录归档 `manifest.json` 的同批哈希。直接触发的原始舞台实测取[Q2 用物原件](../../testing/domains/cross-phase/battle-foundation/report.md)。
- 核对 Editor 精确消失的八条实体地址依赖和 Q2 已刊资料的来源范围。`coverage fast` 仅登记这四个消失的运行身份，并核两包增量环境及保护门。
