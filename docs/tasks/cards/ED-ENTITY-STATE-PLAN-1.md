## 已定设计与后续完整目标

### 1. 统一初始状态集合

每份状态有稳定ID、名称和所属场景，包含一个或多个实体的起始配置。
例如“门口等候”只配置e59；“三人对话前”配置A/B/C；两者是同一种资料。
不再设置“实体起点/演出现场”模式开关，不为正式脚本新增单体/多人类型。

首批已支持坐标、朝向、显隐/碰撞与画序偏置。后续完整现场目标保留帧/基础动画、精确numeric状态、
触发方式/范围和必要的行为绑定。常用字段先展示，其余放在高级属性。
精确值与未赋值保留区别，不把3归一成2，不把临时生命周期硬塞进静态配置。
如脚本依赖玩家位置、flag或队伍等条件，可在同一份状态的高级区显式提供。

预览从当前场景定义建立隔离环境，再覆盖集合中的实体；未加入的实体沿用场景默认值。
因此集合是作者明确提供的切面输入，不声称自动获得整场景的正确剧情前态。
若演出依赖另一个NPC的站位，必须把它加入或从实际现场导入。
正常预览只启动选中入口；需要同时运行的其它实体auto须在状态中明确启用，不能默认猜测。
选中入口调用的片段、交互和实体行为仍按真实脚本语义执行。

完全未配置状态或当前步骤没有默认引用时，使用“场景默认 · 未配置预览状态”，等价于当前静态起点。
只覆盖集合内实体时，其它实体也明确沿用场景默认；这种默认不证明剧情切面已正确。
已有引用却失效/资料损坏时不能静默当作未配置；提示具体原因，可由作者明确选择场景默认继续试播。

同一份状态可被多个方案的多个步骤引用，同一具体步骤可复用多份候选状态并记住其中一个默认，保持多对多。
状态列表中的编辑针对这一份具名状态。界面显示引用它的步骤数及保存会同步更新的范围；
需要独立变体时从列表“复制”，新状态保存后由步骤另行选择。候选交互不再隐式复制或改关联。

**预览入口只属于具备场景上下文的实体行为/场景Hook。** 专门的共享脚本库仅编辑片段，
不提供独立播放入口、不要求给每个片段维护实体列表或起始现场。片段通过callScript被调用时，
在调用方同一预览会话里执行，并按正式规则传递self；共享片段的演出效果在调用方预览中检查。
如需排练某片段，使用场景中的真实调用入口，不为片段添加隐藏场景或临时独立执行模型。
“同一NPC自动方案被多个演出启用”仍是该实体的一个行为方案，不等于上述共享库片段。

### 2. 状态库归场景管理，默认引用关联具体步骤

| 层次 | 编辑器辅助资料/职责 |
|---|---|
| 场景预览状态库 | 保存具名状态集合和其中的实体配置，供当前场景多个入口复用；不是整个场景统一的剧情阶段 |
| 方案 | 包含现有步骤，不另设方案级状态默认与步骤覆盖的继承规则 |
| 具体步骤的预览配置 | 记录默认状态ID及候选引用；选中步骤即自动加载，保存/重开后保持关联；未配置无需手填即可试播 |
| 预览会话 | 用当前步骤默认状态建立隔离现场，再执行所选步骤当前正文 |

这是编辑器辅助关联，不是在游戏步骤schema里内嵌一份状态副本。
默认引用以scene/entity/channel/behavior/stage，或scene/hook/variant/stage等稳定入口地址记录。
步骤重排不改变指向；删除步骤应清理该入口关联，删除状态应列出受影响引用并显式处理。
一份状态只保存一次；多个步骤可复用同一ID，不要求每个步骤重填所有实体。

从步骤2单独开始时，自动使用步骤2记住的状态，界面显示其名称和来源；未配置则用场景默认。
切换步骤时停止旧预览并物化该步骤起点，不沿用上一步骤的最后一帧，也不自动执行此前步骤。
当前正式步骤合同是每次激活执行当前步骤，next决定下次激活的步骤，不是一次播放自动串行全部步骤。
证据为 `packages/editor/src/ui/ScriptEditor.tsx:4103` 的步骤帮助和步骤卡的“下次进入”说明。
预览不能增加自动串行步骤语义；若正式调用域再次激活另一阶段，现场按真实运行演进，不能应用起点。
初始状态仅在新建/重置会话时应用一次，暂停/继续/单步也不能重置NPC。

默认引用仅在独立启动/重置预览时读取。真实运行中的再次激活和嵌套调用不按该引用恢复现场，
不成为每步执行的状态指令。同一步骤有多个实际调用现场时保留具名候选，默认固定，
作者需要另一现场时在现有播放工具栏切换初始状态；选择即记住当前入口，不另设“保存关联/设为默认”动作。
切回步骤自动读取，不要求每次播放重选；持久化仍纳入编辑器辅助资料的正常工程保存事务。

### 3. 从场景状态列表编辑，再由步骤选择关联

推荐工作流：

1. 点击现有左侧场景标题行，进入下方“初始状态”标签，在正文选中一份或点击“新建”；左侧大纲不增加列表。
2. 标签页正文显示状态列表、名称、包含实体及复制/删除操作；上方原画布进入准备态，右侧展示选中NPC的预览属性。
3. 点实体行或画布NPC选中待编辑对象；拖动改站位，右侧可精确改坐标、朝向和其它初始属性。
4. 用“管理方案实体”多选加入该场景NPC；“移出”仅移出这份状态，回落静态默认。改动未加入的NPC时自动纳入。
5. 字段blur/Enter、选项切换与拖动各提交一次正常编辑动作，可撤销；用顶部“保存项目”持久化。已有引用使用更新后的资料，步骤关联ID不变。
6. 回到原有脚本方案/步骤，在上方播放工具栏的“初始状态”选择保存的状态；选择即记住该入口引用，以后自动带入。
   如提供“打开此状态”快捷入口，它跳到同一个场景状态编辑界面；从列表选另一份编辑不会改变当前步骤关联。

准备画布的拖动只改预览辅助资料，不修改场景默认站位；提交进入正常项目历史，磁盘写入统一走项目保存，不增加私有草稿/取消栈。
移除条目意味着该实体回到场景默认值，不能误解为隐藏/删除实体。
编辑共享状态展示使用范围；列表“复制”创建独立资料，但保存副本不自动改变任何步骤的引用。
运行后的画面不自动覆盖起点；后续可通过明确的“把当前预览保存为新状态”保留下一段演出的准备输入（首批未做）。
这只是作者选择的观察结果，不声称与游戏剧情时序自动对应。

真实现场采集/导入使用同一状态库，不另设产品模式。
已有E2E检查点、DEV dumpSave或安全时点的实际world也是导入来源，但不能替代准确的入口前采集。

#### 3.1 初始状态tab首批交互

沿用现有脚本编辑的列表/详情习惯，避免在已窄的中栏再并排塞三列：

- tab正文上方为“状态方案”列表，每项显示名称、实体数量；提供新建，复制/重命名/删除收在方案操作中。
  视觉可复用现有脚本方案卡的选择习惯，但数据类型独立，不复用脚本flow模型。
- 选中方案后，下方显示“包含实体”列表。每行显示实体名称/ID、位置和显隐摘要；移出操作在右侧属性栏。
  “管理方案实体”从当前场景现有实体中选择，可多选；不能在此创建游戏实体。新建方案可先显示空列表等待添加。
- 点击实体行，右侧现有属性栏显示该条目的预览初始属性，标题明确“预览初始状态 / 方案名 / 实体名”。
  属性编辑不会改变左侧场景选择，也不会切换到底部实体脚本标签；切换实体行仅更换当前方案内的编辑对象。
- 上方画布同步展示选中方案，拖动该实体更新它的预览坐标；选中/拖动与列表及右侧属性保持同步。
- 常用属性先展示坐标（含高度）、朝向、显隐/碰撞；触发方式/范围、帧/动作、图层及精确状态等按已核合同
  放入高级区，不能仅以坐标正确代替完整状态正确。名称/ID为实体引用信息，不在这里改游戏实体身份。
- “移出”只从这份方案去掉条目，该实体回落场景默认；隐藏实体要修改显隐属性，不能以移出代替隐藏。
- E2E采集落入同一方案/实体列表，仍按用户要求由Codex整理及关联；此编辑入口负责微调和尚未采集的内容，
  不把逐条手工创建变成主工作流。

数据层次（首批实际类型见 `core/script-preview-library.ts`；高级现场种子尚未定型）：

```text
场景的预览辅助资料
  初始状态方案[]
    id / name
    entities[]
      entityId          引用该场景现有实体，方案内不重复
      initialProperties 预览初始属性；不复制整份实体定义、脚本正文或美术资源
  脚本预览入口偏好[]
    owner / stageId / initialStateId
```

方案ID独立于名称，改名不破坏步骤关联；实体以稳定ID引用，名称仅作为展示。
初始属性的缺席值沿用场景默认，显式值覆盖；不能把缺席、隐藏、停用或numeric 0混为同一状态。
该层次不改变编辑器专属sidecar边界，不直接写进游戏SceneDef或正式存档。
首批类型为 `PreviewEntityState`（pos/facing/hidden/collide/zBias）；E2E真实现场种子/在途信息仍须在后续build前核定。

### 4. E2E实际推进时由Codex批量建库（后续未实现）

这是用户明确提出的工作量要求：实现工具后，Codex在每轮E2E推进中收集经过的真实调用入口，
整理状态库和具体步骤默认引用，并给出已覆盖/未遇到/待补采清单；不要求用户逐NPC逐脚本填表。
当前代码尚无此工具，本轮不宣称已能自动采集。001–006旧截图/日志没有完整入口前状态，
不能据它们批量推断正确站位；已有检查点只在实际合适时点可作为输入。

采集流程候选：

1. DEV/E2E会话开启入口观测；方案解析完成、首条指令执行前，记录实际入口Owner、stage、self和调用来源。
2. 在同一一致性时点读取world及live scene的全部实体实际状态，不先靠静态扫描筛参与者，
   因而A触发演出时也记录B/C的真实站位。记录玩家/条件、必要行为绑定及采集来源。
3. 生成脱离live对象的预览种子，归入统一状态库；相同现场去重，不同现场保留为多个状态。
4. 首次有效采集可为尚未配置的具体步骤设置默认；已有手工默认不覆盖。
   同一步骤的后续不同现场另存为候选并标注入口/路线，不能用最后一次遇到的现场覆盖全部调用场景。
5. Codex复核样本首帧、相关实体和实际执行结果，按工具的正常事务保存工程；游戏进程不直接改作者工程。

观测对象是具备场景上下文的方案实际激活，不是每个命令、每次auto tick或同一次调用的暂停/继续。
共享库片段不另建独立预览状态，只保留调用方现场；其他实体方案的新激活可独立记录。
需要用稳定入口身份和去重规则控制重复auto/循环的数量，不能留下上千份等价状态。

这里利用的是实际运行的明确时序，不是从散乱脚本反推剧情顺序。
E2E走到的路线可以自动收集；未走分支/尚未触发的方案仍显示未采集，不标成全覆盖。
观测结果以实际stage关联默认/候选状态；选中步骤自动带入。不将采集记录变成每步执行时的状态恢复指令。

入口观测只能旁路读取，不等待saveBarrier或暂停前台lease后等其结束，不改变剧情调度/正式存档。
需要核定真实执行入口与live状态的一致快照接口，不能只加日志或复用执行完才可保存的SAVE12接口。
场景onEnter的prepare入口还须核定未呈现场时的物化权威，不把尚不存在的live实例当已采集；
基本静态种子与呈现后的真实现场分别验证，但仍落入统一状态库。
涉及在途motion/action/auto或父调用临时接管的现场，须验证可复现的种子/续跑合同；
静态站位已采集但缺关键在途信息时标为待补采/待复现，由Codex处理，不冒称精确可用。
不能为了“全部自动”静默冻结其它NPC或把它们的auto重启，并宣布还原了实际现场。

### 5. 编辑器专属存储

首批独立存于 `editor/script-preview.json`，kind为`type-pal-script-preview`、version为1。
`states`保存id/sceneId/name/entities，`bindings`保存entry与stateId；entry含sceneId、可选entityId、channel、schemeId、stageId。
同场景状态库全部是可选候选，入口仅记当前选中ID；不复制脚本正文，不改游戏内容schema。世界条件种子后续单独核定。

- 不加入manifest.content，不参与游戏脚本加载，不作为正式存档槽。
- 比照战斗模拟器辅助资料，纳入编辑器保存冲突/undo/重开/另存为/ZIP事务，检查保留路径冲突。
- 同一份状态可供多个步骤/方案使用；默认引用只是编辑器选择，脚本正文与游戏调用不引用它。
- 手工编辑进入正常项目历史，作者保存项目时持久化辅助资料。播放、暂停和重置不改作者数据；导入尚未实现。
- 不为辅助资料提升CONTENT_VERSION/SAVE_VERSION，也不保留旧开发存档转换器。
- 当前版本/工程身份必须匹配；缺失实体/动作等引用在替换预览前报出具体原因。

入口正文修改不使手工静态起点失效；播放始终执行当前正文，从明示的步骤开始。
导入来源记录仅说明来源，不能把全工程digest当静态站位有效性的唯一门槛。
若便利包支持续跑记录，则按真实恢复合同校验，不伪造digest、不静默丢续跑。

### 6. 隔离播放与重置（完整宿主后续未实现）

首批仅将所选静态实体状态分别投影给SceneCanvas及现有Playback，idle/play/reset起点一致。
以下为后续完整目标，首批不宣称具有完整preview world/session：入口种子统一来自所选初始状态，建立独立preview world/session。
复用现有runtime的绑定、条件、lifecycle、运动、动作、auto续跑与take/release；
PreviewCanvas仅负责呈现适配，不另造运动公式或用log-only接管。

手工状态明确启用的其它auto从其选择的合法入口启动；没有配置就不猜测后台行为。

所有资源预检和现场准备完成后才发布预览；失败保留原会话或明确停止，不呈现半初始化状态。

战斗、商店、视频、场景跳转等尚无真实预览宿主时，在执行前暂停并指向引擎试玩。

## 取舍与待审事项

采用统一入口，不保留前版的单体/多人模式分叉。已定原则：

1. 一份初始状态可包含一个或多个实体，仅归编辑器，正式游戏不消费。
2. 已确认场景状态列表独立管理，步骤在播放工具栏选择并记住引用；tab内部为方案→实体→属性，首批已实现并于2026-10-12通过用户验收。
3. 先做状态物化/保存闭环，再由E2E实际入口批量建库；画布用于微调和未遇到的新演出。
4. 不在每步执行时恢复初始状态，不自动串行正式阶段；每个独立预览入口自动带入自己的默认。
5. E2E代配置及具体步骤默认记忆均属于本卡要求；作者只对未采集内容或微调使用准备画布。
6. 未配置使用场景静态默认，保留当前效果；失效资料不静默伪装成已还原。
7. 左栏不增加状态列表；点击原有场景标题/实体行分别显示三项/两项标签，不新增下钻或两级导航。
8. 初始状态选择放在原播放工具栏，选择即记住当前步骤入口，切回自动读取，不设额外关联确认按钮。

仍须在实施前核定实体种子的合法输入/权威恢复路径，验证其它auto的显式启动与真实caller，
不在draft里把未实现的宿主能力标为已验证。全部在途快照恢复的复杂度不压入首版基本流程。
