**build allowed**。Codex 单一 Coding Owner。indexed-RLE 的槽数由 u16 登记，实际帧由同一字节解码器证明。当前 PAL 574 条大世界定义引用 561 份资源，最大 64 个有效帧，全部需求落在实际容量内；171 个战斗定义同样通过。历史声明超出资源仍允许渲染回第 0 帧及编辑时缩小缺失范围。作者值域继续有效。仅收口帧需求、编辑证明、预览与运行准备的帧枚举和诊断。以编辑器真实解码反例、既有回退 oracle 和相邻定向验证核收口。白名单为两份 content 精灵实现、shared RLE 槽数事实、Editor 的精灵命令与预览、Reforge 资产准备和取帧及对应测试。E2E 文件未重叠。

## 目标

精灵的声明范围和实际资源帧数由各自所有者提供。容量不符合要求时应返回可定位的错误。大世界已有声明超过实帧数时允许收敛旧差异，战斗精灵当前要求实际帧完整。

## 范围

记录内容帧需求、帧枚举和编辑器容量比较的风险。大世界与战斗精灵各按自身布局核实。

## 前提与证据

编辑器的 `UpdateBattleSpriteDefinitionCommand` 使用真实解码出的十帧测试资源。超出容量的敌人 profile 符合现行结构条件，应用时应走已有“需要多少帧，实际有多少帧”的错误。实际收到了 JavaScript `RangeError`。帧需求内先构造全部帧索引，再将集合展开为函数参数，容量比较还未执行。

大世界的更新命令会枚举旧、新声明的全部帧来核对增量。当前 guard 允许正整数方向帧数，枚举开销跟声明量走。初审将此项独立登记。当前继续核实际资源证据、编辑和行走取帧的约束。

### 调用与原件

- [战斗加载 readiness](../../../packages/reforge/src/assets.ts#L401)逐槽读取真实帧。[大世界编辑器](../../../packages/editor/src/core/sprite-commands.ts#L146)比较前后缺失帧的集合。

## 本次修复

真实解码清点确认 574 条大世界定义、561 份资源，最大有效帧数 64。171 条战斗定义和资源的最大帧数为 16。两次清点的全部需求、有效帧和容器登记槽结果一致。indexed-RLE 用 u16 记录槽数，可选 sentinel 占一槽。这个物理上界指导需要枚举的编辑和预览操作，作者定义值域由原校验保持。

大世界用连续布局范围与显式动作帧确定新增缺帧。常规诊断仍展示确切槽位，超过物理槽数的声明报告首个新增槽位。合法编辑可收缩历史缺帧。运行时按步相计算而无需构造整张步序表，旧缺帧继续回第 0 帧。声明超过物理范围时，大世界自动布局与敌人连续动作段只枚举实际槽位。显式动作与玩家命名槽保留原声明。既有合法帧序和资源格式保持。

战斗帧需求用非空段右端点及已解码召唤帧数。先检查真实资源容量，拒绝路径保留编辑器业务提示及运行时首个越界帧。已解码 indexed-RLE 的有效帧数组连续，合法敌人各段连续从 0 开始。玩家的效果索引仍属于独立资源。

## 验收

用原战斗编辑红例及同容量正控，补大世界编辑、真实预览、行走回退、战斗预览和两个内容层帧差的独立用例。有效数据清点和 8,575 组有限集合差分分别证明实资源范围和新增缺帧比较。自动循环的正常 3 帧与超大声明分别通过实际预览；临时移除容量保护时，只在超大声明用例复现原有 RangeError。Editor、Reforge、Content 和 Shared 定向结果及前期失败可逐项复验。
