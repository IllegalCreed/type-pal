文档采用「阶段 × 主题」的平面目录结构：
- `docs/README.md` 为总入口，声明三阶段边界与「两阶段世界观严禁混用」铁律。
- `phase1/`：以编号文件（01-feasibility → 06-testing）串联主线设计，`status/` 维护 feature / opcode / cutscene / item / magic / resource 六张完成度真值表，`plans/` 按日期前缀归档 per-milestone 计划与审计快照（历史，不反映现状）。
- `phase2/`：顶层放滚动方针（READ-FIRST / roadmap / decisions / design-backlog），子文件夹按主题划分（foundation/ 跨切片地基、dialogue/、menu/、slice1-indoor/、editor/、migrate/），每个子系统内用 spec/design/plan 角色后缀区分规格、架构与 TDD 实现步骤。
- `phase3/`：仅存放未来 MMO + 深度玩法的远期 backlog。
- `lore/`：独立于阶段的「仙剑设定真值库」，含 characters / timeline / world-rules / factions / taboos / versions / dlc-ideas / narrative-workflow，并带 DLC 子目录（dlc-01-guijie/）记录节拍表与脑暴。
依赖方向单向：phase2 可引用 phase1 的 engine-debt-audit 作为重写输入，但禁止把 phase1 的 sdlpal 真值带入 phase2 新引擎；lore 被所有阶段共同消费但不反向依赖任何 phase。
