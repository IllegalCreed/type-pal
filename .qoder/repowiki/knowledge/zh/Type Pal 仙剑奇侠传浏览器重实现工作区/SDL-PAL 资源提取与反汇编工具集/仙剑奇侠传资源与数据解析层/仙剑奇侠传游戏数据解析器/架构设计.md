本模块是纯函数式解析层,每个 `*.ts` 文件对应一个游戏子域(物品、法术、敌人、队伍、商店、角色、RNG 动画、音效、杂项),统一从上层传入 MKF chunk 原始字节(`Uint8Array`)并返回结构化对象数组。

- 共享基础设施集中在 `_utils.ts`:定义 OBJECT 数组各段起始/数量常量(OBJECT_ITEM/OBJECT_MAGIC/OBJECT_ENEMY/OBJECT_PLAYER)、OBJECT_ENEMY 字段偏移以及 LE u16/s16 读取 helper,所有 parser 仅依赖此文件获取布局常量。
- 每个 parser 遵循同一模式:声明 `SIZE` 常量 + `OFF` 偏移表(`as const`)→ 校验输入长度后 `new DataView(...)` → 循环逐条构造目标类型(来自 `@type-pal/shared`)→ 可选通过 `Words` 反向填充 `_name` 注释字段。
- 跨表关联通过“名称表 + OBJECT 反查”实现:如 `parseEnemies` 先建 `enemyId→_name` Map,再回填;`buildEnemyObjectNameMap` / `buildObjectIndexToEnemyIdMap` 提供面向 enemy-teams 的反向索引。
- 特殊 union 处理:`spells.ts` 把梦蛇(295)从 item 段剥离补入 spells.json;`parseObjectMagics` / `parseObjectPoisons` 以不同 union 视图遍历整个 OBJECT 数组,覆盖 `0x42 SimulateMagic`、`0x28 apply poison` 等 opcode 需求。
- 图像类解析(ball.ts、rng-frames.ts)复用 `../sprite.js` 的 `encodeIndexedPng`,ball 走 RLE→IndexedImage→PNG,rng 走 shared `decodeRngFrames`→PNG;两者均跳过空帧(chunk 0 或宽高为 0)。
- 测试文件位于 `__tests__/` 与同目录 `.test.ts`(如 rng-frames.test.ts),直接 import 被解析函数做断言。
