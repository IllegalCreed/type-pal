模块按「primitive → 具体菜单 → 调度器」三层组织:
- primitives.ts:纯数据 + tick 函数,提供 SelectionMenu/ConfirmMenu/TripleMenu/SwitchMenu 四个 sdlpal `uigame.c` 原语,无 DOM/canvas 引用。
- 各菜单文件(inventory-menu.ts / equip-menu.ts / in-game-magic-menu.ts / shop-menu.ts / sell-menu.ts / save-slot-menu.ts / opening-menu.ts / player-status.ts / inventory-action-menu.ts / script-desc.ts / magic-script.ts / item-select.ts):每个对应一个 sdlpal 菜单入口(PAL_InventoryMenu/PAL_EquipItemMenu/PAL_InGameMagicMenu/…),导出 `createXxxMenu` 构造 state 以及 `moveUp/Down/Left/Right/PageUp/PageDn/Home/End/Cancel/Confirm` 等输入处理函数;state 通过显式 `phase` 字段(如 `'list' | 'use-target' | 'done'`)表达有限状态机,与 sdlpal 内部 while+case 流程一一对应。
- menu-driver.ts:单一帧 dispatch 入口 `dispatchMenuInput`,从 `gs.menuStack` 顶取 entry.kind 分派到对应 dispatcher(`dispatchInventoryMenu`/`dispatchEquipMenu`/…);通过模块级 `_catalogs` 单例注入 items/spells/playerRoles,并通过 `setStartGameHandler`/`setLoadGameHandler`/`setSystemQuitHandler` 回调注入 bootstrap 侧副作用(存档/场景加载/回标题)。
- menu-mode.ts:顶层 mode='menu' 的 tick 循环,维护 `openMenu/closeTopMenu` 与 `resumeAfterMenusClosed`(根据 battleState/eventCursor.waiting 决定切回 explore/battle/event)。
依赖方向:menu-mode → menu-driver → 各菜单文件 → primitives;菜单文件可向上读 GameState 与 Catalogs,但不直接操作渲染层,由 draw-menu.ts 消费其 state。
