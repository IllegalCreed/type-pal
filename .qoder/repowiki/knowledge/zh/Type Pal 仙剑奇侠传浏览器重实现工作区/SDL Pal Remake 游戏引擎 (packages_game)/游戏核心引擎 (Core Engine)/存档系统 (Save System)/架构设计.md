模块由两层组成:
- `api.ts` 暴露统一 `Save` 接口(`saveSlot/loadSlot/listSlots/deleteSlot`)与 `MAX_SAVE_SLOTS=5`、`SlotMeta` 类型,是上层唯一依赖入口。
- `indexed-db.ts` 实现同名 API 的 IndexedDB 驱动(`db='type-pal'`, store=`save-slots`, keyPath=`id`, `DB_VERSION=2`),作为 production 后端。

运行时选择策略:每个 Save 方法先调用 `idbAvailable()` 检测 `indexedDB` 是否可用,若不可用则走 `_slots: Map<number,{gs,meta}>` in-memory stub;否则委托给 `IndexedDbSave`。所有写入前对 `GameState` 执行 `deepClone`(优先 `structuredClone`,回退 `JSON.parse(JSON.stringify)`)以隔离后续 mutate,读取时也深拷贝返回,避免外部修改影响存储。

Schema 演进:DB_VERSION 从 1→2 时在 `onupgradeneeded` 中删除旧 store 并重建,注释记录了 P2#5 脚本游标 ip 从 per-scene 本地下标迁移到全局解释器导致的格式不兼容,因此采用清空旧档的破坏性升级。

测试边界:`__tests__/api.test.ts` 使用 vitest 运行于 Node(无 IDB),自然命中 in-memory 路径,并通过 `Save._clearAllForTest()` 在每个用例前清理状态;`indexed-db.ts` 另暴露 `_resetDbConnectionForTest()` 用于重置单例 db 连接缓存。
