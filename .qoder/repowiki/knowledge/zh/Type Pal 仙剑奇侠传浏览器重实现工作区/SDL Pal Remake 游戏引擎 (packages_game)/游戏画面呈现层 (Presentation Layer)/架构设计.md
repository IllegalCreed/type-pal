模块以 `present.ts` 的 `presentFrame` 作为大世界一帧装配入口,按 sdlpal `PAL_MakeScene` 顺序:清屏 → tilemap layer0/layer1 全画 → 接缝修复 → screen-wave → Y-sort 精灵(party/followers/NPCs)→ palette remap(FadeToRed)→ 对话框/确认框 → dither fadeState → 菜单 overlay → shake。

- 抽象: `framebuffer.ts` 定义 `Framebuffer` 接口(320×200 Uint8Array 索引缓冲 + writePixel/clear/toImageData),所有 draw-* 函数只依赖此接口,不直接碰 Canvas。
- 子域划分:
  - `battle/present-battle.ts` 持有 `BattlePresent` 类(跨帧状态:FloatingNumsLayer、intro/summon dither backup),通过 `presentBattleFrame` 由上层路由;内部再分 `draw-battle-bg|sprites|effect|num|ui|settlement` 各管一层。
  - `menu/draw-menu.ts` 作为菜单栈分发器,按 `ActiveMenuEntry.kind` 分派到 `draw-opening-menu|inventory|equip|player-status|shop|magic|confirm` 等全屏/半屏 UI 组件。
  - 共享基础: `dialog-box.ts`(对话状态机+控制符解析)、`font.ts`(Unifont glyph table + renderText)、`draw-tilemap.ts`(瓦片 blit + cover tile + seam repair)、`draw-sprite.ts`(精灵帧 blit)、`follower-pos.ts`/`follower-render.ts`(跟随者轨迹计算)、`dither-fade.ts`(nibble-dither 步推进)、`screen-wave.ts`/`screen-shake.ts`(全屏特效)。
- 依赖方向: present → core(game-state, command-bus, battle-system, palette-fade, scene-system); present 不反向依赖 core 的 state 修改逻辑,仅消费只读快照;资源通过 `PresentContext` / `BattleAssets` 注入,保持纯函数式 draw 可单测。
- 测试:每个 draw 文件旁有同名 `*.test.ts`,覆盖 draw-tilemap、draw-sprite、dialog-box、dither-fade、screen-shake、menu 及 battle 子模块。
